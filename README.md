# 주정차 신고 자동작성 (safety-report-poc)

안전신문고 **불법주정차 신고**를 어떻게 고치면 좋을지 보여 주는 **개선 제안용 비공식 화면**이다.
2조 「신고해도 될까요」가 국민제안으로 낼 개선안의 근거 자료로 만든다. **실제 신고는 접수되지 않는다.**

- 배포본: https://safety-report-poc.vercel.app
  - `/` — 신고 화면(휴대폰 기준)
  - `/eval.html` — 판독 채점(팀원용). PC 화면에서만 오른쪽 위에 들어가는 단추가 보인다.
- 한 문장: **사진부터 찍으면, 신고서는 앱이 쓴다.**

> 이 저장소의 화면은 안전신문고 앱이 아니다. 기관 로고·명칭·접수번호를 만들지 않고,
> 모든 화면 맨 위에 비공식 화면이라는 띠를 단다.

## 1. 먼저 읽기 — 지켜야 할 원칙

새 기능을 붙이거나 코드를 고치기 전에 아래와 어긋나지 않는지 본다. 어긋나야 한다면 팀에서 먼저 정하고
`docs/design.md`의 결정 기록에 남긴다.

| 원칙 | 뜻 | 코드에서 지키는 곳 |
| --- | --- | --- |
| **AI는 보기만, 판정은 규칙이** | AI는 "사진에 무엇이 보이는가"만 답한다(장면 6항목 보임·아님·모름, 번호판 글자, 근거 위치). 유형 결정·부적합 판정·추천·간격·겹침·번호판 일치·제출 점검은 모두 규칙 코드가 한다. | `api/vision.ts`의 `typesFromScene`·`mergeReads`, `src/lib/*` |
| **판정 근거는 사진뿐** | 좌표 × 공공데이터는 참고용 '의심'이다. 사진에 근거(예: 정류장 표지)가 안 보이면 그 유형을 채우지 않고 다시 찍게 한다. | `src/lib/crosscheck.ts` |
| **AI에게 힌트를 주지 않는다** | 좌표·주변 시설·다른 사진의 판독 결과를 AI에 넘기지 않는다. 사진 한 장씩 따로 읽게 한다. | `api/vision.ts`, `src/lib/vision.ts` |
| **없는 값을 지어내지 않는다** | 키가 없거나 판독이 안 되면 칸을 비우고 이유를 적는다. 표본 값으로 화면을 채우지 않는다. | `reverseGeocode.ts`, `compose.ts` |
| **실제 기관 화면을 흉내 내지 않는다** | 로고·기관명·접수번호·로그인·범죄예방 메뉴·이벤트 띠를 만들지 않는다. | `src/components/Ui.tsx`(비공식 화면 띠) |
| **키는 서버에만** | API 키는 `api/` 함수에서만 읽는다. `VITE_` 접두사를 붙이면 브라우저 번들에 박히므로 붙이지 않는다. | `.env.example`, `vite.config.ts` |
| **규칙은 어디서 돌든 같은 답** | 판정 규칙 파일은 화면·브라우저·네트워크·기기 현지 시각에 기대지 않는다. 기한·단속 시간·촬영시각은 **한국 시각**으로 따진다. | `src/lib/purity.test.ts`, `src/lib/kst.ts` |
| **오래된 규정으로 안내하지 않는다** | 지자체 규정은 출처·확인일과 함께 둔다. 확인한 지 180일이 넘으면 경고, 365일이 넘으면 그 지역 값을 쓰지 않고 전국 기준으로 돌아간다. | `src/lib/localRules.ts` `ruleFreshness` |
| **개인정보** | 번호판은 개인정보다. 채점 사진은 본인·팀원 차량만 쓰고, 사진과 `answers.csv`는 깃에 올리지 않는다. 좌표는 기록·캐시하지 않는다. | `.gitignore`, `api/*.ts` |

### 용어

화면·문서·코드 주석에 같은 말을 쓴다.

| 쓰는 말 | 쓰지 않는 말 |
| --- | --- |
| 첫 번째 사진 · 두 번째 사진 | 첫 사진 · 둘째 사진 · 첫 컷 · 둘째 장 |
| 개선안 · 개선 제안용 비공식 화면 | 시제품 |
| 판정(규칙) · 판독(AI) | AI 판정 |
| 위치자료(참고용 의심) | 위치 판정 |

## 2. 화면 흐름

```
처음 화면 ─ [사진부터 찍기] / [앨범에서 2장 고르기] / 이어할 신고 / 제출한 신고
   │
   ▼
촬영 ─ 첫 번째 사진 → 바로 판독(AI) → 부적합이면 이유 안내 · 다시 찍기
   │        유형이 여럿이면 추천을 보고 사람이 고름
   ▼
남은 시간 ─ 지자체 간격(전국 기준 60초)을 셈 · 자리를 떠도 됨 · 0초에 소리·진동·알림
   ▼
두 번째 사진 ─ 첫 번째 사진 잔상(35%)을 겹쳐 같은 구도로
   ▼
두 사진 확인 ─ 같은 자리(겹침 50% 이상) · 같은 번호판(두 장 모두 읽히고 같음)
   ▼
신고서 5단계 ─ 유형 → 발생지역(적용 규정·기한) → 차량번호(번호판 확대 대조) → 내용(개조식 자동 작성)
             → 점검·제출(신호등 + '담당 공무원이 받는 내용' 미리 보기)
   ▼
제출 ─ 접수되지 않음. '제출한 신고'에 남는다. 걸린 시간·누른 횟수를 함께 보여 준다(현장 확인 ⑦).
```

- **이어하기** — 단계마다 기기(IndexedDB)에 저장한다. 앱을 바꾸거나 꺼도 하던 단계로 돌아온다(36시간 안). 7일 지나면 지운다.
- **앨범 사진** — 사진 파일의 촬영 기록(EXIF)으로 진위를 규칙으로 점검한다(`src/lib/authenticity.ts`).
- 처음이든 자주든 **흐름은 하나**다. 사용자를 나눠 흐름을 따로 두지 않는다(팀 결정).
- **담당 공무원 쪽** — 제출하는 내용 끝에 '사전 점검 요약'(간격·겹침·두 장 번호 일치·위반 근거·적용 규정과 확인일·확인 필요 항목)이 붙는다.
  담당자는 사진을 다시 재지 않고 확인만 하면 된다. 근거와 효과 추정은 `docs/officer-impact.md`.

## 3. AI·규칙·사람이 하는 일

| 단계 | 하는 쪽 | 무엇을 | 파일 |
| --- | --- | --- | --- |
| 첫 번째 사진 촬영 | 사람 | 찍는다. 찍는 순간 촬영시각·좌표를 사진에 새긴다 | `src/lib/camera.ts` |
| 장면·번호판 읽기 | **AI** | 장면 6항목(횡단보도·인도·정류장 표지·보호구역 표시·교차로 모퉁이·소화전) 보임/아님/모름, 번호판 글자, 근거 상자 | `api/vision.ts` |
| 장면 → 유형 | 규칙 | 보임 항목을 유형으로 바꾸고, AI가 따로 낸 유형과 다르면 확신도를 낮춘다 | `api/vision.ts` `typesFromScene` |
| 사진 증거 판정 | 규칙 | 확신도 0.5 이상이어야 유형을 채운다. 위치자료는 일치 여부만 덧붙인다 | `src/lib/crosscheck.ts` |
| 부적합 안내 | 규칙 | 근거·번호판이 안 보이면 이유를 알리고 첫 번째 사진을 다시 찍게 한다 | `src/components/CaptureFlow.tsx` |
| 유형 추천 | 규칙 | 단속 시간 안 → 과태료 큰 것 → 위치자료 일치 → 판독 순서 | `src/lib/choose.ts` |
| 유형 선택 | 사람 | 여럿이면 고른다 | |
| 지자체 규정 | 규칙 | 주소로 관할을 찾아 간격·단속 시간·접수 기한 적용(없거나 오래되면 전국 기준) | `src/lib/localRules.ts` |
| 남은 시간 알림 | 규칙 | 0초에 소리·진동·시스템 알림·탭 제목 | `src/lib/alert.ts` |
| 같은 자리 | 규칙 | 두 사진 윤곽 대조, 겹침 50%·닮음 0.45 이상 | `src/lib/overlap.ts` |
| 같은 차 | 규칙 | 두 장에서 **따로** 읽은 번호가 같을 때만 확정 | `api/vision.ts` `mergeReads` |
| 주소 | 규칙(외부 API) | 좌표 → 도로명주소 | `api/address.ts` |
| 내용 작성 | 규칙 | 있는 값만 이어 붙인 개조식 문장 | `src/lib/compose.ts` |
| 담당자용 점검 요약 | 규칙 | 잰 값·적용 규정·확인 필요 항목을 내용 끝에 붙임(900자 안) | `src/lib/officer.ts` |
| 번호판 확대 | 규칙 | AI가 짚은 번호판 자리를 두 사진에서 잘라 나란히 보여 줌 | `src/components/FormParts.tsx` `PlateZoom` |
| 제출 전 점검 | 규칙 | 빨강이면 제출을 막는다(아래 표) | `src/lib/precheck.ts`, `src/lib/rules.ts` |
| 확인·제출 | 사람 | 채워진 칸을 확인하고 낸다 | `src/components/ReportSteps.tsx` |

### 제출 전 점검 항목

`rules.ts`의 `runChecks`(기본 5개) 위에 `precheck.ts`가 7개를 더한다. **빨강(fail) 하나라도 있으면 제출 불가**, 노랑(warn)은 알리기만 한다.

| 항목 | 출처 | 막는 경우 |
| --- | --- | --- |
| 두 사진 간격 | rules | 지자체 간격 미만 |
| 접수 기한 | rules | 촬영일 다음 날 자정 경과(지역 규정이 이틀이면 이틀) — 한국 시각 |
| 촬영시각 표시 | rules | 사진에 촬영시각 없음 |
| 차량번호 | rules | 형식 불일치·확신도 0.8 미만 |
| 위치 | rules | 좌표 없음 |
| 위반유형 사진 증거 | precheck | 유형이 비어 있음(직접 고른 유형이 사진 판정과 다르면 경고) |
| 두 장 번호판 일치 | precheck | 한 장이라도 안 읽히거나 서로 다름 |
| 같은 자리 두 장 | precheck | 겹침 50% 미만 |
| 단속 시간 | precheck | 그 유형 단속 시간 밖(예: 어린이보호구역 주말) |
| 앨범 사진 진위 | precheck | 편집 흔적·촬영시각 없음 등 |
| 발생지역 | precheck | 좌표도 주소도 없음(좌표만 있으면 경고) |
| 내용 | precheck | 5자 미만 |

## 4. 폴더와 파일 지도

```
api/                     서버 함수(Vercel). 키는 여기서만 읽는다. 서로 import 하지 않는다(함수별로 따로 묶이므로)
  address.ts             좌표 → 도로명주소. 브이월드 우선, 없으면 카카오
  stops.ts               좌표 주변 버스정류장(TAGO 실시간, 반경 500m)
  tile.ts                브이월드 지도 타일 중계(키 숨김, CDN 캐시)
  vision.ts              사진 판독 중계 + 규칙(typesFromScene·mergeReads). 모델 대체 순서 포함
src/
  App.tsx                화면 전환(home·capture·form), 사진별 판독, 겹침 계산, 이어하기
  main.tsx               신고 화면 진입점
  components/
    StartScreen.tsx      처음 화면 — 사진부터 찍기, 앨범, 이어할 신고·제출한 신고
    CaptureFlow.tsx      촬영 — 첫 번째 사진 판독·부적합 안내·유형 선택·남은 시간·두 번째 사진·두 사진 확인
    ReportSteps.tsx      신고서 5단계(유형·발생지역·차량번호·내용·점검·제출)
    FormParts.tsx        신고서 조각들, '지금 앱과 무엇이 다른가' 설명
    PickMap.tsx          위치찾기 지도(Leaflet + 브이월드 타일)
    Ui.tsx               공통 조각, 비공식 화면 띠, 휴대폰 틀
  lib/                   규칙과 계산. 화면 코드 없이 시험할 수 있게 둔다
    rules.ts             신고 요건 상수·기본 점검(간격·기한·촬영시각·번호·위치), INTERVAL_SEC
    precheck.ts          제출 전 점검(사진 증거·번호판 일치·겹침·단속 시간·앨범 진위·주소·내용)
    crosscheck.ts        사진 증거 기준 유형 확정 + 위치자료 일치 표시
    choose.ts            유형이 여럿일 때 추천 순서
    localRules.ts        지자체 규정표(출처·확인일 포함), 전국 기준, 과태료
    overlap.ts           두 사진 겹침(윤곽 대조, AI 없음)
    recommend.ts         좌표 × 주변 시설 거리로 유형 후보(참고용)
    facilities.ts        주변 시설 격자 파일 불러오기 + 정류장 API
    geo.ts               거리 계산(하버사인), 기준 거리 판정
    authenticity.ts      앨범 사진 진위 점검(EXIF, 규칙)
    album.ts             앨범 사진 읽기 + 촬영시각·위치 새기기
    camera.ts            촬영, 촬영시각·좌표 새기기
    vision.ts            판독용 사본 줄이기(긴 변 1280px) + /api/vision 호출
    compose.ts           내용 칸 자동 작성(템플릿)
    officer.ts           담당 공무원에게 함께 가는 사전 점검 요약
    kst.ts               한국 시각 계산(기기 시간대와 무관)
    exifTime.ts          사진 파일 촬영시각 읽기 — 시간대 기록이 없으면 한국 시각으로 가정
    reports.ts           신고 보관함(IndexedDB) — 이어하기·제출한 신고
    alert.ts             0초 알림(소리·진동·시스템 알림·탭 제목)
    reverseGeocode.ts    /api/address 호출
    *.test.ts            단위 시험(vitest). purity.test.ts 는 규칙 파일의 순수성을 강제한다
```

| 전국횡단보도표준데이터 | [data.go.kr 15028201](https://www.data.go.kr/data/15028201/standard.do) | 서울·전북 | 반기 — 갱신되면 다시 돌린다 |

- 결과: `public/fac/{위도칸}_{경도칸}.json` + `public/fac/meta.json`(수집 시각·건수). 받은 원본은 `.cache/fac/`(깃 제외)에 남아 끊겨도 이어 받는다.
- **소화전은 뺐다** — 전국 통합본이 없고 전북 자료가 2017년 기준이다. 낡은 좌표로 판정하느니 하지 않는다(`docs/test-data.md`).
- **교차로 모퉁이는 위치자료가 없다** — 도로망 교차점 계산이 따로 필요하다. 사진 판독에만 기댄다.

### 지자체 규정 추가 절차

1. 그 지자체의 주민신고제 공식 안내 페이지를 찾는다(블로그·뉴스 말고 지자체 누리집).
2. `src/lib/localRules.ts`의 `LOCAL_RULES`에 `region`·`match`(주소 정규식)·`types`·`extra`·`source`·`checkedAt`을 적는다.
3. `src/lib/localRules.test.ts`에 그 지역 주소로 간격·단속 시간 시험을 하나 더한다.
4. 표에 없는 지자체는 전국 기준을 쓰고 화면에 '전국 기준'이라고 밝힌다 — 이 동작은 바꾸지 않는다.
5. `match`는 시·도 이름부터 맞춘다(예: `/^대전(광역시)?\s+동구/`). '동구'만 쓰면 부산·인천 동구에도 걸린다.
6. 규정을 다시 확인하면 `checkedAt`만 고쳐도 신선도 경고가 풀린다. 출처가 바뀌었으면 `source`도 고친다.

등록된 지역: 경기 광명시, 경북 안동시, 충남 아산시(2026-10-02 확인), 서울특별시(시 단위, 2026-10-02),
대전 동구·중구·대덕구(2026-09-18). 서울·대전은 팀원 저장소 [kjy-arch/parking-report](https://github.com/kjy-arch/parking-report)의
확인 기록(`docs/evidence/`)을 옮겼다. 대전 3개 구는 어린이보호구역을 24시간 접수한다(08~20시는 과태료 3배 구간).

## 10. 판독 채점

AI+규칙이 위반 유형과 번호판을 얼마나 맞히는지 **사진 1장 기준**으로 잰다. 자세한 순서는 `data/samples/README.md`.

- 목표: 유형 정답률 95%, 번호판 오채움 0건.
- 사진 약 100장(본인·팀원 차량만). 70장은 '개선'(고치면서 반복), 30장은 '시험'(**발표 직전 한 번만**).
- `/eval.html`에서 정답표(CSV)와 사진 폴더를 고르면 앱과 같은 경로(줄이기 → `/api/vision` → `crosscheck`·`rankTypes`·번호판 기준)로 돌린다(`src/eval/run.ts`).
- 100장 중 95장을 맞혀도 실제 범위는 약 89~98%다. 화면의 '실제 범위'를 함께 말한다.

## 10-1. 발표자료

최종 발표자료는 **저장소 안에서 같이 고친다.** 파일을 주고받지 않는다.

- **주소** — https://safety-report-poc.vercel.app/deck/ (PC 첫 화면 오른쪽 위 '발표자료' 단추)
- **공개 범위** — 검색엔진에는 안 걸리게 `noindex`를 달았다. 하지만 저장소와 사이트가 공개라 **주소를 아는 사람은 누구나 본다.** 공개하면 안 되는 내용은 넣지 않는다.
- **원본** — `public/deck/index.html` 한 파일. 빌드를 거치지 않고 그대로 `/deck/`에 배포된다. 그림·영상은 `public/deck/assets/`.
- **고치는 법**
  1. GitHub 웹에서 파일 연필 단추로 고치거나, 브랜치에서 고쳐 PR을 연다(12장).
  2. `main`에 합쳐지면 1~2분 뒤 사이트에 반영된다.
  3. 로컬에서 볼 때는 `npm run dev` 후 http://localhost:3000/deck/ — 또는 파일을 브라우저로 바로 연다.
- **구조**
  - 장(슬라이드) 하나 = `<section class="slide">`. 순서를 바꾸면 쪽 번호는 저절로 맞는다.
  - 누를 때마다 나오는 조각 = `class="f"`(또는 `pop`) + `data-step="n"`, 장에는 `data-steps="최대 n"`.
  - 발표자 노트 = 각 장의 `<aside class="notes">`.
- **발표할 때** — →/← 또는 클릭으로 넘김, N 발표자 노트, F 전체 화면. 영상은 아래 재생바, P(K) 재생/멈춤, J/L 10초 뒤·앞.
- **고친 뒤 조판 점검** — 외톨이 줄·어절 쪼개짐·내어쓰기를 잡는다. '문제 없음'이 나와야 한다.
  ```bash
  npm i --no-save playwright && npx playwright install chromium   # 처음 한 번
  node scripts/deck-check.mjs
  ```
- **표기 원칙** — '첫 번째 사진·두 번째 사진', 흐름은 하나, 불수용률(20.7%)은 6장 '핵심 문제'에서 한 번만. 숫자를 바꾸면 각주의 출처도 같이 고친다. 채점·인터뷰 결과 칸(테두리 숫자·○ 표시)은 결과가 나오면 채운다.
- **시연 영상**(`assets/demo-current.webm`, `assets/demo-improved.webm`)
  - 지금 앱: 실제 앱 화면 캡처(위치·전화번호 가림)로 신고 순서를 따라간다. 캡처가 없는 동작은 팀원 조작 기록을 설명 상자로 보여 준다.
  - 개선안: 이 저장소의 웹 화면을 실제로 녹화했다. 사진은 시험용 AI 생성 이미지(번호판 가상), 판독 결과는 시험값.
  - 두 영상 모두 해설 음성(마이크로소프트 한국어 남성 음성)이 들어 있다.
  - **영상 다시 만들기는 아직 저장소 밖 도구로 한다**(14장 기술부채). 화면이 바뀌어 영상을 고쳐야 하면 호용에게 요청한다.

## 11. 배포

- Vercel. 정적 화면(`dist/`)과 `api/` 함수를 한 번에 올린다.
- data.go.kr은 브라우저에서 부르면 CORS에 막히고, AI 키는 화면에 둘 수 없어 **함수 중계가 필수**다.
- `main`에 올리면 배포본이 바뀐다고 보고 작업한다. **push는 곧 배포** — 팀에 알리고 올린다.
- 보안 헤더(`vercel.json`): 카메라·위치는 이 사이트에서만, `nosniff`, `strict-origin-when-cross-origin`.
- **빌드 표식** — PC 화면 오른쪽 아래에 커밋 해시와 빌드 시각이 보인다. "방금 고친 게 올라갔나"는 이걸로 확인한다(`+`가 붙으면 커밋하지 않은 변경이 섞인 빌드).

## 12. 팀 작업 방법

여럿이 같은 저장소에 올리므로 아래를 지킨다.

1. **`main`에 바로 올리지 않는다.** 브랜치(`이름/할일`, 예: `chiguk/review-chart`)에서 작업하고 PR을 연다.
2. PR에는 무엇을·왜 바꿨는지, 화면이 바뀌면 캡처를 붙인다. CI가 초록이어야 합친다.
3. 커밋 메시지는 한국어로, 첫 줄에 "무엇 — 왜"를 적는다(지금 기록과 같은 형식).
4. **올리면 안 되는 것**: `.env.local`, 채점 사진·`answers.csv`, 실제 앱 캡처 **원본**(전화번호·위치 등 개인정보가 찍힘), 엑셀 잠금 파일. 개인정보를 가린 발표 영상(`public/deck/assets/`)은 예외.
5. 규칙(1장)을 바꾸는 결정, 기준값(5장)을 바꾸는 결정은 `docs/design.md`에 날짜와 함께 적는다.
6. 새 파일을 만들면 4장의 파일 지도에 한 줄을 더한다. **README가 코드보다 늦으면 그게 기술부채다.**

고치면 이 표에서 지우고 커밋 메시지에 적는다.

| 구분 | 내용 | 어디 | 갚는 법 |
| --- | --- | --- | --- |
| 비용 | 공개 배포에서 누구나 `/api/vision`을 불러 Gemini 사용량을 소진할 수 있다 | `api/vision.ts` | 날짜·IP별 호출 상한(내구 저장소 필요 — Vercel KV 등). 팀원 저장소 `src/server/quota.ts` 참고 |

## 15. 발표·현장 확인 전 점검표

- [ ] `INTERVAL_SEC`를 `MIN_INTERVAL_SEC`(60)로 되돌렸다 — 화면에 '테스트용' 표시가 없어야 한다
- [ ] `npm run lint` · `npm test` · `npm run build` 모두 통과
- [ ] Vercel 환경변수(브이월드·Gemini·data.go.kr 키)가 살아 있다 — 배포본에서 주소·판독이 실제로 채워진다
- [ ] Gemini 무료 사용량이 남아 있다(발표 직전 여러 번 찍으면 막힐 수 있다)
- [ ] 휴대폰에서 카메라·위치 권한이 뜨고 후면 카메라로 열린다
- [ ] 시험용 사진 30장 채점을 **한 번만** 돌리고 결과를 저장했다
- [ ] 화면에 '시제품' 같은 쓰지 않는 말이 없다
