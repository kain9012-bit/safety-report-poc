# 주정차 신고 자동작성 (safety-report-poc)

안전신문고 **불법주정차 신고**를 어떻게 고치면 좋을지 보여 주는 **개선 제안용 비공식 화면**이다.
2조 「신고해도 될까요」가 국민제안으로 낼 개선안의 근거 자료로 만든다. **실제 신고는 접수되지 않는다.**

**현재 작업 방식 — 로컬 웹·iPhone 앱 + GitHub 푸시(2026-10-15)**

운영 서버 전환은 보류하고 로컬 웹과 Xcode 앱을 함께 관리한다. 기존 화면·순서를 유지하면서 응답 호환과 상세 분석 누락 검증을 보완했다. [변경 내용·409개 웹 테스트·앱 빌드·로컬 분석 결과](docs/local-app-release-2026-10-15.md).

**후속 수정 — 기존 흐름 유지(2026-10-15)**

기능 개선 때문에 확인 항목과 촬영 진입이 복잡해졌다는 피드백을 반영했다. 웹의 기존 5단계는 유지하고 상세 질문·사진 관리 기능을 선택 항목으로 접었다. iPhone은 홈에서 촬영을 시작하고 `사진 촬영 → 촬영본 확인 → 기기에 보관`으로 진행한다. 원본 보존과 분석 기준은 유지한다. [변경 이유와 검증](docs/citizen-capture-implementation-2026-10-15.md#후속-수정--기존-신고-흐름-유지-2026-10-15).

**최근 수정 — 민원인 촬영·사진 근거 확인(2026-10-15)**

- 기본 6개와 전용구역 3개, 기타까지 **10개 유형**을 선택한다. AI의 사진 관찰 대상은 기타를 제외한 9개이며, 사진 관찰·사용자 확인·지도 참고·법적 적용 미확인을 구분한다.
- 기본 사진 두 장을 따로 지정하고 보완사진은 역할을 붙여 추가한다. 원본을 보존하며 작은 표시를 원본 부분으로 다시 읽는다. 분석 실패나 GPS 미수신 때문에 사진 보관을 중단하지 않는다.
- GPS 품질·사진별 촬영 방향·여러 정류소 후보·지도에서 지정한 차량 위치를 기록한다. 일반차 병행주차 안내는 적용 칸·시간·조건을 재확인하고 모르면 미확인으로 남긴다.
- SwiftUI·AVFoundation iPhone 소스와 Xcode 프로젝트를 `ios/ParkingGuide/`에 함께 제공한다. 플랫폼별 동작 차이와 검증 상태는 [개선 내용·기술 변화·검증 기록](docs/citizen-capture-implementation-2026-10-15.md)에 적었다.
- 이전 [자료 보존·점검 수정(2026-10-12)](docs/preservation-precheck-2026-10-12.md)의 기존 자료 보존·저장 실패 처리·번호판 점검은 이어 유지한다. 해당 문서의 테스트 수는 당시 결과다.

이번 작업 브랜치는 `codex/preserve-evidence-precheck`이다. 브랜치 push, `main` 병합, 배포 반영은 서로 다른 상태이며 배포본은 빌드 표식으로 별도 확인한다.

- 배포본: https://safety-report-poc.vercel.app
  - `/` — 신고 화면(휴대폰 기준)
  - `/eval.html` — 판독 채점(팀원용). PC 화면에서만 오른쪽 위에 들어가는 단추가 보인다.
- 한 문장: **사진부터 찍으면, 신고서는 앱이 쓴다.**

> 이 저장소의 화면은 안전신문고 앱이 아니다. 기관 로고·명칭·접수번호를 만들지 않고,
> 모든 화면 맨 위에 비공식 화면이라는 띠를 단다.

## 1. 먼저 읽기 — 지켜야 할 원칙

새 기능을 붙이거나 코드를 고치기 전에 아래와 어긋나지 않는지 본다. 어긋나야 한다면 팀에서 먼저 정하고
`docs/design.md`의 결정 기록에 남긴다.

| 원칙 | 뜻 | 코드에서 지키는 곳 |
| --- | --- | --- |
| **사진 관찰과 적용 조건을 분리** | AI는 9개 유형의 표시 식별·대상 장소 연결·차량 관계·경계·읽은 문구를 각각 답한다. 규칙은 관찰의 연결·상충을 검사한다. 실제 거리와 법적 적용은 별도 미확인으로 남긴다. | `api/vision.ts`, `src/lib/evidence.ts` |
| **사진 근거와 위치 참고를 구분** | GPS·지도·시설 자료는 주변 후보를 찾는 참고다. 사진 근거가 부족하면 기존 원본부터 확인하고 필요한 역할의 보완만 안내한다. 미확인으로 보관할 수 있다. | `evidence.ts`, `recommend.ts`, `StopReview.tsx` |
| **관찰 출처와 사진 연결을 보존** | 기본 사진의 번호판은 각각 읽는다. 보완사진에는 같은 차량·장소인지 확인할 기본 사진을 명시해 전달한다. 사람이 고른 유형·검색 영역·주변 위치가 자동 인식의 정답이 되지 않는다. | `api/vision.ts`, `vision.ts`, `photoEvidence.ts` |
| **없는 값을 지어내지 않는다** | 키가 없거나 판독이 안 되면 칸을 비우고 이유를 적는다. 표본 값으로 화면을 채우지 않는다. | `reverseGeocode.ts`, `compose.ts` |
| **실제 기관 화면을 흉내 내지 않는다** | 로고·기관명·접수번호·로그인·범죄예방 메뉴·이벤트 띠를 만들지 않는다. | `src/components/Ui.tsx`(비공식 화면 띠) |
| **서버 비밀과 공개 지도 키를 구분** | AI·공공데이터·REST 비밀 키는 서버에만 둔다. 선택 사항인 `VITE_KAKAO_MAP_JS_KEY`만 공개 JavaScript 키이며 등록 도메인을 제한한다. | `.env.example`, `mapProvider.ts` |
| **규칙은 어디서 돌든 같은 답** | 판정 규칙 파일은 화면·브라우저·네트워크·기기 현지 시각에 기대지 않는다. 기한·단속 시간·촬영시각은 **한국 시각**으로 따진다. | `src/lib/purity.test.ts`, `src/lib/kst.ts` |
| **오래된 규정으로 안내하지 않는다** | 지자체 규정은 출처·확인일과 함께 둔다. 확인한 지 180일이 넘으면 경고, 365일이 넘으면 그 지역 값을 쓰지 않고 전국 기준으로 돌아간다. | `src/lib/localRules.ts` `ruleFreshness` |
| **자료 보존 범위를 명시** | 사진·촬영 위치·품질·선택 위치는 해당 기기의 초안에 저장한다. 서버 함수는 사진·좌표를 별도 보관하지 않는다. 실제 사진·정답표·비밀 키·개인 서명 설정은 Git에 넣지 않는다. | `reports.ts`, `types/report.ts`, `ios/ParkingGuide/`, `.gitignore` |

## 2. 화면 흐름

```
처음 화면 → 사진 두 장 촬영 / 앨범 선택 / 보관함 이어하기
   ↓
기본 사진 두 장 지정 → 촬영 시각·번호판·겹침 점검
   ↓
사진 근거 확인 → 전체 장면 → 필요한 원본 부분 → 표시·장소·차량 관계 확인
   ↓
유형 선택 → 필요한 보완사진·확인 질문 → 위치·차량번호·내용 작성
   ↓
점검·내용 미리 보기 → 기기에 기록 저장 (공식 신고 접수 아님)
```

- **10개 유형** — 기본 6개, 장애인전용주차구역·소방차전용구역·친환경차 충전·전용구역, 기타. 기타는 직접 확인하며 기본 6개용 규정을 전용구역·기타에 복사하지 않는다.
- **촬영과 분석 분리** — 첫 사진 분석이 끝나지 않아도 두 번째 촬영으로 진행한다. GPS를 받지 못해도 촬영할 수 있다. 저장과 AI 성공은 서로 다른 상태다.
- **기본 사진과 보완사진** — 시간·번호판·겹침 점검은 지정한 기본 두 장을 쓴다. 보완사진은 기존 사진을 덮어쓰지 않으며 한 장에 차량·표시·연결·주변 맥락 등 여러 역할을 붙일 수 있다.
- **이어하기·보관** — 웹은 IndexedDB에 저장한다. 36시간 이내 초안은 자동 이어하기 대상이며 더 오래된 기록도 보관함에 남긴다. 자동 삭제하지 않는다. 브라우저 데이터 삭제·저장소 회수와 기기 간 동기화는 별도 문제다.
- **재촬영·저장 실패** — 새 자료 저장이 완료되기 전까지 기존 자료와 수동 입력을 유지한다. 취소·실패 시 돌아가거나 재시도한다. 보완사진을 준비 중일 때는 이동·저장을 잠시 막아 미완료 자료가 빠지지 않게 한다.
- **앨범 촬영시각** — EXIF에 촬영시각이 없으면 파일 수정시각으로 대체해 표시하지 않는다. 촬영시각·간격은 미확인으로 남긴다.
- **사진이 바뀐 뒤** — 기본 쌍·역할·선택 대상·관찰이 달라지면 이전 확인 답변과 병행주차 답변을 삭제하지 않고 재확인 대상으로 표시한다. 수동 주소·본문·유형은 자동 응답이 덮어쓰지 않는다.
- **검토용 요약** — 사진에서 관찰한 내용과 미확인 항목을 함께 기록한다. 요약이 실제 거리 측정·관할 검토·신고 수용을 대신하지 않는다.

## 3. AI·규칙·사람이 하는 일

| 단계 | 하는 쪽 | 무엇을 | 파일 |
| --- | --- | --- | --- |
| 첫 번째 사진 촬영 | 사람 | 찍는다. 찍는 순간 촬영시각·좌표를 사진에 새긴다 | `src/lib/camera.ts` |
| 장면·번호판 읽기 | **AI** | 장면 11항목(6대 6개 + 6대 밖 5개: 장애인 구역·표지, 소방차 구역, 충전구역, 친환경차 표시) 보임/아님/모름, 9개 유형별 관찰(표시 식별·대상 연결·차량 관계·경계), 번호판 글자, 근거 상자. 작은 표시는 원본 부분을 최대 두 곳 다시 본다 | `api/vision.ts`, `src/lib/vision.ts` |
| 장면 → 유형 | 규칙 | 새 응답은 표시·대상·차량 관계가 연결된 유형만, 이전 응답은 보임 항목을 유형으로 바꾼다(표지 붙은 차·친환경차는 뺌). AI가 따로 낸 유형과 다르면 확신도를 낮춘다 | `api/vision.ts` `mergeReads`·`typesFromScene`, `src/lib/evidence.ts` |
| 사진 증거 판정 | 규칙 | 확신도 0.5 이상이어야 유형을 채운다. 위치자료는 일치 여부만 덧붙인다 | `src/lib/crosscheck.ts` |
| 부적합 안내 | 규칙 | 근거·번호판이 안 보이면 이유를 알리고 첫 번째 사진을 다시 찍게 한다 | `src/components/CaptureFlow.tsx` |
| 유형 추천 | 규칙 | 사진 근거가 연결된 후보만 보여 준다. 과태료·위치자료 근접으로 순서를 바꾸지 않는다 | `src/lib/choose.ts` |
| 유형 선택 | 사람 | 여럿이면 고른다 | |
| 지자체 규정 | 규칙 | 주소로 관할을 찾아 간격·단속 시간·접수 기한 적용(없거나 오래되면 전국 기준). 6대 밖 3개 유형·기타는 전국 1분 간격·24시간 | `src/lib/localRules.ts` |
| 남은 시간 알림 | 규칙 | 0초에 소리·진동·시스템 알림·탭 제목 | `src/lib/alert.ts` |
| 같은 자리 | 규칙 | 두 사진 윤곽 대조, 겹침 50%·닮음 0.45 이상 | `src/lib/overlap.ts` |
| 같은 차 | 규칙 | 두 장에서 **따로** 읽은 번호의 형식이 맞고 각각 확신도 0.8 이상이며 번호가 같을 때 일치로 표시 | `api/vision.ts` `mergeReads` |
| 주소 | 규칙(외부 API) | 좌표 → 도로명주소 | `api/address.ts` |
| 내용 작성 | 규칙 | 있는 값만 이어 붙인 개조식 문장 | `src/lib/compose.ts` |
| 담당자용 점검 요약 | 규칙 | 잰 값·적용 규정·확인 필요 항목을 내용 끝에 붙임(900자 안) | `src/lib/officer.ts` |
| 번호판 확대 | 규칙 | AI가 짚은 번호판 자리를 두 사진에서 잘라 나란히 보여 줌 | `src/components/FormParts.tsx` `PlateZoom` |
| 제출 전 점검 | 규칙 | 최종 입력 번호까지 대조하고 빨강이면 제출을 막는다. 화면에서 주기적으로 갱신하며 제출 클릭 시 다시 검사한다 | `src/lib/precheck.ts`, `src/lib/rules.ts`, `src/App.tsx` |
| 확인·제출 | 사람 | 채워진 칸을 확인하고 낸다 | `src/components/ReportSteps.tsx` |

작업 브랜치에서 만든 화면 부품은 파일로만 두고 화면에 연결하지 않았다 — 사진 근거 검토·보완 촬영·확인 질문·병행주차(`EvidenceWorkspace.tsx`), 여러 정류소 비교(`StopReview.tsx`), 정류소·차량 위치 지도(`EvidencePickMap.tsx`). 연결 범위는 기능별 계획을 확인한 뒤 정한다.

### 제출 전 점검 항목

`rules.ts`의 `runChecks`(기본 5개) 위에 `precheck.ts`가 사진과 규정에 따라 최대 7개를 더한다(6대 밖 유형·기타면 1개 더 — `extraTypes.ts`). **빨강(fail) 하나라도 있으면 제출 불가**, 노랑(warn)은 알리기만 한다. 6대 밖 3개 유형·기타도 회의 결정(2026-10-09)대로 같은 규정(사진 2장·1분 간격)을 쓴다.

| 항목 | 출처 | 막는 경우 |
| --- | --- | --- |
| 두 사진 간격 | rules | 지자체 간격 미만 |
| 접수 기한 | rules | 촬영일로부터 `deadlineDays`일 뒤 23:59:59.999 경과 — 한국 시각 |
| 촬영시각 표시 | rules | 사진에 촬영시각 없음 |
| 차량번호 | rules | 입력한 번호가 비어 있거나 번호판 형식과 다름 |
| 위치 | rules | 좌표 없음 |
| 위반유형 사진 증거 | precheck | 유형이 비어 있음(직접 고른 유형이 사진 판정과 다르면 경고) |
| 서로 다른 촬영본 | precheck | 같은 사진을 두 장으로 지정함 |
| 두 장 번호판 일치 | precheck (`mergeReads` 결과 대조) | 한 장이라도 판독 누락·형식 오류·확신도 0.8 미만, 두 번호 불일치, 또는 최종 입력 번호가 판독 번호와 다름 |
| 같은 자리 두 장 | precheck | 겹침 50% 미만 |
| 단속 시간 | precheck | 두 사진 중 하나라도 그 유형 단속 시간 밖(예: 어린이보호구역 주말) |
| 장애인자동차표지 | extraTypes | 막지 않음 — 표지가 보이면 위반이 아닐 수 있다고, 앞유리가 안 보이면 표지 자리가 보이게 찍으라고 경고. 표지 유효성·사용 조건은 사진으로 확정하지 않음 |
| 일반차 여부 | extraTypes | 막지 않음 — 친환경차 표시가 보이면 위반이 아닐 수 있다고(구역마다 허용 차종이 다름), 번호판 색이 안 보이면 확인하라고 경고 |
| 기타 유형 | extraTypes | 막지 않음 — 자동 판독 대상이 아니니 위반 내용을 적고 근거가 사진에 보이는지 확인하라고 경고 |
| 소방차전용구역 대상 건물 | extraTypes | 막지 않음 — 2018. 8. 10. 이후 건축허가 100세대 이상 아파트·3층 이상 기숙사만 과태료 대상이라고 경고 |
| 앨범 사진 진위 | precheck | 편집 흔적·촬영시각 없음·지역별 접수 기한 경과 등 |
| 발생지역 | precheck | 좌표도 주소도 없음(좌표만 있으면 경고) |
| 내용 | precheck | 5자 미만 |

## 5. 기준값 — 바꿀 때 여기부터

숫자는 한 곳에만 둔다. 바꾸면 **같은 파일의 시험(`*.test.ts`)을 함께 고치고**, 이유를 `docs/design.md`에 적는다.

| 이름 | 파일 | 지금 값 | 뜻 | 바꿀 때 주의 |
| --- | --- | --- | --- | --- |
| `INTERVAL_SEC` | `src/lib/rules.ts` | **3 (시험용)** | 두 사진 간격으로 실제로 쓰는 값 | **발표·현장 확인 전 `MIN_INTERVAL_SEC`(60)로 되돌린다.** 화면에 '테스트용' 표시가 자동으로 붙는다 |
| `MIN_INTERVAL_SEC` | `src/lib/rules.ts` | 60 | 실제 신고 기준 간격 | 법령·안내 기준. 임의로 바꾸지 않는다 |

## 8. 서버 함수와 외부 자료

### 서버 함수(`api/`)

| 경로 | 바깥 서비스 | 캐시·기록 |
| --- | --- | --- |
| `GET /api/address?lat=&lng=` | 브이월드 지오코더 / 카카오 | 좌표는 기록·캐시하지 않음 |
| `GET /api/stops?lat=&lng=` | 국토교통부 TAGO 버스정류소(반경 500m) | 기록·캐시하지 않음 |
| `GET /api/tile?layer=&z=&x=&y=` | 브이월드 WMTS | 타일 번호만 오가므로 CDN에 오래 캐시 |
| `POST /api/vision` | Gemini | 서버에 사진을 별도 저장하지 않음. 기본 사진 독립 관찰, 필요한 원본 부분과 보완사진의 기준 사진을 명시 |

- 각 함수는 **다른 파일을 import 하지 않는다.** Vercel이 함수별로 따로 묶어도 깨지지 않게 하려는 것이다. 공통 코드가 필요하면 복사하고 주석으로 짝을 밝힌다.
- 함수 지역은 서울(`icn1`). 국내 공공 API가 해외 IP를 막는 경우가 있다.

### 주정차금지(지정)구역(`public/noparking/`) — 촬영 화면의 '참고' 안내

```bash
python scripts/collect_noparking.py    # 같은 키. 전국 약 1만 7천 구간, 17쪽
```

- 출처: [전국주정차금지(지정)구역표준데이터 data.go.kr 15034542](https://www.data.go.kr/data/15034542/standard.do) — 2026-10-12 기준 16개 시도·145개 시군구, 16,955구간. 전국을 다 덮지 않는다(예: 전주시 없음).
- **좌표가 없다.** 항목 28개 중 위치는 도로명·구간 설명·금지 총연장뿐이고, 나머지는 요일별 금지 시간·허용 시간(점심 유예)·기준일·관리기관이다. 그래서 좌표 대신 도로명으로 맞춘다.
- 맞추는 순서(`src/lib/noParking.ts`·`noParkingData.ts`)
  1. 휴대폰 위치 → 도로명주소(`/api/address`, 브이월드·카카오)
  2. 주소에서 도로명만 뽑기 — 건물번호 바로 앞 '○○로·○○길'. '세종로 79번길'처럼 띄어 쓴 번길은 붙인다
  3. 시군구 찾기 — `index.json`의 시군구 이름. 양주시≠남양주시, 같은 이름의 구(중구 등)는 시도로 가린다. 바뀐 시도 이름(전라북도→전북특별자치도 등)도 맞춘다
  4. 그 시군구 파일(`{시군구코드}.json`)에서 **도로명이 같은 구간**만 고르기 — '세종로'가 '세종로45번길'에 걸리지 않게 뒤 글자까지 본다
  5. 첫 구간의 오늘 요일 시간을 지금 한국 시각과 비교 → '지금 단속 시간' / '지금은 단속 시간 아님' / 시간 정보 없음
  6. 도로명주소가 아니거나(지번만 나옴) 자료에 없는 시군구, 받기 실패면 안내를 띄우지 않는다. 신고 흐름은 막지 않는다
- 화면 문구에는 언제나 '참고', 구간 설명, 기준일, "구간 밖이거나 표지판과 다를 수 있어 참고만"을 붙인다.
- 촬영 화면에 "참고 · 주정차금지 구간 ○○로 — 평일 09:00~18:00(11:00~14:00 허용) · 지금 단속 시간"과 기준일을 보여 준다. 같은 도로라도 구간 밖일 수 있고 표지판이 우선이라, **판정(유형·수용)에는 쓰지 않는다.**
- 공휴일 목록이 없어 일요일만 '일요일·공휴일' 칸으로 본다. 토요일 00:00~00:00은 자료상 단속 시간 없음으로 본다.
- **좌표를 만들 수 있나(2026-10-13 확인)** — 공개 자료 중 금지구역 좌표는 못 찾았다(서울 '불법주정차 단속 정보'는 단속 지점 기록이라 다르다). 구간 설명을 주소 검색으로 좌표로 바꾸는 방법은 일부만 된다. 16,955건을 정규식으로 대략 나누면:

  | 구간 설명 형태 | 비중 | 좌표로 바꾸기 |
  | --- | --- | --- |
  | 주소·지번이 적힘(한 지점 16.0%, 구간 양끝 11.6%) | 약 28% | 주소 검색으로 비교적 정확 |
  | 구간 한쪽만 주소 | 약 7% | 한쪽만 |
  | 장소 이름(학교·교차로·아파트) | 약 28% | 장소 검색 — 같은 이름이 많아 부정확 |
  | 도로명만 | 약 38% | 도로 전체 선으로만 |

  주소 검색 키가 `.env.local`에 없어 실제 변환 시험은 하지 않았다. 정확도를 크게 못 올리므로 PoC는 도로명 맞추기를 유지한다.
- `.env.local`을 윈도우에서 만들면 줄 끝에 `\r`이 붙는다. 셸에서 `. ./.env.local`로 읽으면 키에 `\r`이 섞여 '등록되지 않은 서비스키'가 난다(스크립트는 떼고 읽는다).

### 지자체 규정 추가 절차

1. 그 지자체의 주민신고제 공식 안내 페이지를 찾는다(블로그·뉴스 말고 지자체 누리집).
2. `src/lib/localRules.ts`의 `LOCAL_RULES`에 `region`·`match`(주소 정규식)·`types`·`extra`·`source`·`checkedAt`을 적는다.
3. `src/lib/localRules.test.ts`에 그 지역 주소로 간격·단속 시간 시험을 하나 더한다.
4. 표에 없는 지자체는 전국 기준을 쓰고 화면에 '전국 기준'이라고 밝힌다 — 이 동작은 바꾸지 않는다.
5. `match`는 시·도 이름부터 맞춘다(예: `/^대전(광역시)?\s+동구/`). '동구'만 쓰면 부산·인천 동구에도 걸린다.
6. 규정을 다시 확인하면 `checkedAt`만 고쳐도 신선도 경고가 풀린다. 출처가 바뀌었으면 `source`도 고친다.

대전 동구·중구·대덕구(2026-09-18). 서울·대전은 팀원 저장소 [kjy-arch/parking-report](https://github.com/kjy-arch/parking-report)의

- 최신 전체 시험 수·빌드·브라우저 확인·iPhone 상태는 [2026-10-15 검증 기록](docs/citizen-capture-implementation-2026-10-15.md#검증-기록)을 기준으로 한다. 개별 실행 횟수를 더해 통과 개수로 세지 않는다.
- 화면 회귀시험은 React Testing Library·jsdom, 저장소 회귀시험은 fake-indexeddb를 쓴다. App 통합시험의 카메라·외부 판독·저장 함수는 모의 구현이며 실제 기기 촬영이나 저장공간 부족을 검증한 결과는 아니다.
- **아직 자동 시험이 없는 곳**: 전체 촬영·앨범·신고 동선 E2E, 위 표에 없는 화면 동작, 브라우저 기능에 기대는 `alert.ts`·`album.ts`·`camera.ts`·`overlap.ts`의 그림 처리. 실제 기기와 현장 사진 검증은 별도로 진행한다.
- CI(`.github/workflows/ci.yml`): main push와 PR마다 **타입 검사 → 단위 시험 → 다른 시간대(미국 서부)에서 다시 시험 → 빌드**. 빨간불이면 합치지 않는다.

## 10. 판독 채점

AI+규칙이 위반 유형과 번호판을 얼마나 맞히는지 **사진 1장 기준**으로 잰다. 자세한 순서는 `data/samples/README.md`.

- 목표: 유형 정답률 95%, 번호판 오채움 0건.
- 사진 약 100장(본인·팀원 차량만). 70장은 '개선'(고치면서 반복), 30장은 '시험'(**발표 직전 한 번만**).
- `/eval.html`에서 정답표(CSV)와 사진 폴더를 고르면 앱과 같은 경로(줄이기 → `/api/vision` → `crosscheck`·`rankTypes`·번호판 기준)로 돌린다(`src/eval/run.ts`).
- 100장 중 95장을 맞혀도 실제 범위는 약 89~98%다. 화면의 '실제 범위'를 함께 말한다.

## 10-1. 발표자료

최종 발표자료는 **저장소 안에서 같이 고친다.** 파일을 주고받지 않는다.

- **주소** — https://safety-report-poc.vercel.app/deck/ (PC 첫 화면 오른쪽 위 '발표자료' 단추)
- **공개 범위** — 검색엔진에는 안 걸리게 `noindex`를 달았다. 하지만 저장소와 사이트가 공개라 **주소를 아는 사람은 누구나 본다.** 공개하면 안 되는 내용은 넣지 않는다.
- **원본** — `public/deck/index.html` 한 파일. 빌드를 거치지 않고 그대로 `/deck/`에 배포된다. 그림·영상은 `public/deck/assets/`.
- **고치는 법**
  1. GitHub 웹에서 파일 연필 단추로 고치거나, 브랜치에서 고쳐 PR을 연다(12장).
  2. `main`에 합쳐지면 1~2분 뒤 사이트에 반영된다.
  3. 로컬에서 볼 때는 `npm run dev` 후 http://localhost:3000/deck/ — 또는 파일을 브라우저로 바로 연다.
- **구조**
  - 장(슬라이드) 하나 = `<section class="slide">`. 순서를 바꾸면 쪽 번호는 저절로 맞는다.
  - 누를 때마다 나오는 조각 = `class="f"`(또는 `pop`) + `data-step="n"`, 장에는 `data-steps="최대 n"`.
  - 발표자 노트 = 각 장의 `<aside class="notes">`.
- **발표할 때** — →/← 또는 클릭으로 넘김, N 발표자 노트, F 전체 화면. 영상은 아래 재생바, P(K) 재생/멈춤, J/L 10초 뒤·앞.
- **고친 뒤 조판 점검** — 외톨이 줄·어절 쪼개짐·내어쓰기를 잡는다. '문제 없음'이 나와야 한다.
  ```bash
  npm i --no-save playwright && npx playwright install chromium   # 처음 한 번
  node scripts/deck-check.mjs
  ```
- **기사 캡처**(`assets/press-*.png`) — 기사 제목과 해당 문장만 잘라 출처·날짜를 붙였다(형광은 우리 표시). 원문 주소는 `docs/news-clips/README.md`.
- **불수용 사유 장** — 숫자는 `python scripts/nonaccept-reasons.py`로 다시 셀 수 있다(원자료는 `data/opendata/raw/`).
- **표기 원칙** — '첫 번째 사진·두 번째 사진', 흐름은 하나, 불수용률(20.7%)은 6장 '핵심 문제'에서 한 번만. 숫자를 바꾸면 각주의 출처도 같이 고친다. 채점·인터뷰 결과 칸(테두리 숫자·○ 표시)은 결과가 나오면 채운다.
- **시연 영상**(`assets/demo-current.webm`, `assets/demo-improved.webm`)
  - 지금 앱: 실제 앱 화면 캡처(위치·전화번호 가림)로 신고 순서를 따라간다. 캡처가 없는 동작은 팀원 조작 기록을 설명 상자로 보여 준다.
  - 개선안: 이 저장소의 웹 화면을 실제로 녹화했다. 사진은 시험용 AI 생성 이미지(번호판 가상), 판독 결과는 시험값.
  - 두 영상 모두 해설 음성(마이크로소프트 한국어 남성 음성)이 들어 있다.
  - **영상 다시 만들기는 아직 저장소 밖 도구로 한다**(14장 기술부채). 화면이 바뀌어 영상을 고쳐야 하면 호용에게 요청한다.

## 11. 배포

- Vercel. 정적 화면(`dist/`)과 `api/` 함수를 한 번에 올린다.
- data.go.kr은 브라우저에서 부르면 CORS에 막히고, AI 키는 화면에 둘 수 없어 **함수 중계가 필수**다.
- Vercel에 연결된 배포 브랜치와 빌드 결과를 확인한다. 작업 브랜치 push만으로 `main` 병합·운영 배포 완료를 주장하지 않는다.
- 보안 헤더(`vercel.json`): 카메라·위치는 이 사이트에서만, `nosniff`, `strict-origin-when-cross-origin`.
- **빌드 표식** — PC 화면 오른쪽 아래에 커밋 해시와 빌드 시각이 보인다. "방금 고친 게 올라갔나"는 이걸로 확인한다(`+`가 붙으면 커밋하지 않은 변경이 섞인 빌드).

## 12. 팀 작업 방법

여럿이 같은 저장소에 올리므로 아래를 지킨다.

1. **`main`에 바로 올리지 않는다.** 브랜치(`이름/할일`, 예: `chiguk/review-chart`)에서 작업하고 PR을 연다.
2. PR에는 무엇을·왜 바꿨는지, 화면이 바뀌면 캡처를 붙인다. CI가 초록이어야 합친다.
3. 커밋 메시지는 한국어로, 첫 줄에 "무엇 — 왜"를 적는다(지금 기록과 같은 형식).
4. **올리면 안 되는 것**: `.env.local`, 채점 사진·`answers.csv`, 실제 앱 캡처 **원본**(전화번호·위치 등 개인정보가 찍힘), 엑셀 잠금 파일, 공공데이터 원자료(`data/opendata/raw/`, 120MB). 개인정보를 가린 발표 영상(`public/deck/assets/`)은 예외.
5. 규칙(1장)을 바꾸는 결정, 기준값(5장)을 바꾸는 결정은 `docs/design.md`에 날짜와 함께 적는다.
6. 새 파일을 만들면 4장의 파일 지도에 한 줄을 더한다. **README가 코드보다 늦으면 그게 기술부채다.**

## 15. 발표·현장 확인 전 점검표

- [ ] `INTERVAL_SEC`를 `MIN_INTERVAL_SEC`(60)로 되돌렸다 — 화면에 '테스트용' 표시가 없어야 한다
- [ ] `npm run lint` · `npm test` · `npm run build` 모두 통과
- [ ] Vercel 환경변수(브이월드·Gemini·data.go.kr 키)가 살아 있다 — 배포본에서 주소·판독이 실제로 채워진다
- [ ] Gemini 무료 사용량이 남아 있다(발표 직전 여러 번 찍으면 막힐 수 있다)
- [ ] 휴대폰에서 카메라·위치 권한이 뜨고 후면 카메라로 열린다
- [ ] 시험용 사진 30장 채점을 **한 번만** 돌리고 결과를 저장했다
- [ ] 비공식 개선 화면이며 실제 신고 접수가 아님을 표시한다
