# iPhone 앱 · ParkingGuide

웹과 함께 관리하는 SwiftUI·AVFoundation iPhone 소스입니다. 실제 신고를 제출하지 않는 촬영·기록·근거 확인용 시제품입니다.

최신 작업 방식은 **로컬 웹·앱 검증 후 GitHub 작업 브랜치에 푸시**이며 운영 서버 전환은 보류했습니다. [현재 검증 결과와 서버 연결의 한계](../docs/local-app-release-2026-10-15.md)를 확인하세요. 이번 실제 기기용 SDK 빌드는 서명 없이 통과했고, 앱 소스는 앞선 실기기 호환 시험 설치본과 동일합니다.

`ParkingGuide/ParkingGuide.xcodeproj`를 Xcode에서 열고 `ParkingGuide` scheme을 선택합니다. 이 배포본은 개발자 서명 팀을 비웠고 예시 bundle identifier를 사용합니다. 실기기 설치 시 본인의 서명 설정이 필요합니다. API 키·프로비저닝 프로파일·촬영 자료는 포함하지 않습니다.

## 실행 및 검증

저장소 루트에서 실행합니다. 이번 검증 환경은 Xcode 27, iOS 27 시뮬레이터이며 앱의 최소 배포 대상은 iOS 17입니다.

```sh
xcodebuild -project ios/ParkingGuide/ParkingGuide.xcodeproj \
  -scheme ParkingGuide -sdk iphoneos -configuration Debug \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO build

xcodebuild -project ios/ParkingGuide/ParkingGuide.xcodeproj \
  -scheme ParkingGuide -destination 'platform=iOS Simulator,name=iPhone 18 Pro' \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO test
```

실제 기기에 설치·실행하려면 Xcode에서 사용자의 팀과 기기를 선택해야 합니다. 기기 신뢰·개발자 모드 변경이 필요한 경우 사용자가 직접 설정합니다. 서명 없는 빌드 성공은 실기기 촬영 성공이나 인식 정확도 측정 결과가 아닙니다.

## 기본 흐름 — 웹 main 과 같은 순서 (2026-10-15)

사용자 결정 "팀원 화면(main)을 기준으로 하고 개선 로직은 뒤에서"에 따라 웹 main 의 순서·명칭에 맞췄습니다.

1. 처음 화면: `사진부터 찍기` · `앨범에서 2장 고르기` · 이어할 신고 · 제출한 신고. 하던 신고가 있으면 앱을 열 때 바로 이어서 엽니다(36시간 안).
2. 두 장 촬영: 첫 번째 사진 → 남은 시간(웹과 같이 지금은 시험용 3초, 실제 기준 60초) → 두 번째 사진. 두 번째 사진을 기다리고 찍는 동안 첫 번째 사진을 35% 잔상으로 겹쳐 같은 구도를 잡게 합니다.
3. 신고서 5단계: `유형 → 발생지역 → 차량번호 → 내용 → 점검·제출`. 제출은 개선 제안용이라 접수하지 않고 이 기기의 '제출한 신고'에 보관합니다.

화면에는 민원인이 할 일이 있을 때만 두 가지가 `유형` 단계에 나옵니다: 사진으로 해결되는 부족 사유가 있을 때 "…한 장 더 찍어 주세요"와 `한 장 더 찍기`(같은 사유는 한 번만), 친환경차 충전·전용구역에서 일반 자동차 주차 안내가 보일 때 질문 하나(있어요 / 없어요 / 모르겠어요). 유형은 사진에서 표시·대상 차량·경계가 모두 확인됐을 때만 채우고, 아니면 비워 두어 `유형선택`에서 고르게 합니다.

사진 근거·GPS 품질·카메라 방향·보완사진 연결은 뒤에서 기록만 합니다. 이전의 사진 근거 확인 화면·정류소 대조·구역 초안 보관함(`ZoneWorkspace`, `NativeEvidenceReviewView`, `BusStopReview`)과 홈의 3~5초 영상 촬영(`LegacyMediaHome`)은 코드만 남기고 화면에서 뺐습니다. 기기에 저장된 이전 초안·촬영본 파일은 지우지 않았습니다.

## 사진 근거 확인

- 기본 사진 두 장과 보완사진, 사진별 역할을 보관합니다. 기존 사진·영상 보관함도 유지합니다.
- 기본 6개 유형과 장애인·소방차·친환경차 구역, 기타를 직접 선택합니다. AI가 도착해도 선택·주소·작성 내용을 덮어쓰지 않습니다.
- 원본의 일부 영역을 지정해 다시 읽을 수 있습니다. 원본 파일은 바꾸지 않습니다.
- GPS 취득 시각·보고 오차·일관성과 가능한 경우 후면 카메라 방향을 촬영 시점에 기록합니다. 지도에서 선택한 차량 위치는 별도 값입니다.
- 일반차 병행주차 안내는 원문·해당 칸·촬영 시각·적용 조건을 기록합니다. 일반차 허용, 전기차 시간 연장, 법적 허용은 서로 구분합니다.
- 저장 실패·분석 실패·취소 시 기존 자료를 유지합니다. 새 원본의 저장이 끝나기 전에 이전 원본을 삭제하지 않습니다.

## 선택적인 서버 연결

처음 화면 아래의 ‘사진 판독 설정’(또는 `유형` 단계의 ‘판독 서버 설정’)에서 자신이 운영하거나 신뢰하는 HTTPS `/api/vision` 주소를 입력합니다. 사진 전송 동의는 첫 판독 때 한 번 묻고 기억하며, 같은 설정 화면에서 바꿀 수 있습니다. 설정과 동의가 있으면 두 장을 찍은 뒤 판독이 뒤에서 자동으로 실행됩니다. 앱에는 모델 API 키를 넣지 않습니다. 서버는 저장소의 `api/vision.ts`와 같은 응답 규약을 지원해야 합니다. 키는 서버 환경에서 설정합니다. 위치·주소·작성 내용은 AI 요청에 포함하지 않습니다.

정류소 조회는 같은 서버의 `/api/stops`를 사용하며, 주변 후보 조회에 위치 좌표를 보냅니다. 사진에서 읽은 공개 번호는 공급자의 내부 식별자와 구분합니다. 서버를 설정하지 않아도 수동 확인·사진 보관은 가능합니다.

## 웹과의 차이

- 지도는 iPhone MapKit, 웹은 선택적인 Kakao SDK와 기존 지도 대체 경로를 사용합니다. 같은 지도 공급자 화면이라는 뜻은 아닙니다.
- iPhone 분석은 사용자가 신뢰하는 서버를 설정하고 실행합니다. 웹의 서버 설정은 배포 환경변수로 관리합니다.
- iPhone의 기존 사진·짧은 영상 보관 기능을 유지합니다. GitHub 기준 웹에 기존 별도 로컬 웹의 영상 기능을 새로 이식한 것은 아닙니다.
- 화면 순서·명칭은 웹 main 과 같지만 아래 기능은 iPhone 에 아직 연결하지 않았습니다(직접 입력·점검 생략): 두 장 번호판 판독·대조와 차량번호 자동 채움, 좌표 → 주소 자동 입력과 위치찾기 지도, 촬영 전 주변 시설·주정차금지구역 안내, 첫 사진 즉시 판독·재촬영 안내, 두 사진 겹침 측정, 지역별 규정(간격·단속 시간·접수 기한), 촬영시각 표시 점검, 앨범 사진 진위 점검, 6대 밖 유형 추가 점검, 담당자 요약.
- iPhone 의 유형 자동 채움은 사진 관찰의 연결 확인만 기준으로 합니다. 웹은 여기에 AI 유형 판단의 일치(확신도)까지 함께 봅니다.
- 재촬영: 웹은 다시 찍는 장부터 뒤의 사진(보완사진 포함)을 후보에서 빼지만, iPhone 은 그 장만 바꾸고 보완사진은 남깁니다(기존 사진 보존 방식 유지).
- 양쪽의 기록은 자동 동기화되지 않습니다. 실기기·실제 사진 AI 정확도·인증된 외부 서비스 연결은 별도 검증 대상입니다.

개선별 기술 변화와 최신 검증 결과는 [공동 구현 기록](../docs/citizen-capture-implementation-2026-10-15.md)을 확인하세요.

2026-10-15 응답 호환 후속: `NativeVisionContract`가 최신 상세 근거와 구형 기본 설명을 구분합니다. 구형 응답은 사진별 원래 주장과 제한 안내만 보관하며, 상세 관찰·추천 유형을 임의로 만들거나 미지원 확대 요청을 반복하지 않습니다. 사진 ID/개수/입력 버전이 맞지 않는 응답은 적용하지 않습니다. 화면·촬영 순서는 이번 수정 전과 같습니다. 세부 검증·운영 서버 한계는 [공동 구현 기록](../docs/citizen-capture-implementation-2026-10-15.md)을 확인하세요.
