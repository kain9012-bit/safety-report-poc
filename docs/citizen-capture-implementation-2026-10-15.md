# 민원인 촬영·사진 근거 확인 — 구현·검증 기록

기록일: **2026-10-15**. 작업 브랜치: `codex/preserve-evidence-precheck`.

사용자의 “개선방안을 적용해서 푸시해.”와 후속 “ㄱㄱ”에 따라 기존 계획을 웹과 Xcode 기반 iPhone 앱에 구현하고 기록·검증·커밋·push를 진행한다. 이전 계획 문서의 “구현 대기”, “푸시 직전까지”는 당시 협의 상태다. 항목별 수락 원문은 바꾸지 않으며 이후 포괄 실행 지시와 구분한다. 구현 중 정한 지도 공급자·GPS 기준값은 아래와 같이 실제 선택과 한계를 적는다.

**원격 반영 완료:** 2026-10-15 기능 커밋 [`485a27c`](https://github.com/kain9012-bit/safety-report-poc/commit/485a27cf89e3fc56fae4b2cffb01c06e861116ef)을 `origin/codex/preserve-evidence-precheck`에 정상 push하고 원격 커밋 일치를 확인했다. 이 문서는 그 결과를 남긴 후속 기록이다. `main` 병합과 운영 배포는 수행하지 않았다.

## 민원인에게 달라지는 점

1. 이미 찍은 사진은 그대로 두고 모자란 부분만 더 찍을 수 있다. 한 사진에 여러 역할을 붙일 수 있으며 기본 사진 두 장과 보완사진을 구별한다.
2. 사진 속 시설이 작으면 전체 사진을 본 뒤 원본의 일부를 다시 확인한다. 그래도 모르겠으면 모른다고 남긴다. 작은 표시를 찾았다는 이유만으로 그 차량의 위반이라고 확정하지 않는다.
3. 유형 이름만 보여 주지 않고 어떤 사진에서 무엇을 읽었고 무엇이 부족한지 보여 준다. 사진끼리 관찰이 다르면 서로 다르다고 알린다. 사람이 고른 유형을 뒤늦은 자동 응답이 바꾸지 않는다.
4. GPS가 늦거나 불안정해도 사진을 찍을 수 있다. 정류소는 가까운 한 곳으로 자동 확정하지 않고 사진 속 번호·방향·주변 여러 후보를 비교한다. 지도에서 움직인 위치는 직접 적용할 때만 저장한다.
5. 일반 자동차도 주차할 수 있다는 안내가 있으면 대상 칸·시간·조건을 다시 확인한다. 안내를 읽지 못했거나 적용 여부를 모르면 미확인으로 보관한다.
6. 사진이나 대상이 바뀌면 예전 답변을 지우지 않고 다시 확인할 내용으로 표시한다. 수동 주소·본문과 저장 전 기존 자료를 보존한다.

## 사진 분석을 바꾼 부분

- `identity`, `markingToTarget`, `vehicleRelation`, `boundary`, `chargerToTarget`를 `yes/no/unclear`로 분리한다. 관찰 문구·부족 사유·사진 ID·입력 버전도 저장한다. 모델이 반환한 거리·법적 확정·임의 출처를 신뢰하지 않는다.
- 서로 다른 사진의 “예”만 모아 완성된 관찰을 만들지 않는다. 한 사진 안에서 필요한 연결이 확인되어야 하며 서로 다른 관찰은 상충 상태로 남긴다.
- 전체 분석 사본은 긴 변 최대 1280px이다. 전체 사진 요청 묶음의 원본 부분 분석은 최대 2개로 제한하고 업스케일·생성형 복원으로 가린 정보를 만들지 않는다. 원본 파일을 바꾸지 않으며 부분 이미지를 새 촬영으로 세지 않는다.
- 부분 분석은 작은 시설의 종류·글씨를 보완할 수 있지만 전체 장면의 차량·장소 관계를 더 강하게 확정하지 못한다. 전체와 부분의 관찰이 반대면 미확인·재확인으로 내린다. 부분 분석 실패 때 전체 결과를 보존한다.
- 보완사진의 공간 근거는 현재 기본 사진 ID와 같은 차량·같은 장소 연결을 확인한 뒤 사용한다. 번호판만 같거나 주소만 같다는 이유로 같은 장소로 합치지 않는다. 기본 쌍이 바뀌면 연결을 재검토한다.
- 사진 결과가 늦게 도착해도 다른 초안·교체된 사진·바뀐 입력 버전에 적용하지 않는다. 수동 선택·입력은 별도 출처로 유지한다.

웹에서는 원본의 검색 영역을 사용자가 지정할 수 있다. 지정은 “여기를 살펴봐 달라”는 입력이며 정답 표시가 아니다. iPhone도 사진별 원본 영역 지정·저장·취소와 해당 영역을 사용한 분석을 지원한다.

## GPS·촬영 방향·정류소·지도

GPS의 최신성·단말 보고 오차·짧은 수신 이력의 일관성을 각각 관리한다. 같은 시각의 재수신을 새 측정으로 세지 않으며 셔터 뒤에 받은 위치를 과거 사진에 붙이지 않는다. 권한 거부·시간 초과·오래된 값은 이유와 함께 저장한다.

초기 설정은 최근 10초 이력, 서로 다른 시각 최소 3개, 최신성 5초, 보고 오차 20m/50m 경계, 요청 대기 15초다. 이 값은 **주변 탐색 안내용 설정**이며 실제 위치 오차의 보증·사진 속 차량 거리·법적 거리 기준이 아니다.

촬영 방향은 휴대폰 이동 방향으로 대신하지 않는다. 후면 카메라 광축과 기기 자세를 사용하며 진북 기준 여부·오차·최신성·수평 투영·급격한 변화가 충분하지 않으면 미확인으로 둔다. 웹 브라우저가 진북·오차를 제공하지 않는 환경에서는 방향을 확인된 값으로 꾸미지 않는다.

정류소의 사진 속 번호와 방향은 **그 정보를 제공한 사진**의 위치·촬영 시점에 연결한다. 반대편·이름이 같은 다른 정류소도 후보에서 구분한다. 지도 거리·방향은 탐색 보조이며 차량과 정류소 사이의 실제 거리를 확정하지 않는다. 선택한 정류소는 출처·식별자와 함께 저장하고 사진·기본 쌍·선택 위치·후보 정보가 바뀌면 재확인한다. API가 일부 페이지만 읽었거나 실패한 경우 완전한 목록으로 표시하지 않는다.

웹 지도는 공개 JavaScript 키를 설정하면 Kakao Maps SDK를 사용하며 미설정·로드 실패 때 기존 Leaflet/VWorld 경로를 사용한다. iPhone은 MapKit을 사용한다. 촬영 위치와 사용자가 지정한 차량 위치를 구분하고 적용 버튼 전까지 초안에 반영하지 않는다. 지도 이동이 수동 주소를 덮어쓰지 않는다. 인증된 실제 지도 연결의 검증 여부는 아래에 따로 적는다.

## 일반 자동차 병행주차 안내·재확인

사진에서 읽은 문구와 사람이 입력한 답변은 서로 구별한다. 안내 없음·안내 확인·확인 어려움을 기록하며 안내가 있다면 원문, 층·칸, 일반차 허용인지 전기차 시간 안내인지, 요일·시간·기간·이용 조건, 촬영 당시 적용 여부를 확인한다.

같은 칸에 적용되는지 모르거나 문구가 잘렸거나 시간이 불명확하면 허용·금지로 확정하지 않는다. 웹과 iPhone 모두 편집 후보를 따로 두어 기존 답변을 수정하다 취소할 수 있다. iPhone의 AI 원문 가져오기도 명시적으로 저장하기 전에는 기존 답변을 바꾸지 않는다. 사진·대상이 바뀌면 답을 유지한 채 다시 확인한다. iPhone의 안내 조건 확인 화면도 사진 시각을 한국 시각으로 명시한다. 사용자 작성 본문은 자동 문구로 덮어쓰지 않는다.

웹에는 명시적 한국 시각·완전한 시간 조건을 비교하는 보수적 계산 함수가 있지만 현재 입력 화면의 조건 문장을 자동으로 모두 해석하는 기능은 아니다. 화면은 사용자가 확인한 시간 적용 상태와 미확인을 기록한다. 법적 허용 여부는 계산 결과와 별도로 미확인이다.

## 검토 시 유의할 구현 한계

- 사진에 보이지 않는 실제 거리·공식 지정 경계·차량 자격·허가/운영 조건을 자동 확인한 결과가 아니다. 안내 문구가 있다는 사실과 해당 차량의 합법 여부를 합치지 않는다.
- 원본 부분 재검토는 누락을 줄이기 위한 제한된 검색이다. 흐림·가림·낮은 원본 해상도를 없애거나 모든 소화전을 찾아낸다고 보장하지 않는다.
- 카메라 방향·GPS 설정값·겹침 기준은 실제 기기와 현장 사진으로 보정하지 않았다.
- 웹과 iPhone의 기존 데이터 구조·상세 점검·지도 공급자는 다르다. 위 표의 차이를 완료된 기능으로 세지 않는다.
- 외부 AI 호출 상한·인증 운영, 기기 간 백업/동기화, 여러 탭 동시 편집 충돌은 별도 운영 과제다.
- `origin/main`에는 별도 변경이 있으므로 이번 작업은 기존 작업 브랜치에 정상 push하는 범위다. 이 기록은 `main` 병합이나 운영 배포 완료를 뜻하지 않는다.
