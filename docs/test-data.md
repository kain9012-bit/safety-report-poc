# 테스트 데이터

PoC를 검증하는 데 필요한 자료. **대상 지역은 전북과 서울 두 곳.**
서울은 공공데이터가 가장 잘 갖춰진 곳이고, 전북은 실제로 나가서 찍어볼 수 있는 현장이다.
둘을 같이 쓰면 "데이터가 좋은 곳"과 "보통인 곳"의 차이도 함께 보인다.

---

## 1. 시설 좌표 — 유형 판정용

### 전국 공통 (지역 구분 없이 하나로 받는다)

| 자료 | 쓰는 유형 | 받는 곳 |
| --- | --- | --- |
| 전국횡단보도표준데이터 | 횡단보도 (20.5%) | [data.go.kr 15028201](https://www.data.go.kr/data/15028201/standard.do) |
| 전국어린이보호구역표준데이터 | 어린이보호구역 (1.7%) | [data.go.kr 15012891](https://www.data.go.kr/data/15012891/standard.do) |
| 국토교통부 TAGO 버스정류소정보 | 버스정류소 (2.8%) | [data.go.kr 15098534](https://www.data.go.kr/data/15098534/openapi.do) |

### 소화전 — 이번 PoC에서는 뺀다

전국 통합본이 없고 시도별로 흩어져 있는데, 전북 자료가
[2017년 기준](https://www.data.go.kr/data/15055617/fileData.do)이다. 9년 전 좌표로 "소화전 4m"를
판정하면 틀린 결과를 자신 있게 내놓게 된다. **낡은 데이터로 잘못 판정하느니 판정하지 않는 편이 낫다.**

다만 이 사실은 제안서에 남긴다 — 소화전은 신고의 8.2%인데, 서울은 최신 좌표가 있고 전북은
9년 전 자료뿐이라 **자동 판정의 품질이 사는 곳에 따라 갈린다.** 공공데이터 정비 요구의 근거가 된다.

### 그래서 좌표로 판정하는 범위

| 유형 | 신고 비중 | 자료 |
| --- | ---: | --- |
| 횡단보도 | 20.5% | 전국 표준데이터 |
| 버스정류소 | 2.8% | TAGO API |
| 어린이보호구역 | 1.7% | 전국 표준데이터 |
| **합계** | **25.0%** | |

나머지 75%는 사진 판독에 기댄다. **이 비율을 숨기지 않고 화면에 그대로 적는다.**

### 좌표가 없거나 쓰지 않는 유형

인도(16.1%), 장애인전용구역(8.9%), 소화전(8.2%, 자료 낡아 제외), 친환경차충전구역(7.7%),
소방차전용구역(0.4%), 기타(16.3%), 교차로 모퉁이(17.4%, 도로망 교차점을 따로 계산해야 함).
**사진 판독에만 기댄다.**

### 주소 변환

VWorld 지오코더(무료·공공)를 쓴다. 카카오·네이버는 상용이라 공공 제안물에 끼우면 설명이 길어진다.

## 2. 사진 표본 — 판독 정확도 측정용

30~50장. **촬영 화면이 완성되면 그 화면으로 모은다** — 좌표·촬영시각·정확도가 자동으로 붙어
정답표가 반쯤 저절로 채워진다.

### 갖춰야 할 조합

- **유형별**: 횡단보도 · 교차로 모퉁이 · 인도 · 버스정류소 · 어린이보호구역 ·
  장애인전용 · 친환경차충전 (소화전은 판정에서 뺐지만 사진은 모아 둔다)
- **조건별**: 주간 / 야간 / 비 오는 날 / 번호판 오염 / 정면 / 후면 / 먼 거리
- **지역별**: 전북과 서울 각각

야간과 번호판 오염은 반드시 넣는다. 리뷰에서 "코앞에서 찍어놔도 화질이 구데기라 신고를
못 하겠다"는 불만이 24건 나왔고, 실제 반려 사유이기도 하다.

### 개인정보 — 사진은 깃에 올리지 않는다

저장소를 팀에 공유하므로, 사진에 찍힌 **무관한 사람 얼굴과 다른 차량 번호판**이 그대로
올라가면 안 된다.

- 사진은 `data/samples/` 에 두고 **`.gitignore` 로 제외**한다 (로컬에만 보관)
- 깃에는 **정답표 CSV만** 올린다
- 정답표의 차량번호는 **뒤 4자리만** 적는다 (판독 정확도를 재는 데는 그걸로 충분하다)

### 정답표 형식 — `data/samples/answers.csv`

| 열 | 뜻 |
| --- | --- |
| file | 사진 파일명 |
| region | 전북 / 서울 |
| type | 실제 위반유형 |
| plate_last4 | 실제 차량번호 뒤 4자리 |
| lat, lng | 촬영 좌표 (앱이 기록한 값) |
| accuracy_m | GPS 정확도(m) (앱이 기록한 값) |
| taken_at | 촬영 시각 (앱이 기록한 값) |
| light | 주간 / 야간 / 역광 |
| weather | 맑음 / 비 / 흐림 |
| distance_m | 차량까지 대략 거리 |
| note | 번호판 오염 등 특이사항 |

## 3. 합성 테스트 케이스 — 지금 바로 만든다

실제 데이터가 없어도 **거리 계산과 판정 로직은 검증된다.** 가짜 시설 좌표로
경계값을 짜 둔다.

- 버스정류소에서 9.5m, GPS 정확도 3m → **확정 불가** (오차가 기준 10m를 넘나든다)
- 버스정류소에서 6m, GPS 정확도 3m → 확정 가능
- 버스정류소에서 20m, GPS 정확도 5m → 기준 밖으로 확정
- 기준 거리 양쪽 경계(9.5m / 10.5m)
- 좌표 없음 / 정확도 없음 → 언제나 확정 불가

`src/lib/geo.test.ts` 에 넣는다. **진짜 데이터가 와도 로직은 이미 검증된 상태가 된다.**
