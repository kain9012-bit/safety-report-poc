# 장애인전용주차구역 사진 확인 — 단계별 개선 제안

기준일: 2026-10-14. 상태: **사용자 확정 완료·웹/iPhone 구현 대기**.

확정 기록: 2026-10-14 사용자가 장애인 구역 안의 확정 대기 안내에 대해 **“확정.”**이라고 답했다. 아래 표시 식별·대상 면 연결·차량 관계 분리, 원본 우선 확인·필요한 보완만 촬영, 사진 밖 조건의 미확인 유지, 자료 보존·실패 처리·양쪽 플랫폼 검증 계획을 확정한다. 다른 유형이나 전체 계획의 일괄 확정은 아니다. 다음 협의는 [소방차전용구역](fire-plan.md)이며 전체 계획 확정 후 구현하는 순서를 유지한다.

사용자가 전용구역 3개도 각각 깊게 조사하고 차량이 실제로 서 있는 여러 상황을 시뮬레이션하도록 요청했다. 첫 협의 대상은 장애인전용주차구역이다. 이 문서는 웹과 iPhone에 함께 적용할 기능 의미를 제안한다. 공식 조사 근거는 [장애인 구역 조사](disabled-research.md), 상황별 검토 입력과 기대 결과는 [상황 목록](disabled-scenarios.json)에 둔다.

## 1. 이번에 해결할 문제

사진에 휠체어 표시가 있다는 사실만으로 촬영한 차량이 장애인전용주차구역에 있다고 판단하면 안 된다. 차량이 큰 바닥 표시를 가릴 수 있고, 보이는 표지는 옆 주차면이나 건물 출입구를 안내할 수도 있다. 반대로 표시가 낡거나 설치 방식이 현재 표준과 다르다는 이유만으로 구역이 아니라고 처리해도 안 된다.

따라서 **표시 식별 → 대상 주차면 연결 → 차량과 주차면의 관계 → 별도로 확인해야 할 운영·자격 조건**으로 나누어 확인한다. 사진에서 해당 구역의 표시와 차량 관계를 확인하는 결과와 관할의 법적 위반 판단을 분리한다. 여러 단서의 개수나 AI 신뢰도 하나로 모든 단계를 통과시키지 않는다.

## 2. 사진에서 확인할 세 단계

| 단계 | 읽거나 관찰할 사실 | 잘못된 자동 결론을 막는 조건 |
| --- | --- | --- |
| A. 구역 표시 식별 | 바닥/주차선의 휠체어 표시, 표지의 문구와 그림, 설치 위치, 읽히는 부분·가려진 부분 | 파란색·넓은 칸·휠체어 모양 하나를 구역 확정으로 사용하지 않는다. 차량 스티커·출입구·화장실·이동 방향 안내를 구분한다. |
| B. 그 표시가 대상 주차면에 적용되는지 | 보이는 주차선, 표지 방향·화살표·적용 범위, 주차면 번호, 기둥·벽 등 연결 근거 | 옆 칸, 맞은편, 다른 층의 표시를 대상 칸에 옮겨 붙이지 않는다. 화면상 가까움·같은 GPS만으로 연결하지 않는다. |
| C. 대상 차량과 해당 면의 관계 | 어떤 차량인지, 보이는 바퀴/차체/주차선, 해당 면 안·밖·경계 부근·통행 공간의 관계 | 가려진 바퀴·선·경계를 만들어내지 않는다. 이미지 상자 겹침이나 한 픽셀 침범을 실제 점유·법적 방해 확정으로 바꾸지 않는다. |

차량·표지·주차선이 한 장에 함께 보인다는 사실만으로 A~C가 모두 확인되는 것은 아니다. 차량이 어느 칸에 있는지 확인돼도 기둥 가운데의 공용 표지가 어느 칸에 적용되는지는 모를 수 있다. **차량→면과 표시→면의 연결을 각각 확인**하고, 전경을 추가했어도 표시 적용 범위가 계속 불명확하면 그 상태를 유지한다.

큰 바닥 표시가 완전히 보여야만 다음으로 갈 수 있는 구조는 피한다. **읽을 수 있는 해당 면의 표시와 대상 차량까지의 연결이 충분하면 그 근거를 사용할 수 있다.** 한 장으로 충분한 상황에 표지 종류 두 개나 추가사진 세 장을 일괄 요구하지 않는다. 작은 선 표시의 일부만 남아 있고 그것이 휠체어 표시인지 불분명하면 후보로만 남긴다.

구역 표시와 차량 관계가 모두 사진에서 확인됐을 때의 문구 예시:

> 장애인전용주차구역 표시와 해당 주차면에 있는 차량이 사진에서 확인됩니다.

남아 있는 사항은 따로 표시한다. 이 문구가 설치·운영 근거, 허용 차량 자격, 공식 신고 요건까지 확인했다는 뜻이 되어서는 안 된다.

## 3. 사진을 추가하는 순서

1. 원본 전체에서 대상 차량·주차선·표지 후보를 찾는다. 차량이 여러 대여서 대상이 모호하면 관련 확인을 남긴다. 사용자 지정과 AI 관찰은 구분한다. 질문 형식과 유형 선택 유지 정책은 후속 6번 협의에서 통일한다.
2. 원본의 바닥 앞/뒤, 주차선 끝, 벽·기둥·입식 표지 등 필요한 부분을 제한된 범위로 다시 읽는다. 전체 사진에서 탐지에 실패한 부분도 검토할 수 있게 하되 호출량·전송량에 상한을 둔다. 단순 확대나 생성형 복원으로 없는 글자를 만들어 근거로 쓰지 않는다.
3. **문구나 표시 자체가 흐리면** 표지 전체와 문구가 읽히는 보완사진을 제안한다. 잘린 예외 문구·화살표를 제외한 단어만 읽어 결론 내리지 않는다.
4. **표지는 읽히는데 어느 칸의 것인지 모르겠으면** 차량·주차선·표지가 함께 보이는 사진을 제안한다. 같은 표지만 다시 크게 찍도록 안내하지 않는다.
5. **차량이 바닥을 가리면** 보행 가능한 위치에서 옆 또는 뒤로 구도를 바꾸어 선 끝·기둥/벽 표지와 차량을 담는 방법을 제안한다. 차 밑을 찍거나 차량 이동을 기다리거나 차도로 나가는 것을 요구하지 않는다. 촬영할 수 없으면 미확인 상태로 저장한다.
6. 사진을 보완해도 해결되지 않는 설치 근거·운영 상태·자격 문제는 자료 확인 항목으로 남긴다. 이를 해결하려고 사진 재촬영을 반복시키지 않는다.

사진 용도는 ‘차량과 주차면’, ‘표시 상세’, ‘주변 연결’이다. 필요한 정보가 이미 있으면 한 장이 여러 용도를 담당한다. 이는 권장 촬영 목적이며 공식 제출 장수나 법정 촬영 간격을 뜻하지 않는다. 기본 사진 쌍과 보완사진을 보존하는 공통 확정안을 재사용하되, 기본 6개 유형의 시간·거리·제출 조건을 이 유형에 자동 적용하지 않는다.

## 4. 서로 다른 사진을 연결하는 기준

- 상세사진의 표시를 전체사진에 연결할 때 보이는 주차면 번호, 같은 기둥/벽의 특징, 주차선 형태, 대상 차량 등 공통 특징을 확인한다. 각 연결에는 어느 사진의 어느 부분이 근거인지 남긴다.
- 같은 차량이 옆 칸으로 이동할 수 있고 기둥 도색·선 형태·면 번호가 반복될 수 있다. 차량 일치나 반복 양식만으로 같은 면을 확정하지 않는다. 해당 면을 구별할 수 있는 고정 위치 단서와 두 사진의 모순 여부를 확인하고, 고정 단서가 부족하면 면 연결을 미확인으로 남긴다.
- 단지 촬영시각이 가깝거나 같은 주소·GPS라는 이유만으로 같은 주차면이라고 확정하지 않는다. 지하층과 반복되는 칸 번호는 특히 구분한다.
- 사진 사이에 차량이 이동했거나 다른 차량/다른 면일 수 있으면 연결 확인을 다시 요구한다. 번호판을 읽지 못해도 동일 차량이라고 가정하지 않는다.
- 차가 떠난 뒤 찍은 빈 주차면 사진은 후속 시점의 관찰로 보존한다. 고정 단서로 같은 면을 연결하고 표시 변경·시점 충돌을 확인한 경우 원래 사진의 구역 식별을 보조할 수는 있다. 당시에도 같은 표시였다는 사실을 자동 보증하거나, 계속 주차·기본 두 번째 차량 사진·촬영 간격 충족 근거로 사용하지 않는다. 오래된 사진과 섞이면 촬영 시점별로 표시 상태를 남긴다.
- 사용자가 같은 칸이라고 답한 것은 ‘사용자 확인’으로 보존한다. AI가 사진 연결을 확인한 상태로 바꾸지 않는다.
- 원본을 자른 사진은 같은 촬영의 파생 자료로 취급한다. 같은 표시를 여러 번 검출해도 서로 독립적인 근거 여러 개로 계산하지 않는다.
- 위치는 시설 후보와 주소 확인의 보조 자료다. GPS나 지도 건물명으로 지하 주차면·장애인 구역 경계·차량 점유를 확정하지 않는다.
- [공개 자료 연결 조사](public-data-feasibility.md)에서 전국주차장정보표준데이터의 장애인 구역 보유 여부·시설 좌표·기준일 항목을 확인했다. 이는 시설 후보를 보강하는 자료이며 칸별 경계나 현재 지정 이력은 아니다. 사진의 해당 면 연결과 별도 상태로 표시하고 N·공란·미조회 결과로 사진 근거를 지우지 않는다. 실제 API 연동은 아직 수행하지 않았다.

## 5. 상황을 바꿔가며 검토한 대표 흐름

아래는 가상의 장면 사실을 주고 판단 절차를 따라간 **문서 기반 상황 시뮬레이션**이다. 실제 사진을 AI에 입력한 결과가 아니다. 전체 상황·반례·근거는 별도 JSON에 기록한다.

| 첫 사진의 상황 | 다음 확인 또는 보완 | 기대되는 결과 |
| --- | --- | --- |
| 승용차가 큰 바닥 그림을 가림. 선 끝 작은 표시와 같은 칸의 벽 표지가 보임 | 원본 부분 확인과 주차선 연결 확인. 이미 충분하면 추가 촬영 없음 | 해당 면 표시와 차량 관계 확인 가능. 법적 자격은 별도 |
| SUV 때문에 바닥이 모두 가려짐. 벽 표지만 확대해 찍음 | 차량·해당 벽 표지·주차선이 함께 보이는 전경 | 연결이 드러나면 해당 면 근거로 사용. 전경도 가려져 있으면 미확인 유지 |
| 차량은 일반 칸, 옆 칸에 선명한 휠체어 표시 | 두 칸의 선과 차량 위치 확인 | 옆 칸 표시를 대상 차량 근거로 사용하지 않음. 다른 쟁점까지 위반 없음으로 단정하지 않음 |
| 여러 칸 가운데 표지 하나가 서 있음 | 표지 적용 범위·화살표·칸별 바닥 표시/번호 확인 | 범위가 분명한 칸만 연결. 전체 줄을 자동 지정하지 않음 |
| 건물 입구에 휠체어 이동 안내가 있고 앞에 차량이 있음 | 표지 원문·화살표와 주차 구획 맥락 확인 | 이동 안내를 전용 주차면 표지로 오인하지 않음 |
| 바닥이 낡았지만 칸별 벽 표지와 차량 관계가 선명함 | 낡은 표시와 현재 안내 사이의 충돌 여부 확인 | 새 규격과 다르다는 이유로 구역을 부정하지 않음 |
| 예전 바닥 그림과 ‘구역 변경’ 안내가 함께 보임 | 양쪽 원문·날짜·적용 면 확인, 필요 시 운영 자료 | 상충 표시 상태. 최근처럼 보이는 쪽을 AI가 임의로 확정하지 않음 |
| 주차면 옆 사선 통행 공간에 차량이 있음 | 주차면·보행/승하차 공간·차량의 관계를 전경으로 확인 | 구역 내 주차와 접근/승하차 방해 가능성을 별개 관찰로 기록 |
| 지하 1층 차량 사진과 지하 2층의 같은 번호 표지 상세 | 층·기둥·차량 등 공통 특징 대조 | 같은 주소·번호여도 같은 칸으로 합치지 않음 |
| 같은 차량이 옆 칸으로 이동했는데 주차선·기둥이 비슷함 | 해당 면을 구별하는 고정 위치와 모순 확인 | 차량 일치만으로 표시를 옮겨 연결하지 않음 |
| 차가 떠난 뒤 바닥 그림이 드러난 사진을 추가 | 같은 면 고정 단서·사진 시점·표시 변경 여부 확인 | 후속 시점의 구역 단서로만 보조. 계속 주차나 기본 두 번째 차량 사진으로 사용하지 않음 |
| 유리 반사 때문에 주차표지가 보이지 않음 | 현재 사진에서 확인 가능한 범위만 기록 | ‘주차표지 미확인’. 표지 없음·위조·무자격·탑승자 미동승으로 단정하지 않음 |
| 주차선과 바퀴가 눈·어둠·다른 차량에 가려짐 | 다른 안전한 구도 또는 저장 후 보완 | 확인되지 않은 점유 관계를 남김. 표시 식별 성공이 점유 확인을 대체하지 않음 |

핵심 비교는 ‘사진에 표시가 하나라도 있으면 유형 선택’과 ‘대상 면까지 연결해서 선택’의 차이다. 보완 전후에 **어느 부족 항목이 해결됐는지**를 확인한다. 해결되지 않은 상황도 실패를 숨기지 않고 미확인으로 끝낼 수 있어야 한다. 상황 건수는 판독 정확도나 예외 전체를 포괄했다는 수치가 아니다.

## 6. 구역 확인과 분리할 조건·예외

- 차량이 서 있는 곳의 표시를 식별한 사실과 그 장소의 법적 설치·운영 근거를 구분한다. 공중이용시설, 공동주택, 개인주택, 여객시설 등 장소 맥락을 보존하며 외관만으로 적용 법령을 정하지 않는다.
- 오래된 구역, 설치 의무가 없던 공동주택의 설치, 사유지라는 이유, 비표준 색·치수만으로 효력 유무를 일괄 판정하지 않는다. 공식 조사에 담긴 장소별 설명은 관할 확인이 필요한 조건으로 연결한다.
- 차량용 주차표지는 보임·문구/번호 판독 가능·불명확·관찰 범위 밖을 구분한다. 유효성·발급대상·탑승 요건을 사진 한 장으로 확인한 것으로 표시하지 않는다. 사람의 외모·보행 모습으로 장애 여부를 추정하지 않는다.
- 주차표지와 번호판이 다르게 읽혔더라도 먼저 원본 판독·사용자 확인 상태로 남긴다. OCR 오차를 부정사용·위조 확정으로 바꾸지 않는다.
- 승하차·출차 등 개별 사정과 안내서의 예외는 보통 정지사진만으로 확정할 수 없다. 예외 후보나 확인 필요 사항으로 남기며 설명 문구만으로 자동 면제하지 않는다.
- 차량 일부가 선 밖에 보이는 정지사진에서 진입·출차 방향을 알아냈다고 하지 않는다. 사선 공간도 보이는 선·기둥·연결을 관찰하고, 승하차 공간 또는 기둥 보호공간이라는 용도는 명시적 표시·자료가 있을 때 별도 확인한다. 상가·주택처럼 보이는 외관을 법령상 시설 분류 확인으로 바꾸지 않는다.
- 충전시설과 장애인 표시가 함께 있는 면은 복수 속성을 보존한다. 충전구역이라고 장애인 표시를 지우거나 그 반대로 처리하지 않는다. 최종 유형 추천은 5번에서 통일한다.
- 관할 신고 요건·사진 시각·수량·계속 주차 등은 별도 규칙으로 다룬다. 이번 구역 식별의 성공이 공식 접수나 과태료 조건 충족을 뜻하지 않는다.

## 7. 실제로 달라질 기술 구조

현재 GitHub 웹의 `api/vision.ts`와 `src/types/report.ts`에는 기본 6개 장면/유형만 있다. 전용구역 3개는 현재 이 경로에서 구현되어 있지 않다. iPhone의 기존 `ZoneEvidence` 역할과 `ZoneCase` 질문 답변도 사진 속 내용을 AI가 읽었다는 의미가 아니다.

| 현재 한계 | 제안하는 변경 |
| --- | --- |
| 기본 유형 중심 장면 응답, 전용구역별 근거 없음 | 표시 종류·읽힌 원문·설치 위치·가림/불명확 사유를 별도 관찰로 추가 |
| 사진 전체를 축소해 분석 | 전체 장면과 원본 부분 분석을 분리하고 사진 ID·원본 영역을 연결 |
| 표지와 차량을 같은 화면에서 찾았다는 사실에 의존할 위험 | 대상 차량→주차면→표시의 연결 근거와 미확인 사유를 명시적으로 저장 |
| 사진 역할/사용자 응답만 존재 | 실제 관찰 결과, 사용자 확인, 공식 자료 확인을 출처별로 분리 |
| 부족 사유를 유형 없음으로 합칠 위험 | 표시 미식별·면 연결 미확인·점유 미확인·상충·분석 실패를 따로 관리 |
| 전용구역을 기본 6개 규칙으로 처리할 위험 | 전용구역별 관찰 규약과 적용 조건을 분리하고 미확인 규칙을 유지 |

관찰에는 사진/원본 ID, 대상 ID, 보이는 영역, 원문 또는 관찰 설명, 출처, 불명확 이유, 연결 대상, 입력 버전을 둔다. 구체 필드명과 모델/검출기의 선택은 구현 설계에서 정한다. 이 계획만으로 고정확도 분할 모델·학습 데이터·3차원 측정 기능을 확보한 것으로 표현하지 않는다.

원본 보존, 교체 성공 후 전환, 늦은 옛 분석 응답 차단, 수동 주소/내용/유형 보호, 취소·통신 실패·저장 실패의 처리에는 이미 확정한 공통 흐름을 적용한다. 양쪽 플랫폼의 촬영 화면은 각자 유지하되 같은 상태명과 부족 사유를 사용한다. 자동 동기화는 포함하지 않는다.

## 8. 구현 후 무엇으로 검증할 것인가

현재 상황 목록은 설계 반례 목록이다. 구현 후에는 다음 검증을 분리해서 수행한다.

2026-10-14 추가 독립 검토에서 사진 밖의 사실이 시나리오 입력에 섞이는 문제를 확인해 [입력 출처·기대 결과 분리 규칙](scenario-input-protocol.md)을 추가했다. 사진 관찰, 촬영 메타데이터, 외부 자료, 사용자 진술, 시스템 상태, 평가자만 아는 설정을 나눈다. 기대 결과도 사진만 있는 경우와 별도 정보가 제공된 경우로 구분한다. 사례 제목·함정·정답은 실제 모델에 주지 않으며, 평가자만 아는 설정은 어느 단계에도 정답 힌트로 사용하지 않는다.

1. **로직/저장 검증:** 같은 원본 중복, 다른 층/주차면 연결 거절, 상충 상태 보존, 실패·취소·이어하기와 수동 입력 보존을 확인한다. 합성 입력으로 통과해도 인식 성능으로 보고하지 않는다.
2. **실제 사진 판독 검증:** 적법하게 사용할 수 있는 별도 사진 표본에 대상 차량·표시·해당 면·가림·연결 상태를 사람 검토로 표시한다. 같은 장소/차량/원본이 보정용과 평가용에 겹치지 않게 나눈다. 판단 불가능한 사진도 평가에 포함한다.
3. **구분해서 보고할 지표:** 표시 검출 누락, 옆 칸/다른 층 잘못 연결, 근거 부족인데 자동 확인한 비율, 확인 가능한 사진에서도 보류한 비율, 보완 전후 해결 여부, 불필요한 추가 촬영을 각각 본다. 하나의 전체 정확도로 합치지 않는다.
4. **양쪽 플랫폼 확인:** 웹과 iPhone 각각 빌드, 실행, 저장/취소/복원, 원본/부분 좌표 연결, 실제 기기 촬영 여부를 따로 보고한다. 인식 연결 없이 UI만 완료한 상태는 구분한다.
5. **출시 판단:** 사전에 정의한 평가 표본과 허용 오판 기준을 적용한다. 이번에 근거 없이 목표 정확도·합격 수치나 현장 검증 완료를 약속하지 않는다. 검증이 부족한 조건은 자동 확인 범위를 제한하고 사유를 표시한다.

## 9. 결정 기록

2026-10-14 사용자 **“확정.”**으로 이 안을 확정 완료·구현 대기로 전환했다. **표시 식별·대상 면 연결·차량 관계를 각각 확인하고, 원본으로 해결되지 않는 부분만 촬영하며, 사진으로 확인할 수 없는 조건은 남기는 방식**이다. 본문에 남은 제안·설계 표현은 확정 당시의 계획 내용이며 실제 구현·정확도 검증 완료를 뜻하지 않는다. 소방차전용구역 안을 이어서 협의한다.
