# 소방차전용구역 사진 확인 — 단계별 개선 제안

제안 기준일: **2026-10-14, 한국 시각**. 확정일: **2026-10-15**. 상태: **사용자 확정 완료·웹/iPhone 구현 대기**.

사용자 확정 기록: 2026-10-15 **“확정했어”**. 아래 표시 식별·해당 구역 연결, 차량의 내부·경계·인접·진입 관계 구분, 원본 우선 확인과 필요한 보완만 안내, 행정 자료 분리, 자료 보존·실패 처리·양쪽 플랫폼 검증 계획을 확정한다. 다음 협의는 [친환경차 충전구역](ev-plan.md)이며 다른 안과 전체 구현을 함께 승인한 것으로 처리하지 않는다.

사용자가 장애인전용주차구역 안에 대해 “확정.”이라고 답해 전용구역 두 번째 안으로 진행한다. 근거는 [공식 조사·예외](fire-research.md), [가상 상황 32개](fire-scenarios.json), [입력 출처 분리 규칙](scenario-input-protocol.md)에 둔다. 웹과 기존 SwiftUI·AVFoundation iPhone에 같은 기능 의미로 구현할 계획이다.

## 1. 민원인에게 달라질 점

차가 바닥 글씨를 가려도 남은 표시와 구획 경계를 먼저 확인한다. 구역 전체가 한 장에 다 나와야 한다고 요구하지 않는다. 표시를 읽는 데 부족한 사진과 그 표시가 차량 자리와 연결되는지 확인할 사진을 구분하여 필요한 부분만 안내한다.

결과는 **표시 식별 → 해당 바닥 구역 연결 → 대상 차량의 위치 관계 → 별도 적용 자료**로 나눈다. 구역 안·경계·인접 주차면·진입 통로를 구별하고, 사진 근거가 충분해도 법적 적용 자료는 미확인일 수 있게 한다.

## 2. 사진에서 확인할 순서

1. **대상 차량 지정:** 여러 차량이 있으면 어느 차량을 확인할지 정한다. 사용자 지정, 번호판 판독, 같은 차량 확인은 별개로 기록한다.
2. **표시 식별:** 원본 전체에서 소방차 전용 문구, 119, 주차금지 기호, 빗금 테두리, 안내 표지를 찾는다. 각 요소의 읽힌 내용·위치·가림·흐림을 기록한다. 한 색·숫자만으로 확정하거나 모든 표준 요소가 보여야만 인정하는 규칙을 두지 않는다. 소방차 진입로·소방활동공간·소화전 표시는 정확한 문구와 맥락을 보존하며 전용구역과 자동으로 합치지 않는다.
3. **원본 부분 확인:** 작거나 흐린 부분을 원본 해상도로 재분석한다. 자른 위치와 원본 사진 ID를 유지한다. 가려진 글자나 선을 생성해 관찰 사실로 사용하지 않는다. 원본에 없는 세부 정보는 복원했다고 표시하지 않는다.
4. **표시와 구역 연결:** 문구·테두리·고정 위치 단서가 어느 바닥 범위를 가리키는지 확인한다. 옆 구역의 표시를 대상 차량에 적용하지 않는다. 별도 상세 사진은 구별 가능한 고정 특징·촬영 시각·사진 간 모순을 검토한다. 같은 차량·주소·반복 도색만으로 같은 구역이라고 확정하지 않는다. 사용자 답변과 도면은 각각 진술·외부 자료이며 사진 연결 확인과 구분한다.
5. **차량과 구역 관계:** 내부에 보임 / 경계에 걸쳐 보임 / 인접 면에 있음 / 진입 통로를 가리는 것으로 보임 / 미확인으로 나눈다. 보이는 바퀴·차체와 경계를 보되 사진 상자 겹침만으로 점유·통행 가능 폭을 계산하지 않는다. 표시는 식별됐어도 차량 관계는 미확인일 수 있다.
6. **남은 부분만 보완:** 기존 사진에서 해결된 항목은 제거한다. 글씨가 부족하면 상세, 적용 범위가 부족하면 차량·표시·경계의 연결, 진입 관계가 부족하면 차량·통로·구역의 연결이 보이는 사진을 제안한다. 촬영으로 해결되지 않으면 이유와 함께 저장한다.

GPS·지도는 주소와 시설 후보를 좁히는 데 사용한다. 같은 좌표라고 같은 동·층·구획으로 확정하지 않는다. 전국 전용구역의 현행 경계·지정 이력을 함께 제공하는 API는 이번 조사에서 확보하지 못했으므로 지도만으로 구역 확인 완료를 만들지 않는다.

## 3. 차가 서 있는 상황별 동작

아래는 기존 32개 문서 시나리오의 대표 상황이다. 실제 사진을 AI에 넣어 얻은 결과가 아니다.

| 상황 | 먼저 확인할 것 | 부족할 때만 안내할 행동 |
| --- | --- | --- |
| 차가 중앙 글씨를 가리고 일부 문구·테두리만 보임 | 남은 글자와 같은 구획의 연결. 기존 두 번째 사진도 활용 | 차량·남은 표시·보이는 테두리가 함께 보이는 다른 각도 |
| 대형차가 표시를 전부 가림 | 다른 기존 사진·고정 안내판의 적용 범위 | 안전한 위치에서 연결이 보이는 경우만 보완. 계속 가리면 미확인 저장 |
| 옆 빈 구역에 문구가 선명함 | 두 구획의 경계와 대상 차량 위치 | 옆 구역 표시를 옮겨 적용하지 않음. 대상 구역의 연결만 확인 |
| 노란 빗금 또는 119만 보임 | 바닥 표시인지, 통로·차량 도장 등 다른 용도인지 | 정확한 문구와 주변 구획이 드러나는 사진 |
| 소방차 진입로 표지만 보임 | 표지가 가리키는 통로와 연결된 전용구역 | 연결이 보이는 범위만 보완. 표지 하나를 전용구획 존재로 대체하지 않음 |
| 구역 안은 비었지만 차량이 입구 쪽에 있음 | 구역·통로·차량의 실제 연결 | 세 요소의 관계가 보이는 사진. 단지 전체 우회로 촬영은 요구하지 않음 |
| 옆 일반 주차선 안에 차량이 있음 | 인접 구획·경계 침범·진입 관계를 구별 | 법적 주차구획 여부는 별도 자료 확인. 단순 인접만으로 방해 확정 금지 |
| 바퀴는 밖이고 범퍼가 경계 쪽으로 보임 | 차체 끝과 보이는 경계, 원근·가림 | 관계를 확인할 수 있는 다른 각도. 실제 돌출량은 임의 계산하지 않음 |
| 옛 표시와 새 주차선이 겹침 | 읽히는 두 표시·변경 안내·사진 시점 | 상충 상태 저장, 지정·변경 자료 확인. 선명도만으로 현행 표시 선택 금지 |
| 밤·비·반사로 문구가 겹침 | 원본 품질·동일 표시의 반사라는 근거 | 구분 못 하면 미확인. 무조건 중복 제거하거나 구역을 늘리지 않음 |
| 상세 사진이 다른 동의 비슷한 구획일 수 있음 | 구별 가능한 고정 특징·시점·모순 | 연결 불명은 보류. 다른 구획임이 확인되면 연결 거절 |
| 통신 실패 또는 추가 촬영 불가 | 사진 저장 여부·실패 사유 | 저장한 원본으로 재시도하거나 미완료 상태로 이어하기 |

사용자가 차량을 옮기거나 차량 아래를 촬영하도록 요구하지 않는다. 모든 테두리·문구를 한 장에 넣기 위해 무리하게 이동시키지 않는다. 한 장으로 여러 부족 사유를 해결할 수 있으면 안내를 묶는다.

## 4. 사진으로 확인할 수 없는 조건 처리

- 소방기본법 시행령 제7조의14는 구역 내부, 인접 위치, 진입로 등을 구별한다. 특히 앞·뒤·양옆 주차에 관한 호에는 주차장법상 부설주차장 주차구획 내 주차의 제외 단서가 있다. **인접함 자체를 방해로 확정하지 않으며**, 이 단서를 내부 침범이나 다른 진입 방해까지 모두 허용한다는 뜻으로 확대하지 않는다. 사진에 선이 보이는 사실과 법적 주차구획의 지위도 별개다. [현행 조문](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=14&joNo=0007&lsiSeq=289137&urlMode=lsScJoRltInfoR)
- 적용 시기와 관련해 건축허가·주택건설사업계획 승인 **신청 시점**을 준공·입주·승인 시점으로 대체하지 않는다. 신축처럼 보이는 외관으로 확인하지 않는다. 개별 적용·변경허가·다른 법적 근거는 별도 확인 사항이다. [법제처 해석례 22-0799](https://www.law.go.kr/LSW/expcInfoP.do?expcSeq=335067&mode=2)
- 설치대상·예외·다동 공용·현행 지정 여부는 출처와 기준일이 있는 자료로 구분한다. 자료가 없다고 사진 근거를 지우거나 주차 허용을 안내하지 않는다. 민원인이 인허가 서류를 구해야만 기록을 저장할 수 있도록 만들지 않는다.
- 사진 수·간격·기한은 해당 관할의 최신 접수 안내를 확인한다. 과거 특정 지역의 5분 안내를 전국 공통 값으로 고정하거나, 기본 6개 유형의 조건을 복사하지 않는다.

따라서 화면에서 **“표시 확인됨 / 차량과 구역 관계 확인됨 / 적용 자료 미확인”**을 동시에 표현할 수 있다. 실제 신고 접수·과태료 판정과는 구분한다.

## 5. 기술 변경과 자료 보존

현재 GitHub 웹 판독에는 기본 6개 장면과 소화전 근접 필드가 있으며 소방차전용구역 판독은 없다. iPhone의 기존 전용구역 수동 안내·사진 역할도 AI가 사진을 읽은 결과가 아니다. 새 유형은 다음 구조를 추가하는 계획이다.

| 변경 | 사용자에게 갖는 의미 |
| --- | --- |
| 표시 관찰: 원문·위치·종류·가림/흐림/상충 | 무엇을 보고 해당 구역이라고 추천했는지 확인 가능 |
| 표시→구역과 차량→구역의 별도 연결 | 옆 구역이나 다른 동의 근거를 잘못 가져오는 오류 방지 |
| 내부·경계·인접·진입로·미확인 관계 구분 | 실제 사진이 보여 주는 차량 위치를 구체적으로 설명 |
| 원본/부분/보완사진 ID·영역·입력 버전 연결 | 원본을 재사용하고 같은 사진의 중복 계산·옛 응답 덮어쓰기 방지 |
| 사진 부족·외부 자료 미확인·분석 오류 분리 | 사진으로 해결되지 않는 문제 때문에 재촬영 반복 방지 |

확정된 공통 보존·취소·실패 처리에 연결한다. 새 사진 저장 성공 전 기존 사진·수동 주소·본문을 유지한다. 보완사진 추가가 기본 시간 비교 쌍이나 대기시간을 초기화하지 않는다. 유형 변경 시 기존 자료를 보존하고 새 유형에서의 연결과 관할 요건을 다시 확인한다. 한 시점의 사진이나 원본을 자른 이미지를 독립된 시간차 사진으로 세지 않는다.

모델 교체·별도 학습·3차원 거리 측정을 확정하는 안은 아니다. 우선 관찰·연결·불확실성·보완 요청 구조를 개선한다. 웹과 iPhone은 같은 상태·용어·실패 의미를 사용하며 기존 사진·영상·보관 흐름을 유지한다.

## 6. 구현 후 검증 계획과 현재 상태

1. 로직·저장 시험: 다른 구획 연결, 선택 변경 뒤 옛 응답, 같은 원본 중복, 상충 자료, 저장 실패·취소·복원 등을 확인한다.
2. 실제 사진 시험: 표시 누락/오인, 옆 구역 오연결, 불명확한 점유의 과잉 확인, 법적 사실 추측, 불필요한 보완 요청을 따로 측정한다. 같은 원본·차량·장소가 보정과 평가에 섞이지 않게 한다.
3. 표시 가림·퇴색·반사·원근·인접 주차·진입로·다른 시점·법적 적용 미확인을 포함한다. 평가자만 아는 정답은 모델 입력에서 제외한다.
4. 웹과 iPhone 각각 구현·빌드·실행·실기기 촬영·모델 정확도를 별도로 보고한다. 구현이나 빌드 성공을 실제 인식 성공으로 표현하지 않는다.

제안 당시 완료한 것은 공식 조사, 32개 가상 상황의 문서 검토, 별도 검토자의 핵심 흐름·예외 점검, 세부안 기록이다. 시행령 제7조의14와 해석례는 제안 시 원문을 다시 확인했다. 별표 PDF는 선행 조사 기록을 참고했으며 당시 웹 재열기는 도구 접근 오류로 성공하지 못했다. 이후 2026-10-15 사용자가 이 안을 확정했다. 실제 사진 시험·기능 구현·push는 수행하지 않았다.

## 7. 결정 기록

2026-10-15 사용자 **“확정했어”**로 이 안을 확정 완료·구현 대기로 전환했다. **표시와 해당 구역을 연결하고, 차량의 내부·경계·인접·진입 관계를 구별하며, 원본으로 해결되지 않는 사진만 보완하고, 행정 자료 미확인을 별도로 남기는 방식**이다. 본문은 확정 당시의 계획이며 실제 구현·정확도 검증 완료를 뜻하지 않는다. 친환경차 충전구역 안을 이어서 협의하며 전체 계획 확정 후 구현·검증·푸시 직전 상태를 준비하는 기존 순서를 유지한다.
