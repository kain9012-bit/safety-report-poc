# 장애인전용주차구역: 사진 근거 판독 개선 연구

작성·출처 확인일: **2026-10-14, 한국 시각**. 상태: **조사 근거·기능 구현 전**. 이 연구에 기반한 [단계별 개선안](disabled-plan.md)은 2026-10-14 사용자 “확정.”으로 확정 완료·웹/iPhone 구현 대기로 전환했다.

이 기록은 공식 법령·정부 사업안내와 가상 촬영 관찰 상황을 비교한 설계 연구다. [disabled-scenarios.json](disabled-scenarios.json)의 시나리오는 실제 현장 사진이나 AI의 출력이 아니다. 실제 모델에 사진을 넣어 인식률을 측정하거나 현장·실기기 검증을 수행하지 않았다. 모든 예외를 알아냈다는 보증 대신, 확인 불가능한 경우를 별도로 보존하는 설계를 제안한다.

## 1. 제안의 중심

차가 주차하면 가장 큰 바닥 휠체어 그림이 가려질 수 있다. **큰 그림 전체를 반드시 보여 달라고 하지 않고, 남아 있는 구획선의 작은 표시·벽이나 기둥의 안내판·노출된 바닥 표시를 대상 차량이 있는 정확한 주차면과 연결한다.** 근거가 충분하면 촬영을 끝낸다. 부족하면 원본 재분석을 먼저 하고, 모자란 연결만 한 번 더 찍도록 안내한다.

서로 다른 네 가지 사실을 합치지 않는다.

| 층 | 기록하는 사실 | 사진만으로 넘지 않을 경계 |
|---|---|---|
| 사진상 표시 | 장애인 주차를 뜻하는 글씨·그림·주차면 선이 실제로 보임 | 표지 색 또는 휠체어 그림 하나가 있다고 주변 모든 주차면을 전용구역으로 확정하지 않음 |
| 차량과 주차면 연결 | 대상 차량이 그 표시가 적용되는 주차면 안/경계/옆 통로 중 어디에 보임 | 다른 칸의 표시를 붙이거나, 화면상의 상자 겹침을 실제 침범으로 바꾸지 않음 |
| 법적 구역 성립·적용 | 시설 종류, 설치·변경 경위, 적용 법령, 현재 운영 상태 | 사유지·오래된 표시라는 이유만으로 무효라고 하지 않음. 임시표지 하나만으로 법적 유효성을 인증하지 않음 |
| 차량 이용 자격·법적 위반 | 주차표지 관찰, 등록·유효성, 탑승 및 이용 상황, 관할 검토 | 주차표지가 안 읽힘=미부착, 사람이 걸음=자격 없음, 빈 차=장애인 미탑승으로 판단하지 않음 |

법적 설치 확인 자료가 없다는 이유로 충분한 사진상 구역 근거까지 삭제하지 않는다. 반대로 사용자가 전용구역을 선택했다는 사실을 AI 확인이나 법적 성립 확인으로 바꾸지 않는다.

## 3. 구역의 특징과 오인 방지

### 표시와 설치 형태

- 장애인등편의법 별표1 제4호는 일반형 주차면을 폭 3.3m 이상·길이 5m 이상, 평행주차형을 폭 2m 이상·길이 6m 이상으로 규정한다. 넓이만으로 유형을 판정하거나 좁아 보인다고 무효로 만들지 않는다. [D-RULE-A1]
- 같은 별표에는 바닥의 큰 표시(1.3m × 1.5m)와 **주차구역선의 작은 표시(50cm × 58cm)**가 있다. 차량 하부를 억지로 촬영하지 않고 노출된 작은 표시도 원본 부분 분석 대상으로 삼는다. 작은 그림 하나를 다른 칸의 큰 그림과 중복하여 독립 증거 둘로 세지 않는다. [D-RULE-A1]
- 안내판은 식별하기 쉬운 곳에 부착·설치하도록 되어 있다. 입식만 인정하지 않고 벽·기둥 부착도 살피되, 그 판의 문구·화살표·주차면 번호·설치 위치로 적용 범위를 구분한다. 0.7m × 0.6m, 지면에서 1.5m라는 설치 규격을 사진 필수 통과값으로 사용하지 않는다. [D-RULE-A1]
- 바닥 표시는 식별하기 쉬운 색상이라는 기준이다. 청색 바탕의 유무만으로 분류하지 않는다. 청색·백색의 편의시설 일반 안내표지와 전용주차면을 혼동하지 않는다. [D-RULE-A1, D-RULE-A2]
- 표시가 일부 닳거나 차량·눈·빛 반사에 가려졌다면 `표시 확인 어려움`이다. `구역 아님`이 아니다. 구역선의 작은 표시가 없다는 이유도 동일하다. 오래된 기준 및 별도 시설 법령 경로를 고려한다. [D-RULE-TRANS, D-TRANSPORT-A1]
- 휠체어 접근 통로·승하차 여유 공간·사선·진입로를 모두 주차면으로 합치지 않는다. 그렇다고 주차면 밖이면 관계없다고 버리지도 않는다. 주차면 점유와 접근·승하차를 막는 상태를 따로 기록한다. [D-DECREE-9, D-RULE-A1]

2023년 시행규칙 경과조치는 편의시설 안내표지의 종전 형태를 계속 사용할 수 있도록 한다. 이것을 차량 주차표지의 모든 구형 형태가 주차 허용된다는 뜻으로 확장하지 않는다. 시설 표지와 차량 표지는 서로 다른 객체다.

## 4. 권장 판독 단계

1. **대상 차량을 먼저 연결한다.** 차량이 여러 대면 사용자가 신고 대상으로 고른 차량 ID를 유지한다. 번호판 글자 인식과 대상 선택은 별개다. 대상 변경 시 이전 연결 결과를 무효화한다.
2. **사진 품질과 관찰 가능 범위를 남긴다.** 밝기·흔들림·차량/기둥 가림·유리 반사를 기록한다. 분석 장애, 표시 미관찰, 표시가 없다고 볼 수 있는 충분한 시야를 별도로 구분한다.
3. **주차구역 표시와 다른 표시를 분리해 찾는다.** 큰/작은 바닥 휠체어 그림, 전용주차 문구, 벽/기둥/입식 표지, 화살표, 주차면 번호를 찾는다. 접근로·화장실 안내, 가족·임산부 우선석, 차량 스티커는 별도 종류다.
4. **표시가 적용되는 주차면을 만든다.** 보이는 구획선, 양옆 면, 화살표 방향, 안내문 범위를 확인한다. 표지에 가장 가까운 차라는 이유로 연결하지 않는다. 같은 표지가 여러 칸에 적용되면 각 칸을 분리하되 존재하지 않는 칸 경계를 추정 확정하지 않는다.
5. **차량 위치를 연결한다.** 면 내부, 경계 부근, 옆 승하차 공간, 앞·뒤 또는 진입로, 관계 불명으로 나눈다. 바퀴 접지점·차체 끝부분·통로 관계를 각각 남긴다. 선/바퀴가 가려지면 자동 거리·침범량을 생성하지 않는다.
6. **법적 적용과 자격을 별도로 남긴다.** 일반 건물/공동주택/여객시설/도로/개인집 구분 및 재지정·임시운영 충돌 단서를 저장한다. 사진상 구역 근거가 충분하면 추가 법적 확인이 끝나지 않아도 보관은 가능하다. 주차표지는 읽힌 상태·문구만 기록하고 정품·유효성·탑승 자격은 미확인으로 둔다.
7. **남은 부분만 보완한다.** 원본 부분 분석 → 다른 기존 사진 확인 → 한 장으로 해결할 수 있는 구체 안내 순서다. 예: “차량 앞쪽과 그 칸 양옆의 선, 벽의 주차 안내가 함께 보이게 찍어 주세요.” 표지 상세사진만으로 부족하면 차량·주차면과 연결되는 전경이 필요하다는 이유를 표시한다. 전체 장면의 연결이 이미 충분하면 또 찍게 하지 않는다.

표시 전체가 가려졌는데 원본의 다른 부분으로도 연결을 확인할 수 없다면 **차량 이동이나 표지 노출을 요구하지 않고 ‘이 사진에서는 해당 주차면 확인 어려움’으로 저장**한다. 가까이 접근하거나 도로로 내려서야 하는 보완을 필수화하지 않는다. 지도는 건물·관할의 보조 정보이며, 지하 층수와 정확한 칸은 기둥번호·층 표시·주차면 연결을 우선한다.

## 5. 설계할 결과 데이터와 사용자 안내

| 항목 | 제안하는 상태/내용 |
|---|---|
| 구역 표시 | `observed / ambiguous / not_observed / unavailable`, 표지 종류·원문·사진 ID·원본 영역 |
| 해당 주차면 연결 | `linked / ambiguous / conflicting / unlinked`, 표지→면→대상 차량 관계와 근거 |
| 차량 위치 | `inside_bay / boundary_unclear / adjacent_access_space / access_route / outside / unknown` |
| 현재 지정/적용 | `not_checked / corroborated / conflicting / authority_review_needed`, 자료 출처·날짜·시설/층/주차면 ID |
| 차량 주차표지 | `readable / partially_readable / obscured / not_observed / not_checked`, 읽힌 주차가능/불가 문구와 번호 비교 결과. 유효성 인증 필드와 분리 |
| 남은 확인 | 사진 보완 / 기존 원본 재분석 / 지역·관리자료 확인 / 담당기관 확인을 분리 |

`not_observed`는 미부착·부존재 확정값이 아니다. 모든 관찰은 사용한 원본 사진과 연결하고 잘라낸 이미지의 좌표를 원본에 되돌릴 수 있어야 한다. 사진 두 장에서 같은 표지를 보았다고 서로 독립된 법적 증거 두 개로 부풀리지 않는다. 같은 차량과 반복되는 기둥 도색만으로 같은 주차면이나 계속 주차를 인정하지 않는다. 면 번호·고유 기둥·비반복 구조 같은 고정 단서가 필요하다. 차량이 떠난 뒤 표시가 드러난 사진은 같은 면과 당시 지정 상태의 충돌 여부를 확인하면 구역 식별의 보조자료가 될 수 있으나, 계속 주차나 두 번째 기본 촬영의 증거로 사용하지 않는다. 사용자 선택·관리자 설명·공식 설치자료·사진 관찰의 출처를 구분한다.

사용자에게는 “장애인 주차 표시가 있고, 선택한 차량이 그 칸에 서 있는 것으로 보입니다”, “표시는 보이지만 이 차가 있는 칸에 적용되는지는 확인이 필요합니다”, “차량 옆 통로를 막는 모습이 보입니다”처럼 관찰 범위 안에서 설명한다. `불법 확정`, `과태료 대상 확정`, `주차표지 정품 확인`, `사람 외모상 장애 없음` 같은 결과를 만들지 않는다.

웹/iPhone은 같은 의미·상태를 사용한다. 기존 사진과 작성 내용은 보완 촬영 취소·분석 실패에도 유지한다. 보완자료는 기본 촬영쌍을 덮어쓰거나 해당 지역 신고 간격을 자동 충족하지 않는다. GitHub 웹의 현재 기본 6개 AI 필드에 임의 문자열만 추가하는 작업으로 끝낼 수 없고, 주차면과 표시의 연결·다중 사진 원본 근거·모호함 상태가 신규 구현 범위다.

## 6. 상황 시뮬레이션과 검증 범위

[JSON 상황 목록](disabled-scenarios.json)은 표시 가림·인접 칸 혼동·주차면/통로·판독 품질·법적 적용·차량 자격·운영 변경·서로 다른 사진을 분리해 검토한다. 총 46개 항목이며, 각 항목은 출처가 구분된 가상 입력 사실, 오인 함정, 입력 범위별 기대 관찰 결과, 필요한 다음 근거, 금지 결론, 공식 출처 ID를 갖는다. 가상의 사정에 대한 기대 결과이지 모델 실행 결과가 아니다.

### 입력 출처와 평가자 설정의 분리 — 2026-10-14 재검토

`sceneFacts`의 각 항목은 `{source, text}` 객체다. **이 안의 사진·메타데이터·시스템 상태도 모두 시나리오를 위한 가정**이며 실제 현장 사진, 실측 시각, 실행 로그를 확보했다는 뜻이 아니다. 2절에서 실제 조회한 법령·정부 안내는 일반 규정 조사 근거이고, 특정 주차장의 설치 사실을 증명하는 외부 기록이 아니다.

| source | 뜻 | 판독 입력에 포함할 때의 한계 |
|---|---|---|
| `photo` | 해당 사진의 보이는 문구·도형·선·차량·가림 범위 | 보이지 않는 구역 용도, 건물 법적 분류, 설치 시기, 이동 방향을 주지 않는다. ‘명확한 구역’ 같은 정답 대신 어떤 표시와 연결이 보이는지 적는다. |
| `capture_metadata` | 촬영 파일/수집 과정에 기록됐다고 가정한 시각·위치 | 사진 픽셀의 관찰과 구분한다. 기록값의 존재가 실제 시각·정확한 위치를 보증하지 않는다. |
| `external_record` | 해당 사례에 제공됐다고 가정한 설치·운영 등 외부 문서 | 제공을 가정했다는 사실, 문서 종류·대상·시점을 명시해야 한다. 실제 확보한 현장 자료처럼 쓰지 않는다. |
| `user_statement` | 사용자가 그렇게 말했다고 가정한 정보 | 사용자 진술로 남기며 사진의 확인 결과나 공식 확인으로 바꾸지 않는다. |
| `system_state` | 선택 대상·원본 ID·요청 버전·저장/오류·자료 미제공 상태 | 사진에서 읽은 사실이 아니다. ‘자료 미제공’은 실제 기록이 없다는 증명이 아니다. |
| `evaluator_only` | 평가자만 아는 배경 설정·숨은 실제 상황 | 아래 두 평가 입력과 기대 관찰 모두의 근거에서 제외한다. 정답을 맞히게 하는 힌트로 전달하지 않는다. |

`expectedObservation`은 다음 두 문장 필드로 나눈다.

- `photoOnly`: `source=photo`의 사실만 입력했을 때 허용되는 관찰이다. 사진 관찰이 없는 DIS-044에서는 사진만으로 판단할 수 없다고 남긴다.
- `withContext`: 사진에 더해 실제로 해당 사례의 입력에 제공한 메타데이터·외부 기록·사용자 진술·시스템 상태를 출처별로 사용할 때의 기대 결과다. 사진만 있는 사례에서는 관찰 범위가 늘어나지 않는다. **`evaluator_only`는 이 경우에도 사용하지 않는다.**

현재 46개 사례에는 사진 가정 113개, 촬영 메타데이터 가정 3개, 시스템 상태 가정 17개, 평가자 전용 설정 20개가 있다. 기존 사례에 실제 제공된 것으로 설정한 개별 현장 문서나 사용자 진술이 없으므로 `external_record`와 `user_statement`는 현재 0개다. 출처 종류를 채우려고 문서나 진술을 새로 만들어 넣지 않았다.

향후 모델 평가 입력을 만들 때는 **허용한 `sceneFacts`만 추려서** 전달한다. `title`, `trap`, `expectedObservation`, `requiredNextEvidence`, `forbiddenConclusions`, `referenceIds`, `evaluator_only` 설정은 평가자용이다. 이 전체 JSON을 그대로 모델에 주고 기대 결과와 일치하는지 재는 방식은 정답 누출이므로 사용하지 않는다. 실제 사진 평가는 이 가상 텍스트를 사진 대신 제공해 성능을 측정하는 작업도 아니다.

이번 재검토에서 바꾼 주요 사례:

- DIS-003: 프레임 밖에 화살표가 존재한다는 전제를 제거했다. 현재 관찰되지 않는다고만 쓰고, 전경을 보완해도 적용 단서가 없으면 해당 면 연결을 확인하지 않는다.
- DIS-013·014·016: 사선의 공식 승하차·기둥 보호·통로 용도와 사진상의 선·기둥·차량 관계를 분리했다. 더 넓게 찍는 것만으로 공식 용도가 정해지지 않는다.
- DIS-025~027: 주택·상점·아파트 안내 같은 외관과 소유·공중이용시설 분류·연식·공식 의결을 분리했다. 후자는 입력에 없으면 확인할 수 없다.
- DIS-037~042: 사람 미관찰, 정지사진의 차량 위치, 표지 문구에서 빈 차·출차·걸어가는 동작·돌봄 관계·특별교통수단 자격을 단정하지 않게 했다.
- DIS-019·021·023·034·043·044: 원본 파생 관계·위치와 날짜·OCR 후보·저장 성공·오류·늦은 응답은 메타데이터 또는 시스템 정보로 이동했다. 사진만 사용하는 결과에서는 이 정보를 이용하지 않는다.
- DIS-045·046: 이미 검토한 동일 차량의 옆 칸 이동과 차량이 떠난 뒤의 사진도, 숨은 상황을 평가자 설정으로 분리했다. 후속 촬영 시점은 메타데이터 출처로만 사용한다.

### 문서 구조 검증과 실제 구현 검증의 구분

이 재검토의 구조 검증은 46개 항목의 고유 ID·필수 필드·허용 출처·기대 결과 두 필드·공식 출처 ID 참조를 검사한다. 별도의 입력 선택 검사에서는 사진 전용 입력에 사진 사실만 남고, 맥락 포함 입력에서도 평가자 설정이 제외되는지 확인한다. 평가자 설정을 삭제하거나 바꿔도 선택되는 입력이 같아야 한다. 이것은 JSON과 입력 선택 규칙의 검사이며, 아직 없는 앱 판독 기능이나 모델의 추론 정확도를 검증하는 시험이 아니다.

2026-10-14 검사 결과: 46개 고유 ID/제목, 출처가 붙은 가상 사실 153개, 두 종류의 기대 결과 92개, 필수 필드·허용 출처·참조 ID·문서 내 개수·로컬 링크·줄 끝 공백 검사를 통과했다. 46개 사례 각각에서 평가자 설정을 삭제하거나 다른 문장으로 교체해도 사진 전용/맥락 포함 입력 선택 결과가 같음을 확인했다. 검사 과정에서 실제 모델·현장 사진·앱 기능을 실행하지 않았다.

추후 구현 후에는 다음을 각각 검증한다.

- 상태/규칙 검증: 모든 시나리오에서 부족한 사진과 부족한 행정자료를 구분하고, 모호한 근거가 위반 확정으로 상승하지 않는지 확인.
- 모델 검증: 사용권이 확인된 실제 주차 사진으로 전경 1회 방식과 원본 부분 분석·면 연결 방식을 비교. 주차장 단위로 평가 자료를 분리하고 같은 장소의 잘라낸 사진이 학습/평가 양쪽에 섞이지 않게 함.
- 측정값: 다른 칸 잘못 연결한 비율, 필요한 증거를 충분하다고 오인한 비율, 이미 충분한데 추가 촬영 요구한 비율, 모호함을 남기는 비율, 유형별 판독 성능, 비용·응답시간. 출처가 다른 행정 확인 결과를 사진 모델 정답으로 혼합하지 않음.
- 두 플랫폼: 원본·보완사진·수동 선택 보존, 대상/면 변경 시 이전 결과 차단, 저장 실패·취소·이어하기를 각각 확인. 빌드 성공을 현장 판독 성공으로 보고하지 않음.

## 7. 남은 검증 공백

1. 전국 모든 시설의 유효한 전용면 설치·변경·폐지 현황을 조회하는 공통 DB는 확보하지 않았다. 주소/GPS만으로 법적 구역 인증을 약속하지 않는다.
2. 시행규칙 별표의 그림 종류별 실제 설치 사례·최신 지자체 안내판 변형을 모두 수집한 것은 아니다. 원본 규정의 그림을 추후 허용된 자료로 검증하고, 현재 형태 하나만을 허용하는 모델로 만들지 않는다.
3. 2026 사업안내의 후속 수정본·정오표 및 지역별 민원 접수 세부 기준은 운영 지역 확정 시 재조회해야 한다. 이 문서의 행정 예외는 시민이 사진으로 자격을 조사하라는 지시가 아니다.
4. 판독 지표의 목표 숫자는 실제 표본을 확보한 뒤 정한다. 확률값 90% 같은 임의 수치로 법적 상태를 확정하지 않는다.
5. 원형/사각형 표지, 임시·시설·보훈 관련 표지의 모든 세부 유효 조건을 이번 사진 분류만으로 검증할 수 없다. 읽힌 내용과 관할 확인 항목을 분리한다.

**최종 제안:** 전체 표시가 안 보이는 실제 주차 상황에서도 구역 근거를 찾되, 그 근거가 정확히 이 차량의 주차면을 가리키는지 검증한다. 법적 성립·이용 자격·최종 처분은 분리한다. 이것이 촬영 부담과 잘못된 추천을 함께 줄이기 위한 협의안이다.
