# 촬영 상황 시뮬레이션 — 입력 출처와 기대 결과 분리

작성일: 2026-10-14. 적용 대상: 장애인 46개·소방차 32개·충전구역 40개, 총 118개 설계 사례. 실제 사진 모델 실행 결과는 아니다.

## 재검토에서 발견한 문제

종전 `sceneFacts` 문자열 목록에는 사진에서 보이는 사실, 촬영 메타데이터, 가정상 제공된 시설 자료, 평가자만 아는 실제 상황이 섞여 있었다. 예를 들어 ‘차가 출차 중이다’와 ‘주차선 밖에 차체가 보인다’는 다른 정보다. 정지사진만으로 전자를 알고 있다고 가정하면 실제 사진 인식보다 쉬운 시험이 된다.

대상 차량 옆 사선 공간의 용도, 건물의 법적 분류, 소방 구역의 인허가 신청일, 충전구역의 세대수·차종도 같은 방식으로 분리해야 한다. 따라서 사례의 출처를 구조화하고 기대 결과를 사진만 있는 단계와 별도 정보가 제공된 단계로 나눴다.

## 입력 필드의 의미

각 `sceneFacts` 항목은 `source`와 `text`를 갖는다.

| source | 의미 | 사용 범위 |
| --- | --- | --- |
| `photo` | 사진에서 관찰하도록 가정한 시각 정보 | 사진 단계에 사용. 실제 모델 평가에서는 이 설명문도 정답 힌트로 주지 않고 원본 이미지를 제공 |
| `capture_metadata` | 촬영시각·원본/사진 ID 등 출처가 있는 메타데이터 | 별도 정보 단계에서 사용. 파일 추가시각과 촬영시각을 혼합하지 않음 |
| `external_record` | 가정상 별도로 제공된 시설·지도·기기·행정 자료 | 출처와 대상 연결이 있는 자료 단계에서만 사용. 실제 확보한 해당 시설 자료라는 뜻이 아님 |
| `user_statement` | 사람이 입력하거나 확인했다고 가정한 내용 | 사용자 확인으로 보존. 사진 AI 확인으로 변경하지 않음 |
| `system_state` | 저장 성공/실패, 요청 버전, 네트워크 오류 등 | 앱 상태 검토에 사용. 이미지에 보인 사실로 바꾸지 않음 |
| `evaluator_only` | 실제 용도·이동 경위 등 평가자만 아는 설정 | 사진 단계와 별도 정보 단계의 입력에서 모두 제외 |

**`title`, `trap`, `expectedObservation`, `requiredNextEvidence`, `forbiddenConclusions`, `referenceIds`는 평가자용이다.** ‘완속 PHEV’, ‘정상 일반면’, ‘출차’ 같은 사례 제목이 정답을 미리 알려 줄 수 있으므로 모델 입력 파일명·프롬프트에 넣지 않는다. 공식 출처 ID도 사진 속 유형을 암시할 수 있어 사진 판독 입력에서 제외한다.

## 기대 결과를 두 개로 나누는 이유

- `expectedObservation.photoOnly`: `photo`로 분류된 내용에서만 가능한 결과. 사진만으로 구별되지 않는 용도·시점·자격은 미확인이다. 사진에 표시가 선명하게 보인다는 문서상 가정이 실제 OCR 성공을 뜻하지 않는다.
- `expectedObservation.withContext`: 사진에 더해 실제로 제공된 것으로 설정한 메타데이터·외부 자료·사용자 응답·시스템 상태를 이용한 결과. 출처별 확인을 유지한다. 외부 자료에 근거한 판단을 사진에서 관찰했다고 쓰지 않는다.
- `evaluator_only`는 둘 모두에서 사용할 수 없다. 평가자가 알고 있는 실제 구역·이동 방향도 모델이 이를 확인할 근거가 없으면 미확인으로 남기는 것이 올바른 기대 결과다.
- 외부 자료가 없으면 `withContext`가 더 확정적인 결과가 될 이유가 없다. API 장애 시 사진의 관찰 결과는 유지하고 자료 확인만 미완료로 남긴다.

## 추가 사진 전후에 확인할 것

한 사진에 차·표지·주차선이 모두 들어왔다는 사실만으로 세 객체의 관계가 모두 확인되는 것은 아니다.

1. **차량→주차면:** 차량이 어느 칸과 연결되는지 확인한다.
2. **표시→주차면:** 화살표·칸 번호·바닥선과의 연결 등 표시 적용 근거가 있는지 별도로 확인한다.
3. **사진→사진:** 해당 면을 구별할 고정 단서·촬영 시점·상충 여부를 확인한다. 같은 차나 반복 도색만으로 연결하지 않는다.
4. **구역/차량→외부 자료:** 자료의 대상·기준일·시설/기기 식별자가 맞는지 확인한다. 외부 자료 연결이 성공해도 사진상 가려진 관계를 봤다고 쓰지 않는다.

각 보완 단계는 어느 관계를 새로 확인했는지와 여전히 모르는 관계를 함께 기록한다. 표지만 크게 찍어도 어느 칸의 것인지 계속 모를 수 있고, 전경을 찍어도 공용 표지의 범위가 불명확할 수 있다. 해결되지 않은 촬영을 성공으로 채점하지 않는다.

반사로 여러 번 보이는 표시도 같은 원본 물체의 반사임을 확인한 경우만 합친다. 확인할 수 없으면 서로 독립된 표시 여러 개로 세거나 임의로 하나로 합치지 않고 반사 의심·연결 미확인으로 남긴다.

## 실제 모델 평가로 옮길 때

1. 원본 이미지와 허용된 맥락을 각각 분리한다. 보이지 않는 정답 설명·사례 제목·기대 결과를 요청에 포함하지 않는다.
2. 사진만 있는 첫 결과를 보존하고, 맥락이 추가된 결과와 따로 비교한다. 출처 없는 자동 확정이 증가하는지 확인한다.
3. 기존 사진→원본 부분→필요한 보완사진의 각 단계에서 새로 얻은 근거와 남은 결손을 기록한다. 모든 사례에 일괄 추가사진을 주지 않는다.
4. 같은 이미지의 확대·자르기와 동일 장소·차량의 연속 촬영은 표본의 의존성을 유지한다. 독립적인 성공 사례 수를 부풀리지 않는다.
5. 구역 확인, 다른 면 오연결, 가림, 자료 충돌, 무의미한 추가촬영, 저장/취소를 따로 평가한다. 여기의 논리 기대 결과와 실제 사진 정답은 별도 검토한다.

현재는 평가 입력을 잘못 구성할 위험을 줄인 설계 자료다. 실제 이미지·모델 출력·인식률·현장 검증 기록은 생성하지 않았다.

각 수정은 미확정 안의 근거·검토 품질 보완이다. 사용자 확정을 대신하거나 다음 유형의 협의를 완료한 것으로 처리하지 않는다.
