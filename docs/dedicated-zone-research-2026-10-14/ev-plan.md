# 친환경차 충전구역 사진 확인 — 단계별 개선 제안

제안·수락 기록일: **2026-10-15, 한국 시각**. 상태: **확정 완료·웹/iPhone 구현 대기**.

수락 기록: 일반차 병행주차 보완안을 제시한 뒤 사용자가 **“다음 진행”**이라고 지시했다. 직전 충전구역 안과 병행주차 보완안을 수락하고 다음 항목으로 진행하라는 뜻으로 해석한다고 사용자에게 명시했으며, 이 범위를 확정 완료·구현 대기로 기록한다. 교차로·지도/GPS·기타·후속 5·6번을 일괄 확정하지 않는다. 전체 계획 확정 후 구현하는 순서는 유지한다.

2026-10-15 추가 요청: **“일반자동차 병행주차 가능 구역에 대한 안내 또는 재확인도 필요할거 같아”**. 안내·재확인 요구를 계획에 추가하고 아래 7-1절에 화면 순서·판독 조건·미확인 저장·추가 가상사례를 구체화했다. 이 추가 요청 자체는 전체 확정으로 처리하지 않았고, 이후 위 “다음 진행” 지시에 따라 보완안을 포함한 수락을 기록했다.

사용자가 소방차전용구역 안에 대해 “확정했어”라고 답해 전용구역 세 번째 안으로 진행한다. [공식 조사·예외](ev-research.md), [문서 기반 가상 상황 40개](ev-scenarios.json), [공개 자료 활용 범위](public-data-feasibility.md), [평가 입력 분리](scenario-input-protocol.md)를 바탕으로 웹과 SwiftUI·AVFoundation iPhone에 같은 기능 의미를 제안한다.

## 1. 민원인에게 달라질 점

차량이 충전 표시를 가려도 기존 원본과 다른 사진을 먼저 확인한다. 충전기가 가까이 있다는 이유로 옆 일반 주차면을 충전구역으로 판단하지 않고, 충전선이 보인다는 사실을 실제 충전 중이라는 결론으로 바꾸지 않는다. 이미 충분한 사진이 있으면 추가 촬영을 요구하지 않는다.

확인 순서는 **구역 표시의 종류 → 표시·충전기·차량이 연결되는 주차면 → 일반차 병행주차 안내·조건 확인 → 필요한 경우 충전 관련 관찰 → 부족한 부분 보완 → 별도 적용 자료 확인**이다. 구역 식별과 차량 자격·계속 주차·시간 초과·법적 허용은 각각의 확인 상태를 유지한다. 사진에서 이미 충분히 확인한 안내를 매번 다시 묻지는 않는다.

## 2. 같은 친환경차 관련 표시도 구분한다

| 사진에서 보이는 표시 | 저장할 내용 | 단독으로 결정하지 않을 것 |
| --- | --- | --- |
| 충전·전기차 충전 표시 | 읽힌 원문, 적용 면과 충전시설 관계 | 인근 모든 면이 충전구역이라는 결론 |
| 친환경차 전용주차 표시 | 주차 용도의 원문과 적용 범위 | 충전기가 안 보이면 일반 주차면이라는 결론 |
| 전기차 우선주차 | ‘우선’이라는 원문과 게시 위치 | ‘전용’으로 바꿔서 인식 |
| 겸용·일반차 허용·시간제 안내 | 허용 대상·시간·유효기간·적용 면·게시 주체 | 안내만 보고 법정 예외 충족 확정 |
| 고장·점검·사용 예정 안내 | 실제 읽힌 글씨와 촬영 시각 | 현재 실제 고장·지정 해제·일반차 주차 허용 확정 |
| 장애인 표시와 충전 표시가 함께 있음 | 같은 면의 두 속성 모두 보존 | 한 유형을 선택했다고 다른 표시를 삭제 |

법 제11조의2는 충전구역과 친환경차 전용주차구역의 허용 차량 범위를 다르게 정한다. 충전구역은 전기차·외부충전식 하이브리드차, 전용주차구역은 전기차·하이브리드차·수소전기차를 열거한다. 구역 종류를 먼저 구분해야 하는 근거이며, 차량 외형·번호판 색·로고로 등록 자격까지 판정하겠다는 뜻은 아니다. [법 제11조의2 제7·8항](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1024298657)

녹색 바닥·번개·EV 글자는 후보를 찾는 단서다. 색 하나로 확정하거나 현재 표준 모양과 다르다는 이유로 제외하지 않는다. 차량이 가린 문구·경계는 추측해서 채우지 않는다. 겸용 여부는 구역 종류를 덮어쓰는 단일 값으로 두지 않고 별도 조건으로 남긴다.

## 3. 사진 확인 단계

1. **대상 차량과 주차면을 정한다.** 차량이 여러 대면 사용자가 대상을 지정할 수 있다. 사용자 선택, 번호판 판독, 동일 차량 확인은 별개로 기록한다. 층·면 번호·기둥·보이는 선·차체의 위치를 확인하고 내부/경계/외부/통로/미확인을 구별한다.
2. **표시를 읽고 원본에서 재확인한다.** 전체 사진에서 후보를 찾은 뒤 작은 문구는 원본 부분을 분석한다. ‘일반차 주차 금지’, 허용 시간·날짜·조건문의 일부를 빠뜨리지 않는다. 자른 이미지에는 원본 ID·영역을 연결하며 새 촬영으로 세지 않는다.
3. **세 연결을 따로 확인한다.** 표시→주차면, 충전기→주차면, 대상 차량→주차면에 각각 근거를 둔다. 바닥 문구·화살표·명시된 면 번호·구별 가능한 고정 특징을 대조한다. 같은 화면에 함께 있음, 가까움, 케이블이 닿을 수 있음, 같은 주소·GPS만으로 연결하지 않는다. 충전시설 연결이 불명확해도 읽힌 충전 표시는 보존하고 남은 연결만 미확인으로 남긴다.
4. **충전 상태는 필요할 때만 별도로 확인한다.** 구역 표시와 차량 위치를 확인하는 데 충분하면 충전기 화면·명판을 일괄 요구하지 않는다. 사용자가 확인하려는 내용이 실제 충전 상태나 시간 조건일 때 관련 자료를 추가로 확인한다.
5. **현재 사진으로 해결되지 않는 부분만 보완한다.** 글씨 문제면 표시 상세, 면 연결 문제면 차량·표시·면 경계의 연결이 드러나는 사진을 안내한다. 한 장으로 여러 결손이 해결되면 안내를 묶는다. 이미 해결한 요구는 지우고, 재촬영으로 해결할 수 없는 문제는 자료 확인이나 미확인 저장으로 남긴다.

세 연결이 항상 세 장을 의미하지 않는다. 한 장이 충분하면 재사용하며 바닥 전체나 모든 표지 요소를 반드시 한 장에 담게 하지 않는다. 다른 사진의 연결에는 반복되지 않는 위치 단서와 시점·모순을 검토한다. 같은 차량이 다른 면으로 이동했거나 면 번호가 층마다 반복되는 상황을 구분한다. 사용자 진술과 외부 도면은 각각의 출처로 남기며 사진 연결 성공으로 바꾸지 않는다.

연결 상태는 **사진 근거로 확인 / 불명확 / 다른 면이라는 반대 근거 있음**을 구별한다. 확인으로 올리려면 적용 면 번호·화살표 등 명시된 범위 또는 가시적인 연속 경계·고유 위치 관계가 대상 면을 구별해 연결해야 하며, 그 원본 영역과 연결 이유를 남긴다. 단서가 몇 개라는 수나 충돌을 못 찾았다는 사실만으로 통과시키지 않는다. 다른 면·층이라는 근거가 생기면 영향을 받는 연결을 다시 검토한다. 구체적인 판독 임계값과 사례별 판정 기준은 구현 명세·실제 사진 평가에서 정하며 현재 모델 성능이 확보됐다고 표현하지 않는다.

## 4. 충전선·화면·기기 정보의 의미

- 선이 안 보이면 ‘미관찰/가림’을 기록한다. 실제로 연결하지 않았는지, 충전할 자격이 있는지, 시간 조건에 해당하는지는 별개다. 선 미관찰만으로 위반이나 합법을 확정하지 않는다.
- 플러그가 꽂힌 모습은 물리적 연결의 근거다. 실제 전력 공급·충전 완료·중단·예약 대기는 그것만으로 구분하지 않는다. 차의 반대편으로 이어지는 선은 끝을 확인하지 못하면 대상 차량 연결 미확인이다.
- 충전기 화면에 ‘충전 중’이 보여도 **같은 기기→같은 채널→대상 차량→해당 시각의 세션**이 연결되는지 확인한다. 다른 차량·다른 채널·이전 세션의 화면을 적용하지 않는다. 표시를 읽었다는 사실과 자료상 운영 상태를 구분한다.
- 기기 ID나 채널이 사진/API에 없으면 임의로 만들지 않는다. 번호·연결 근거가 충분하지 않으면 기기 단위 정보 또는 미확인 상태로 남긴다. 노즐 두 개가 반드시 독립된 동시 충전 채널 두 개라는 가정도 두지 않는다.
- 꺼진 화면·고장 안내·본체 미관찰은 서로 구분한다. 고장 또는 철거가 별도 자료로 확인돼도 주차면 지정이 해제됐다고 자동 처리하지 않는다.
- 급속·완속 정보가 필요한 경우 명판·운영 자료와 출처를 확인한다. 기기 크기나 화면의 순간 출력으로 정하지 않는다. 과금형 콘센트와 일반 콘센트, 이동형 시설도 고정 충전기 모양만으로 제외하지 않는다.

타인 차량·케이블·충전기를 조작하거나 연결을 끊도록 요구하지 않는다. 화면·기기 ID가 확인 불가능하면 그 상태로 자료를 보관할 수 있다.

## 5. 대표 가상 촬영 상황과 다음 행동

아래는 40개 설계 사례 중 대표적인 경우다. 실제 사진 AI 실행 결과가 아니다.

| 상황 | 처리 | 필요한 경우의 보완 |
| --- | --- | --- |
| 큰 차량이 바닥 글씨를 가림(EV-02) | 벽 표지 식별, 차량→면과 표지→면 연결을 각각 확인 | 차량·면 번호·표지 적용 범위가 드러나는 사진. 계속 가리면 미확인 |
| 옆 빈 칸만 충전 표시가 선명함(EV-03) | 옆 칸 표시를 대상 차량에 적용하지 않음 | 대상 면의 선·문구·관계만 보완 |
| 녹색이 아니지만 충전 문구가 읽힘(EV-05) | 색 때문에 배제하지 않고 실제 문구와 면 연결 확인 | 기존 사진이 충분하면 추가 촬영 없음 |
| 충전기 하나에 여러 노즐과 차량(EV-10·11) | 기기·각 연결부·선의 끝·대상 차량 관계를 분리 | 연결 상태를 확인할 필요가 있을 때만 보이는 경로 보완 |
| 선이 꽂혀 있으나 화면이 안 보임(EV-12) | 물리적 연결 관찰, 실제 충전 상태 미확인 | 구역 확인만 필요하면 여기서 종료. 충전 상태가 필요할 때만 화면/자료 확인 |
| 고장 안내가 있거나 화면이 꺼짐(EV-16·17) | 안내 원문/화면 관찰과 실제 상태 구분 | 기기·면·시점이 맞는 운영 자료. 사진 반복 요구 없음 |
| 일반차 허용 시간이 잘려 보임(EV-23) | 조건 일부 미판독으로 남김 | 조건·적용 면이 읽히는 안내 상세사진 |
| 같은 좌표지만 사진은 B2, 자료는 B1(EV-34) | 층 불일치 기록, 기기 연결 재검토 | 층·기기 ID 단서. 지도 좌표로 덮어쓰지 않음 |
| 번호판과 표지만 각각 찍음(EV-36) | 어느 차량·면의 표지인지 연결 미확인 | 차량·표시·해당 면을 연결하는 전경 |
| 같은 번호판을 긴 간격으로 촬영(EV-37) | 두 시점에 관찰됐다는 사실 보존 | 연속 점유를 자동 증명하지 않고 관할 증거 요건 별도 확인 |
| 충전·장애인 표시가 같은 면에 있음(EV-39) | 복수 속성과 각 근거 보존 | 이미 확인된 표시는 재촬영하지 않음. 최종 추천은 후속 5번에서 협의 |
| 구역 밖 차량이 통로를 가림(EV-32·40) | 구역 밖 위치와 통로·충전시설 관계를 별도로 기록 | 필요한 연결 구도만 보완, 실제 방해 여부를 사진 상자 겹침으로 확정하지 않음 |

차량이 떠난 후 사진·과거 안내 사진을 섞는 경우 각각의 시점을 유지한다. 이후 사진이 당초 시점의 운영·표시나 계속 주차를 자동 증명하지 않는다. 가려짐·반사·변경 표시를 해소할 수 없으면 불명확 사유와 자료를 보존한다.

## 6. 지도·공개 충전기 자료 활용안

한국환경공단 공개 API 설명은 충전소/충전기 ID, 주소·좌표, 지상·지하 층수 관련 정보, 기기 타입, 운영·상태 시각 등의 항목을 제공한다고 안내한다. [공식 데이터 설명](https://www.data.go.kr/data/15076352/openapi.do)

이를 바탕으로 사진에서 읽은 기기 번호·운영사·층과 공개 후보를 대조하는 기능을 제안한다. 실제 해당 레코드에 값이 있는지·같은 기기인지·자료 기준일과 상태 시각이 무엇인지 먼저 확인한다. 공개 ID와 본체 표기 ID가 항상 같은 형식이라고 가정하지 않고 연결 가능한 경우만 대조한다.

조회 성공은 주차면 지정·차량 자격·대상 차량의 충전 인증이 아니다. 채널·차량 식별을 API가 제공한다고 가정하지 않는다. 조회 시각과 상태갱신일시는 따로 저장하고, 현재 조회값을 과거 촬영 당시 상태로 옮겨 적용하지 않는다. 시간대와 갱신 정책·누락·페이지 범위는 실제 응답을 확보한 뒤 검증한다. 사진과 자료가 다르면 양쪽 출처·시점을 남긴다.

API 미등록·검색 없음·오류는 구역이 없다는 증거가 아니다. 연결 실패에도 사진 촬영·저장·수동 주소 입력을 유지한다. 이번 안은 공개 자료 연결 방식을 제안하며 실제 키 발급·인증 API 연동·계정 설정은 아직 수행하지 않았다. 지도 공급자와 GPS 수치의 공통 미확정 상태도 유지한다.

## 7. 운영·차량 자격·시간 조건은 따로 확인한다

겸용·일반차 허용 문구가 있으면 그대로 보존하고 대상 차량 종류·시간·적용 면·게시 주체·유효기간을 확인한다. 그 안내를 무시하거나 법적 예외 충족으로 자동 승격하지 않는다. 건물 용도·세대수·입주 차량 수·관리 권한은 외관이나 사진만으로 판단하지 않는다. 자료 미확인 때문에 시민에게 인허가·차량등록 서류를 반드시 제출하게 하거나 기록 저장을 막지 않는다.

시간 초과 확인은 구역 식별과 분리한다. 기기 종류·차량 종류·시설 조건·촬영 시점에 유효한 규칙을 확인하고, 사진 간격·계속 점유 근거·관할 접수 요건을 별도로 관리한다. 기존 기본 6개의 간격이나 과거 지역 안내를 복사하지 않는다. 충전 화면의 시작 시각·최근 충전 이력·사용자 체류 진술을 검증된 주차 시작 시각으로 바꾸지 않는다.

2026-10-14 연구에 기록한 시간·시설 예외 수치는 그날 확인한 버전의 조사 기록이다. 이번 안의 확정 대상은 **조건별 규칙과 근거를 분리하고 촬영 시점에 맞는 버전을 적용하는 구조**이며 특정 수치를 영구 고정하는 것이 아니다. 구현·출시 때 공포·시행 여부와 관할 최신 공고를 재확인한다. 입법예고는 현행 규칙으로 사용하지 않는다.

## 7-1. 일반자동차 병행주차 안내·재확인 추가안

### 왜 별도 단계가 필요한가

충전구역 표시는 식별했어도 일반차 병행주차 안내를 놓치면 민원인이 불필요한 촬영을 계속하거나 예외를 누락한 초안을 만들 수 있다. 기존 수동 안내의 ‘겸용 표시 있음/없음/모름’ 한 값으로는 일반차 허용, 전기차의 시간 초과 허용, 적용 칸과 촬영 시각을 구분하기 어렵다. 사용자가 모를 때도 자료를 보관할 수 있는 짧은 확인 단계를 둔다.

이 재확인은 충전구역 후보와 대상 면을 검토할 때 표시하고, 기록 검토 화면에서도 요약을 다시 볼 수 있게 한다. 첫 촬영·두 번째 기본 촬영·저장을 막는 사전 문답으로 만들지 않는다. 기본 안내는 짧게 노출하되 질문은 아직 확인되지 않은 항목에만 한다. 이미 답했거나 같은 사진에서 해결된 내용을 화면 이동마다 반복하지 않는다.

### 보여줄 안내와 질문

기본 안내: **“이 칸에는 일반 자동차도 주차할 수 있다는 안내가 있을 수 있어요. 적용되는 칸과 조건을 함께 확인해 주세요.”** 모든 충전구역이 병행주차 가능하다거나 밤에는 일반차가 가능하다는 뜻으로 표시하지 않는다.

| 현재 상태 | 사용자에게 보여줄 문구·선택 | 기록할 의미 |
| --- | --- | --- |

### 적용 칸·촬영 당시 조건 재확인

표시에서 **허용 대상, 허용 행위, 적용 층·면, 시간대·요일·날짜·유효기간, 기타 조건, 게시 주체**를 읽히는 범위에서 추출한다. 구역 전체에 적용되는 안내인지 특정 몇 개 면만 적용되는지도 구별한다. 빈 필드는 제한 없음이나 상시 허용으로 바꾸지 않는다. 명시적으로 ‘상시’라고 읽힌 사실과 조건 부분이 사진에 없다는 사실은 다르다.

시간 대조는 현재 앱을 열어 본 시간이나 업로드 시간이 아닌 **각 사진의 촬영 시각과 출처**를 사용한다. 자정을 넘는 시간, 요일·휴일, 공지 시작/종료일, 원문상 종료 시각 포함 여부가 불분명한 경계를 처리한다. 시각·시간대가 없거나 모순이면 대조 불가로 남기며 사용자가 입력한 시각은 별도 출처다. 휴일 자료가 없으면 일반 요일 계산으로 휴일 조건을 통과시키지 않는다. 두 기본 사진이 시간 경계의 앞뒤에 있으면 각각의 결과를 보존하고 사건 전체를 하나의 허용/불허로 합치지 않는다.

예를 들어 가상의 안내가 ‘일반차 22:00~다음 날 07:00, 12~14번 면’이라면 23:10 사진의 대상이 13번 면인지 별도로 확인한 뒤 **“안내의 면·시간 조건과 촬영 정보가 일치함”**까지 표시한다. 번호판으로 이용자 자격까지 확인하거나 법적 주차 허용을 확정하지 않는다. 이 예시 시간·면 번호는 전국 규칙이나 실제 시설 정보가 아니다.

재확인 사유는 대상 면 변경, 새 표지·상충 자료, 시간 조건을 넘는 새로운 촬영, 촬영 시각 정정, 이어하기 중 다른 시점의 안내 추가다. 현행 공지를 과거 촬영에 소급 적용하지 않고, 오래된 안내 사진을 촬영 당시 유효 공지로 자동 사용하지 않는다. 차량·면·사진·자료가 바뀌면 영향을 받는 확인만 갱신하고 이전 결과와 변경 이유를 남긴다.

### 결과·초안·사용자 선택

관찰 요약은 `일반차 병행주차 안내 확인`, `적용 칸 확인 필요`, `촬영 시각과 안내 시간 대조 불가`, `전기차 시간 조건 안내`, `안내·자료 충돌`, `일반차 허용 여부 미확인`을 구별한다. 안내 조건과 사진 정보가 맞아도 ‘합법’, ‘위반 아님’, ‘신고 불가’로 자동 전환하지 않는다.

안내가 확인되면 사용자에게 어느 부분이 근거인지 보여 주고, 아직 없는 적용·운영 자료는 별도로 표시한다. AI가 자동 생성할 초안에는 확인된 허용 안내와 남은 조건을 누락하지 않는다. 미확인 예외가 있는데 ‘일반차 불법주차 확정’처럼 단정하는 문장을 생성하지 않는다. 사용자가 직접 작성한 본문·유형·설명은 덮어쓰거나 지우지 않으며 관찰 요약을 함께 보관한다. 최종 추천 우선순위와 확인 질문의 공통 정책은 후속 5·6번에서 확정한다.

병행주차 안내가 있어도 인접 충전시설 접근·통로 방해 등 별도 관찰이나 같은 면의 장애인 표시를 없애지 않는다. 병행 안내를 찾지 못했거나 추가 확인을 건너뛰면 ‘허용 여부 미확인’으로 남겨 저장한다. 건너뛴 사실을 점검 완료·예외 부재로 처리하지 않는다.

### 기술적으로 추가할 데이터·상태

기존 `sharedSign`의 세 값만으로 처리하지 않고 **안내 원문·사진 영역, 일반차 허용과 전기차 시간 허용의 구분, 적용 면, 조건, 게시 주체·자료 시점, 사용자 답변, 사진별 조건 대조 결과, 미확인/충돌 사유**를 별도로 둔다. 하나의 안내에 여러 조건이 있을 수 있게 한다. 실제 법적 적용 상태와 화면에서 읽은 안내 상태는 별개다.

확인 결과에는 사진·면·공지·규칙의 입력 버전을 연결한다. 사용자 수정과 뒤늦은 AI/API 응답이 충돌하면 새 선택을 보존하고 관련 연결만 재검토한다. 웹과 iPhone에 동일한 의미·질문·저장/취소/이어하기를 적용한다. 기존 기록의 `sharedSign=yes`는 ‘이전 사용자 입력에 겸용 표시 있음’으로 호환하며 일반차 허용·적용 시간까지 확인됐다고 승격하지 않는다. 본문·원본은 새 저장 성공 전 보존한다.

| SP-06 | 관리사무소 구두 답변만 입력됨 | 사용자 진술로 보관. 공식 지정 또는 사진 확인으로 승격하지 않음 |
| SP-07 | 촬영 후 새 안내가 부착됨 / 오래된 사진이 추가됨 | 안내 시점과 사건 시점 분리. 소급 적용 금지 |
| SP-08 | 벽 안내는 일반차 허용, 별도 공지는 금지·변경 | 대상 면·유효기간·출처 검토, 해결 전 충돌 보존 |
| SP-09 | 허용 안내 면의 차량이 옆 충전 접근을 가리는 모습 | 병행 안내와 별도 방해 관련 관찰을 함께 보존 |
| SP-10 | ‘입주민 등록 차량만’ 조건이 잘리거나 자격을 알 수 없음 | 조건 누락 보완 또는 자격 미확인. 모든 차량 허용으로 채우지 않음 |

구현 후에는 안내 미발견·원문 오독·옆 면 적용·자정/휴일·촬영 시각 누락·안내 변경·상충·오래된 응답·취소/복원을 검증한다. 사용자가 이미 충분한 자료를 줬을 때 중복 질문이 사라지는지, 모름·건너뛰기로 저장해도 확인 완료가 되지 않는지 확인한다. 이는 로직 시험과 실제 사진 판독 성능 시험으로 나누어 보고한다.

### 확인한 법적 근거와 한계

2026-10-15 국가법령정보 검색과 별표 파일 추출로 현행 시행령(2025-10-01 시행, MST 278487)의 별표 제1호다목을 다시 확인했다. 일정한 아파트의 충전시설 설치 면 수·입주자 등의 전기차 등 수량·관리주체 등의 표시를 전제로 일반차 주차와 전기차 등의 시간 초과 주차를 나누고, 부과권자가 해당 과태료를 부과하지 않을 수 있도록 정한다. 단순히 현장에 안내가 보인다는 이유로 전국 공통의 자동 면제·무조건 주차 가능으로 설명하지 않는 근거다. [현행 시행령·별표](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=278487)

초기 날짜 지정·별표명 조회는 도구에서 파일을 찾지 못했으나, 반환된 실제 별표번호 `000000`으로 재조회하여 현행 별표 본문을 확인했다. 별표가 존재하지 않는다는 결론으로 사용하지 않는다. [2026-552호 입법예고](https://www.moleg.go.kr/lawinfo/makingInfo.mo?lawSeq=88174&lawType=TYPE5)의 적용 시설 확대안은 입법예고로 구분한다. 향후 촬영·구현 시점의 확정 공포·시행 여부를 다시 확인한다. 개별 시설의 수량·관리 권한·병행 면 지정 자료나 인증 API 응답을 이번에 확보한 것은 아니다.

## 8. 기술 변화·실패 처리·검증

GitHub 기준 웹의 기본 6개 판독에 새 전용구역 분석 항목을 추가하는 계획이다. 기존 로컬 웹·iPhone의 수동 전용구역 질문과 사진 역할은 보존하고, 실제 사진 판독 결과와 구분한다.

| 추가할 구조 | 사용자에게 갖는 의미 |
| --- | --- |
| 구역 종류·겸용/시간 조건·복수 속성의 개별 기록 | 전용주차·충전·일반차 허용을 섞지 않고 설명 |
| 표시→면, 기기→면, 차량→면 연결과 반대 근거 | 옆 칸·다른 층·다른 기기를 잘못 적용하는 오류 방지 |
| 물리적 케이블 연결·화면 원문·자료상 운영 상태 분리 | 선이나 화면 하나로 대상 차량 충전 중이라고 단정하지 않음 |
| 사진·사용자 답변·외부 자료의 출처·유효시각·버전 | 현재 자료를 과거 촬영 사실로 바꾸거나 사용자 답변을 AI 확인으로 바꾸지 않음 |
| 부족 정보별 다음 행동과 해결 상태 | 필요한 보완만 안내, 자료 문제·통신 오류는 재촬영과 구분 |

확정된 원본 보존·기본 사진 ID·보완사진 복수 역할·저장/취소/이어하기 흐름을 사용한다. 저장 성공 전 기존 사진·주소·본문·선택은 유지한다. 대상 차량·주차면·표지가 바뀌면 영향을 받는 연결만 재확인하고 옛 분석 응답이 덮어쓰지 못하게 한다. 사진 교체는 의존 관찰을 무효화하되 변경 이력을 남긴다. 보완사진이 기본 시간 비교 쌍과 대기시간을 초기화하지 않는다.

구현 후에는 저장·취소·복원·옛 응답·다른 면 연결·자료 충돌을 로직 시험으로 확인하고, 실제 사진 표본에서 표시 오인/누락·면 오연결·충전 상태 과잉 확인·불필요 보완 요청을 따로 측정한다. 평가자만 아는 정답과 기대결과를 모델 입력에서 제외하고, 동일 원본·차량·장소가 보정과 평가에 섞이지 않게 한다. 웹/iPhone의 구현·빌드·실행·실기기 촬영·실제 모델 정확도·실제 API 호출 상태는 각각 기록한다.

현재는 공식 자료 조사와 40개 문서 가상사례 검토·개선안 기록 단계다. 2026-10-15 독립 검토에서 복수 표시·조건 보존, 세 연결의 확인/불명확/반대 근거 구분, API가 채널·차량·세션을 제공한다고 가정하지 않는 조건을 점검했다. 2026-10-15 제안 시 법 제11조의2 본문과 충전소 API 공개 항목을 다시 확인했다. 시행령·고시 페이지의 시행 표시는 확인했으나 이 웹 도구의 추출에는 본문/별표가 포함되지 않았다. 해석례 26-0093 직접 열기와 대체 첨부파일 접근도 성공하지 못해 선행 API 확인 기록과 구분한다. 이번 턴에 세부 시간·예외의 전체 원문을 새로 검증했다고 보고하지 않는다. 실제 사진 AI 실행·기능 구현·빌드·push는 하지 않았다.

## 9. 수락 범위와 다음 협의

확정안은 **구역 종류를 읽고 세 연결을 따로 확인하며, 충전 상태·운영 조건·시간을 구분하고, 필요한 사진만 보완하는 방식**이며 7-1절의 일반차 병행주차 안내·재확인을 포함한다. 수락 원문은 2026-10-15 “다음 진행”이며 직전 보완안 수락으로 해석해 기록했다. 본문은 계획 내용으로, 기능 구현이나 실제 인식 정확도 검증을 완료했다는 뜻이 아니다. 다음에는 미확정 교차로 모퉁이 안을 정리한다. 기타 범위·지도/GPS 공통 설정과 원래 5번 사진 근거 중심 추천, 6번 확인 질문·선택 유지 협의도 남는다. 모든 계획 확정 후 웹과 iPhone 구현·검증을 진행하고 푸시 직전 상태에서 실제 변화와 한계를 설명한다.
