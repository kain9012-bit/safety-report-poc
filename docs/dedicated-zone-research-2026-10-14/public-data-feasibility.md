# 전용구역 사진 확인을 보조할 공개 자료 — 연결 가능 범위

확인일: 2026-10-14. 상태: **공식 데이터 설명·공개 항목 조사, API 연동 전·사용자 세부안 확정 전**.

사진에서 본 표시가 어느 주차면의 것인지 확인할 때 외부 자료가 어디까지 도움을 줄 수 있는지 조사했다. 아래는 제공기관의 공개 문서와 화면에서 확인한 내용이다. 인증 API를 호출해 실제 시설의 현행 지정·차량 상태를 검증한 결과가 아니다.

## 1. 장애인 구역: 주차장 단위의 보유 정보는 활용 후보가 있다

[공공데이터포털 전국주차장정보표준데이터](https://www.data.go.kr/data/15012896/standard.do)는 주차장관리번호, 주차장명, 주소, 위도·경도, 관리기관, 장애인전용주차구역보유여부, 데이터기준일자를 제공한다. 공개 화면의 실제 표에서도 보유 여부와 기준일을 확인했다. 제공 범위는 지방자치단체가 관리하는 대상 공영·민영 주차장이고 거주자우선주차구역은 제외된다. 안내된 갱신주기는 반기이며 기관별 자료를 매월 병합해 시차가 생길 수 있다. 페이지 수정일은 2026-04-20으로 표시되어 있다.

**설계에 대한 판단:** 이 자료로 주변 주차장 후보와 그 시설의 장애인 구역 보유 정보를 찾을 수 있다. 공개 항목에는 칸별 경계·층·개별 면 지정 이력이 없으므로 특정 차량이 있는 주차면의 구역 인증 자료로 쓰지 않는다. 전국의 모든 실제 전용면이 빠짐없이 들어 있다고 가정하지 않는다.

제안하는 결과 문구는 ‘이 주차장은 공개 자료에 장애인 구역 보유로 등록되어 있습니다. 자료 기준일: …’다. 사진의 ‘해당 면 연결 확인됨’과는 별도 상태다. 보유가 N·공란이거나 검색 결과가 없더라도 사진에서 관찰한 표시를 지우지 않는다. 해당 자료의 누락·변경·위치 불일치 가능성을 남긴다.

## 2. 충전구역: 충전기 식별자와 층·상태 정보도 활용 후보가 있다

[한국환경공단 전기자동차 충전소 정보](https://www.data.go.kr/data/15076352/openapi.do)의 설명에는 충전소/충전기 ID, 상세주소·좌표, 지상/지하 층수 관련 정보, 기기 타입·운영 정보·삭제 여부와 상태 시각 등이 제시되어 있다. 페이지 수정일은 2026-07-21이다. 공개된 상태 API는 `getChargerStatus`이며 기관 ID(`busiId`), 충전소 ID(`statId`), 충전기 ID(`chgerId`), 상태(`stat`), 상태갱신일시(`statUpdDt`) 등을 설명한다. 인증키를 요구하므로 이번 조사는 문서 확인까지다.

**설계에 대한 판단:** 사진에서 읽은 기기 ID와 제공기관·충전소·충전기 식별자를 대조해 잘못된 시설/층 연결을 줄일 수 있다. 층 필드가 제공된다는 사실과 모든 실제 레코드에 정확히 채워져 있다는 사실은 다르므로 값·누락·출처를 확인해야 한다. 기기 위치를 확인해도 대상 차량의 주차면 경계나 법적 지정이 확인된 것은 아니다.

특히 기기 상태가 ‘충전 중’이어도 그것이 사진 속 대상 차량의 충전 상태라고 연결하지 않는다. 같은 기기의 여러 채널, 다른 차량, 이전 시점의 정보일 수 있다. 사진과 기기·채널·대상 차량·시점의 연결이 부족하면 기기 단위 자료로만 남긴다. 차량 식별 정보가 API에서 제공된다고 가정하지 않는다.

API 조회 시각과 제공기관의 상태갱신일시는 따로 보관한다. 상태 변경 시각을 방금 측정한 시각으로 바꾸거나, 시각이 오래되었다는 이유만으로 통신 장애를 확정하지 않는다. 타임스탬프의 시간대·미변경 상태의 갱신 정책은 상세 명세와 실제 응답을 확인한 뒤 처리한다. 고장 안내 사진·기기 API·현장 모습이 다르면 각각의 관찰과 시각을 보존한다.

## 3. 소방차 구역: 개별 구역의 자료 연결은 미확보

2026-10-14 공개 검색에서 ‘소방차전용구역/소방차 전용구역’, ‘현황·좌표·공공데이터’ 조합을 확인했으나, 이번 조사에서 전국 개별 구역의 경계·식별자·인허가 신청 시점·현재 지정 상태를 함께 검증할 데이터는 확보하지 못했다. 이는 해당 데이터가 어디에도 없다는 결론이 아니다.

후속 설계는 지역 자료가 실제로 확보되면 출처·대상 구역·기준일·공간적 범위를 확인해 연결하는 방식으로 둔다. 건물 주소 또는 준공 정보만 확보한 상태를 개별 전용구역 설치 근거 확인으로 올리지 않는다. 외부 도면에 연결된 근거는 사진상 연결과 분리한다. [소방차 조사와 적용 시점의 구분](fire-research.md)을 따른다.

## 4. 자료가 들어와도 유지해야 할 확인 순서

| 주어진 자료/상황 | 가능한 활용 | 남는 확인 |
| --- | --- | --- |
| 주차장 보유 여부 Y | 주변 시설 후보·시설 단위의 등록 정보 표시 | 촬영한 칸이 해당 구역인지, 현재 표시와 일치하는지 |
| 보유 여부 N·공란·검색 없음 | 자료 미확인/불일치 사유 보존 | 사진의 표시가 실제 없는지로 바꾸지 않음 |
| 충전소 좌표 같음, 사진 B2·API B1 | 층 불일치를 기록하고 후보 재검토 | 대상 기기·면 연결 |
| 기기 ID와 층 모두 일치 | 기기 자료를 해당 사진과 연결하는 보조 근거 | 어느 주차면에 적용되는지, 기기 상태가 어느 차량에 해당하는지 |
| 현장 고장 안내와 API 이용 가능이 충돌 | 문구 관찰과 기기 API 상태를 출처·시각별 보존 | 현재 운영 상태·지정 상태. 어느 쪽도 조용히 덮어쓰지 않음 |
| 검증된 시설 도면이 제공됨 | 도면의 구역·기준일과 사용자 선택을 대조 | 실제 사진의 면 연결, 촬영 시점 이후 변경 여부 |
| API 실패·페이지 일부·자료 지연 | 부분 조회·오류·조회 시각 기록 | 미조회 자료를 시설/구역 부존재로 처리하지 않음 |

사진 모델에는 우선 보이는 내용을 독립적으로 읽게 한다. 외부 후보·자료는 별도 대조 단계에서 사용하며 어느 출처가 어떤 결론을 보강했는지 남긴다. 문서 기반 시뮬레이션에서도 이 입력 경계를 유지한다.

## 5. 구현 때 확인할 것

- 현재 명세·실제 응답, 키 권한, 호출량, 페이지 누락, 지역 범위, 레코드 기준일·갱신 의미를 확인한다. 문서상 제공 항목을 실제 확보값으로 표시하지 않는다.
- 시설/기기 자료의 일치가 사진상 면 연결을 대신 통과시키지 않는지, 누락 자료가 사진 근거를 지우지 않는지 확인한다.
- 사용자 주소·시설 선택은 자료 조회 실패나 옛 비동기 응답으로 덮어쓰지 않는다. 사진 촬영·보관·수동 입력을 계속 제공한다.
- 공개 자료를 사용하는 출력에는 해당 이용조건에 맞춰 출처를 남긴다. 새 공급자 계정·API 연동이 이미 완료된 것으로 보고하지 않는다.

이 내용은 기존 장애인 안의 ‘GPS/지도는 보조 근거’ 원칙을 구체적인 공개 항목으로 보강한 조사 기록이다. 지도 공급자·GPS 수치 또는 전용구역 세부안을 대신 확정하지 않는다.
