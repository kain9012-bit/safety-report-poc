# 친환경차 충전구역 심층 조사·후속 협의 초안

확인일: 2026-10-14, 한국 시각. 상태: **친환경차 충전구역 확정안의 조사 근거·기능 미구현**. 일반차 병행주차 보완 후 2026-10-15 사용자 “다음 진행”을 직전안 수락으로 해석한다고 알리고 세부안을 확정 완료·웹/iPhone 구현 대기로 기록했다. 2026-10-15 소방차 안 확정 후 [단계별 개선안](ev-plan.md) 협의를 시작했다. 장애인전용주차구역부터 순서대로 협의하는 전체 계획 중 친환경차 유형을 준비한 자료다. 여기의 권장안·시나리오가 사용자의 승인을 뜻하지 않는다. 메인 협의 문서와 기능 코드는 변경하지 않았다.

## 1. 먼저 해결해야 하는 구분

친환경차 관련 구역을 하나의 `ev_charging=true`로 묶으면 일반 하이브리드차가 허용되는 전용주차구역과 전기 충전구역을 혼동한다. **구역의 종류, 대상 차량이 있는 면, 운영·지정 자료, 법적 위반 판단을 별도로 저장**하는 것이 이번 개선의 중심이다.

| 구분 | 사진에서 읽을 대상 | 사진만으로 확정하지 않을 것 |
|---|---|---|
| 충전구역 | 충전 표시·문구·면의 경계·해당 충전기·면 번호 | 근처에 충전기가 있다는 이유만으로 모든 주변 면이 충전구역이라는 결론 |
| 친환경차 전용주차구역 | 전용주차 문구와 적용되는 면·표지 범위 | 충전기가 없다는 이유만으로 일반 주차구역이라는 결론 |
| 일반 주차면·충전구역 밖 | 대상 차량과 충전구역의 상대 위치, 진입로 연결 | 면 밖이라는 이유로 진입·충전 방해 가능성이 전혀 없다는 결론 |
| 병행·겸용·시간제 허용 표시 | 허용 대상, 시간, 적용 면, 게시 주체·기간 | 관리사무소 안내만 보고 전국 법정 예외 충족이라고 확정 |
| 고장·미개통·철거·임시 이전 | 현재 기기 상태 표시, 철거 흔적, 바뀐 안내 | 고장 또는 철거 흔적만으로 구역 지정까지 해제됐다는 결론 |

법 제11조의2제7항의 충전구역 대상과 제8항의 전용주차구역 대상은 다르다. 전자는 전기차와 외부충전식 하이브리드차, 후자는 전기차·하이브리드차·수소전기차를 규정한다. 이는 차량 외양으로 어느 차량인지 판정할 근거가 아니다. 차량 자격은 사진상 단서와 확인된 등록·공식 자료를 구분해야 한다. [EV-L1]

## 2. 현행 법령에서 확인한 중요사항

### 색과 표지는 도움이 되지만 단일 필수 조건이 아니다

2026-09-14 시행 고시 별표2는 녹색 바탕·흰색 실선과 문자를 원칙으로 하면서, 해당 기준으로 설치하기 부적합하면 색상이나 문자를 달리할 수 있게 한다. 안내표지도 설치할 수 있도록 규정한다. 따라서 “녹색이 아니면 충전구역 아님”, “벽 표지가 없으면 아님”, “녹색이면 무조건 충전구역”을 모두 금지한다. [EV-R1]

표준 모양은 후보를 찾는 참고자료다. 차량에 가려진 바닥 전체를 AI가 채워 넣지 않는다. 색상 불일치는 표지 문구·면 번호·충전기 배치·운영 자료를 추가로 살펴야 하는 사유로 사용한다.

### 시간 기준은 충전기 종류·차량 종류·시설에 따라 다르다

2026-10-14 현재 고시 제6조에서 확인한 값은 급속 1시간, 완속 전기차 14시간, 완속 플러그인 하이브리드차 7시간이며 마지막 경우 0~6시는 제외해 산정한다. 완속 시간 초과 규정의 시설 예외에는 단독주택, 연립·다세대주택, 100세대 미만 아파트가 있다. 이는 모든 주차·진입 방해에 대한 포괄적 면제가 아니다. 급속 2시간이라는 시행령의 위임 한도를 실제 고시 시간으로 사용하거나, 예전 500세대 기준을 유지하면 안 된다. [EV-R1, EV-D1]

시행령은 충전 시작 시각만을 기준으로 한 표현이 아니라 계속 주차에 관한 요건을 둔다. 사진 두 장은 그 시각의 관찰을 제공할 뿐, 중간에 떠났다가 돌아오지 않았다는 사실이나 총 점유기간을 자동 보증하지 않는다. 공식 주민신고에서 요구하는 사진 수·간격·중간 사진은 해당 관할의 유효한 안내를 확인해야 한다. [EV-D1, EV-I1, EV-M2]

### 충전선이 안 보인다는 이유로 곧바로 위반으로 바꾸면 안 된다

법제처 26-0093(2026-04-22)은 전기차 등이 충전하지 않은 채 급속·완속 제한시간 이내로 주차하는 경우를 해당 시행령 제18조의8제1항제6·7호의 충전 방해에 해당하지 않는다고 해석했다. 다른 요건·관리규정에 대한 포괄적 허용 선언은 아니다. [EV-I1]

2026-08-20 입법예고에는 미충전 주차, 구역 밖 충전기 점유, 오피스텔 등 병행주차 확대가 제안돼 있다. **입법예고를 현행 규칙에 넣지 않는다.** 이번 조회에서 현행 시행령은 2025-10-01 시행본이었다. 구현·출시 시점에는 확정 공포·시행 여부를 다시 확인한다. [EV-P1, EV-D1]

### 병행주차와 설치시기 예외

시행령 별표의 병행주차 관련 미부과 재량은 아파트, 충전시설이 설치된 면 수와 입주자 등의 전기차 등 수량, 관리주체의 적용 면 표시 등 요건을 갖는다. 일반차 허용과 전기차 등의 시간 초과 허용은 서로 다른 분기다. 단순한 “공유 가능” 스티커만으로 충족 여부를 알 수 없다. [EV-D2]

2024-02-14 법제처 해석은 당시 규정의 아파트 예외에 오피스텔을 포함하지 않았다. 현행 별표와 대조해도 아파트라는 문구가 유지되지만, 확대 입법예고가 있어 이후 변경 확인이 특히 필요하다. [EV-I2, EV-P1]

건물의 오래된 외관 또는 설치연도가 빠르다는 사실로 일괄 제외하지 않는다. 2022년 시행령 부칙에는 기축시설 설치 의무 유예·연장 등 규정이 있지만, **설치 의무의 대상·기한과 이미 있는 구역의 주차·방해 여부는 별개의 질문**이다. 준공·허가·설치·이전·해제일은 근거 자료가 있을 때만 기록한다. [EV-D3]

## 3. 권장 인식 절차

1. **대상 차량과 면을 정한다.** 여러 차량이면 사용자가 대상만 지정할 수 있다. 사용자 선택은 번호판 OCR 성공이나 위반 확인으로 승격하지 않는다. 대상 면의 보이는 선, 차륜·차체, 면 번호, 층·기둥 번호를 원본 좌표에 연결한다.
2. **충전 표시의 종류를 읽는다.** `충전`, `전용주차`, `우선주차`, `겸용`, `일반차 허용`, 시간대, 적용 화살표를 원문과 함께 읽는다. `EV`·번개·녹색·파란색 하나만 있으면 종류 미확인으로 둔다. 부정어·조건문·유효기간을 버리면 안 된다.
3. **표시가 그 면에 적용되는지 대조한다.** 표지→면, 충전기→면, 차량→면의 연결마다 근거를 둔다. 케이블이 닿는 범위, 화면 속 사각형 겹침, 표지와 차량의 단순 근접성만으로 연결하지 않는다. 차량·기둥·면 경계가 한 사진에 함께 나와 차량→면 관계를 확인했어도 표지→면의 적용 범위까지 자동 확인하지 않는다. 벽 표지가 여러 면을 가리키면 화살표·명시된 적용 면 번호·범위를 별도로 확인한다.
4. **운영 안내의 관찰·실제 운영 확인·지정 근거를 분리한다.** 고장/점검/미개통이라는 글씨가 보인다는 것과 촬영 당시 실제로 그 상태였다는 것은 다르다. 본체가 안 보이는 것도 철거 확인이 아니다. 실제 운영 상태에는 기기·채널·출처·유효시각을 연결하고, 지정·폐지·시간별 허용은 별도로 확인한다. 화면 또는 운영 자료를 대상 차량에 연결할 때는 **동일 기기 ID→동일 채널→대상 차량의 물리적 연결→해당 촬영시각의 세션**을 대조한다. 같은 기기의 다른 채널·다른 차량·이전 세션일 수 있으므로 연결하지 못하면 화면 문구만 관찰로 남긴다. 조회가 일치하더라도 최신 시각과 상태 지연 가능성을 표시하고, 현장 사진과 충돌하면 충돌을 남긴다.
5. **원본 재분석 후 빠진 것만 보완한다.** 표지 글씨 문제는 상세 사진, 면 연결 문제는 차량·표시·경계를 함께 보인 사진을 안내한다. 한 장으로 두 목적이 충족되면 추가 요구를 줄인다. 사진으로 알 수 없는 건물 세대수·차량 등록 자격·관리주체 승인 등은 자료 확인으로 넘긴다.
6. **사진의 관찰 결과와 법적 점검 결과를 따로 보여 준다.** 예: `대상 차량이 충전 표시가 있는 12번 면에 보임`, `충전기 고장 표시 확인`, `일반차 허용 안내의 법적 적용 확인 필요`. “위반 확정”은 출력하지 않는다.

기본 구역 식별에는 원본 전체·표시·면 연결이 우선이다. 시간 초과를 사용자가 확인하려는 경우에만 급속·완속 기기 정보와 시간 증거를 다음 단계로 요청한다. 모든 신고에 화면·명판·차량 자격 서류·여러 각도의 촬영을 필수로 요구하지 않는다.

## 4. 구조·데이터 제안

아래 필드는 확정된 구현 스키마가 아닌 후속 논의용이다.

| 그룹 | 보관할 항목 | 중요한 실패·충돌 처리 |
|---|---|---|
| 사진 관찰 | 원본 ID, 촬영 시각, 읽은 원문, 표시·기기·차량·면의 원본 영역 | OCR 실패/안 보임/표시 없음/분석 장애 구분 |
| 구역 종류 | 충전/전용주차/겸용표시/일반면/분류 불가, 근거 ID | 사진 확인과 공식 지정 확인을 다른 상태로 보관 |
| 면 연결 | targetVehicleId, bayId, visibleBoundary, signScope, chargerToBay | 연결 명확/불명확/반대 근거 구분; 사용자 지목만으로 확인 처리 금지 |
| 기기 | chargerId, channelId, 표기 출력·종류, 자료 출처·조회 시각, 화면 문구·세션과 대상 차량의 연결 근거 | 여러 노즐을 여러 면 또는 동시충전 채널로 자동 계산하지 않음; 동일 본체라도 다른 채널·이전 세션의 상태를 대상 차량에 적용하지 않음 |
| 운영 안내 관찰 | 고장/점검/사용 예정이라는 보이는 원문, 화면 미판독, 본체 미관찰, 사진 ID·영역 | 안내 문구=현재 실제 상태, 본체 미관찰=철거라는 변환 금지 |
| 실제 운영 확인 | 확인 자료가 있는 상태만 별도 보관, 기기·채널·자료 출처·유효시각·조회시각·연결 검증 | 자료가 없으면 미확인; 화면 꺼짐=고장, 온라인 누락=철거, 고장=지정 해제 금지 |
| 예외 후보 | 공유·겸용 안내 원문, 시간, 적용 면, 게시 주체, 자료 확인 여부 | 아파트·오피스텔·단독주택 구분은 외관만으로 확정하지 않음 |
| 시간·법규 | 시간별 사진·동일차량 관찰, 관할/규칙 버전/시행일/확인일 | 규칙 미확인일 때 기본 6개의 1분 기준을 이식하지 않음 |

기기의 크기나 실제 순간 출력으로 급속·완속을 정하지 않는다. 현행 고시는 최대 출력과 연결부 규격을 기준으로 하고 이동형·휴대용 충전기용 과금 콘센트도 다룬다. 화면에 7kW가 보이는 큰 급속기, 두 노즐 중 한 채널만 동작하는 기기는 모두 별도 관찰이 필요하다. [EV-R1]

지도는 충전소 후보·주소를 찾는 보조 자료다. 지상·지하 층수, 기기 ID, 상태시각이 제공되는 API 자료는 해당 필드를 활용해 사진과 대조한다. 필드가 제공된다는 사실과 해당 시설 레코드가 완전·최신이라는 사실은 별개다. 같은 평면 좌표라도 층·면별 재배치·업체 교체가 있을 수 있으므로 대상 기기와 목록의 완전성을 확인한다. 장소명·주소·충전소 ID 일치가 곧 촬영한 주차면의 지정 증명은 아니다. 지도/운영 API 미등록이나 오류도 구역 부정 근거로 사용하지 않는다.

웹과 iPhone에는 동일한 역할·용어·취소 동작을 적용한다. 보완 사진의 변경이 해당 사진에 연결된 관찰과 면 연결을 무효화하도록 설계하고, 늦게 도착한 과거 분석이 새 대상 차량·면 선택을 덮어쓰지 못하게 한다. 저장 성공 전에는 기존 원본·입력 내용·선택을 유지한다.

## 5. 현장 상황 시뮬레이션 및 검증 수준

[ev-scenarios.json](ev-scenarios.json)의 **40개 사례**는 **실제 사진이 아닌 가정된 장면을 이용한 설계 검토용 사례**다. 기대 관찰·추가 증거·금지 결론을 먼저 정해 과잉 확정 경로와 무한 재촬영을 점검한다. 이것만으로 모델의 실제 인식률이 검증되었다고 말하지 않는다. `referenceIds`는 법적 구분 또는 관련 안내의 근거이며, 각 가상 장면이 실제 발생했다거나 출처가 해당 기술 설계를 권고했다는 의미는 아니다.

각 `sceneFacts`는 `{source, text}`로 출처를 구분한다. 아래 분류는 작성자의 지식을 사진 판독 성공으로 잘못 계산하지 않기 위한 것이다.

| source | 의미 | 사용할 수 있는 기대결과 |
|---|---|---|
| `photo` | 가상 사진에서 보이는 내용·가림·미판독 | `photoOnly`, `withContext` |
| `capture_metadata` | 가정상 제공된 촬영 메타데이터 | `withContext`만 사용하고 사진 관찰과 분리 |
| `external_record` | 가정상 제공된 문서·지도·운영 목록 | `withContext`만 사용. 실제 확보한 자료로 표시하지 않고 대상 시설·기기·면·시점과의 연결을 검증 |
| `user_statement` | 사용자의 설명이 제공된 경우 | `withContext`만 사용. 사용자 진술을 검증된 시설 사실로 승격하지 않음 |
| `system_state` | 앱의 첨부·저장·요청·선택 상태 | `withContext`만 사용. 자료 미제공을 현실의 사실 부재로 해석하지 않음 |
| `evaluator_only` | 시나리오 작성자만 아는 숨은 설정 | 두 기대결과 모두에서 사용 금지. 판독 입력에도 전달하지 않음 |

`expectedObservation.photoOnly`는 `photo`만으로 관찰할 수 있는 내용을 적고, `withContext`는 사용 가능한 메타데이터·가상 문서·앱 상태 등의 출처를 유지한 결과를 적는다. 후자는 실제로 검증된 자료가 있다는 뜻이 아니다. 테스트를 만들 때 제목·함정·기대결과·금지 결론·숨은 설정을 판독 입력에 함께 넣지 않는다. 가상 문서의 세대수·준공일이나 작성자만 아는 차량 종류·재방문 사실을 사진 분석의 정답 근거로 사용할 수 없다.

다음은 작성한 사례를 제안 절차에 대입한 수동 논리 검토다. 실제 모델이나 사진을 입력한 실행시험과 구분한다.

| 대입 장면 | 최초 분석에서 멈춰야 하는 지점 | 다음 자료를 받았을 때 | 그래도 안 풀릴 때 |
|---|---|---|---|
| EV-02 바닥 전체 가림 | 표지는 보이나 적용 면 연결 미확인 | 같은 차량·기둥·12번 면 경계로 차량→면 관계만 갱신. 표지→면은 명시된 면 번호·화살표·범위 근거가 있어야 별도 갱신 | 표지 범위가 안 풀리면 사진에 함께 나온다는 이유로 연결하지 않고 미확인 저장 |
| EV-03 옆 빈 면만 충전 표시 | 옆12번과 대상13번을 별개로 유지 | 13번에 일반주차 안내가 보이면 반대 근거로 보존 | 충전기 근접성으로 결정하지 않음 |
| EV-12 화면 반사 | 케이블의 물리적 연결만 관찰, 실제 충전 상태 미확인 | 화면이 읽혀도 기기→채널→대상 차량→촬영 시각의 세션 연결을 대조한 뒤에만 해당 자료의 상태를 별도 기록 | 다른 채널·이전 세션을 제외할 수 없으면 화면 문구만 보존하고 충전 상태 미확인 |
| EV-16 고장 표시 | 충전 표시와 고장 안내 문구 관찰까지; 실제 고장은 미확인 | 관리 안내가 추가되면 문구·적용 면·기간을 기록하고, 실제 운영 상태는 별도 자료의 출처·유효시각으로 확인 | 실제 상태·법적 적용은 확인 필요로 남기며 사진을 반복 요구하지 않음 |
| EV-19 본체 미관찰 | 기초 흔적·충전 표시와 본체 미관찰만 기록 | 전체 사진으로 가림·프레임 범위를 검토하고, 실제 철거·이전은 해당 기기·시점에 연결된 자료로 별도 확인 | 본체를 못 봤다는 이유로 실제 부재나 지정 해제를 확정하지 않음 |
| EV-20 병행 허용 | 충전 표시와 일반차 허용 안내의 병존까지 | 정확한 면·기간은 사진으로 보완, 수량·권한은 자료로 확인 | 허용 안내를 지우거나 법적 면제를 확정하지 않음 |
| EV-27 자정 통과 | 두 시점 관찰과 미확인 차종까지 | 차종·기기·시설이 확인되면 해당 고시의 제외시간 규칙 검토 | 사진 간격을 연속 점유 사실로 승격하지 않음 |

이 검토에서 권장하는 방식은 **현재 사진→원본 부분 재분석→결론을 바꿀 수 있는 한 가지 부족 정보 요청→미확인 저장**이다. 한 번에 다섯 장을 요구하는 방식은 EV-01에서 불필요한 촬영을 만들고, 사진 한 장의 단일 결론만 받는 방식은 EV-02·03·16에서 잘못 확정하기 쉽다. 보완 자료가 이미 충분하거나 사진으로 해결할 수 없는 상태라면 요청을 종료한다. 이는 촬영 부담과 잘못된 확정을 함께 줄이려는 설계 선택이며, 최적성이 실측으로 입증됐다는 뜻은 아니다.

특히 다음 실패를 분리한다.

- 바닥이 차에 완전히 가려짐: 표지가 읽혀도 동일 면 연결이 없으면 구역 후보까지만 인정.
- 옆 빈 충전면이 잘 보임: 그 면을 대상 차량의 면으로 복제하지 않음.
- 공용 벽표지와 복수 면: 화살표·면 번호·경계를 확인하며 케이블 도달 범위로 추정하지 않음.
- 케이블이 반대쪽 차에 연결됨: 충전기 존재와 대상 차량 충전 상태를 별개로 유지.
- 동일 충전기 화면의 다른 채널·이전 세션: 화면 문구를 읽어도 대상 차량과 시각 연결이 없으면 상태를 적용하지 않음.
- 미개통·고장·철거 흔적·임시시설: 운영 상태와 지정 유효성을 분리하고 관할 자료 경로를 둠.
- 차량 외양·푸른 번호판·하이브리드 로고: 차량 자격 확정에 사용하지 않음.
- 같은 차량이 재방문: 두 사진 간격을 연속 점유로 단정하지 않음.
- 공유 허용 표지와 법령 충돌: 원문·시각·범위를 보존하고 미확인 사유를 표시.

후속 실사진 검증은 사용 권한이 있는 자료에서 차량·면·표지·기기 연결을 사람이 주석하고, 장소 단위로 개선용/시험용을 분리한다. 야간·반사·눈·차량 가림·실내 층별·외형 유사 사례를 각각 평가한다. 구역 종류 정확도만이 아니라 **잘못된 면 연결률, 과잉 확정률, 필요한 보완 촬영을 찾은 비율, 충분한 사진에 불필요한 재촬영을 요구한 비율, 미확인 처리율**을 함께 본다. 실제 표본·실모델 시험은 아직 수행하지 않았다.

## 6. 현재 구현과의 차이

확인한 GitHub 기준 `src/types/report.ts`의 유형은 기본6개다. `api/vision.ts`도 기본6개 관찰과 단일 유형을 반환하며 충전구역·기기·면 연결 필드는 없다. 따라서 선택 항목 하나만 추가해서 해결할 수 없다.

iPhone `dedicatedGuides.json`에는 충전기·표시와 대상 차량 위치 확인, 케이블 미관찰만으로 충전방해 단정 금지, 차종·기기종류·시간·관할 기준 확인 안내가 이미 있다. 이는 촬영 안내 자료이며 이번에 제안한 AI 근거 연결이나 공식 지정 확인 구현의 증거는 아니다. 기존 안내의 의미를 보존하며 관찰 결과·자료 확인 경로를 확장해야 한다.

## 8. 미확인·후속 과제

1. 모든 예외를 빠짐없이 인식한다고 보증할 수 없다. 신규 표지·지자체 해석·임시 운영 변경은 생길 수 있다. **기존 분류로 설명되지 않는 표시/충돌을 버리지 않고 미확인으로 남기는 경로**가 필요하다.
2. 전국에 통용되는 최신 충전방해 단속 지침 원문 전체는 이번 조사에서 확보하지 못했다. 현행 법령·고시·별표·법제처 해석과 확인 가능한 지역 안내까지만 근거로 쓴다. 검색에 걸린 비공식 재게시 해설집은 최종 규칙 근거로 채택하지 않았다.
3. 고장·미개통·철거·운영중단에 따른 개별 구역의 지정 효력, 비의무 임의설치·사유주택·이동형 임시충전의 단속 범위는 사진만으로 해결하지 않는다. 해당 구역에 적용되는 자료와 관할 확인이 없으면 법적 점검 미완료다.
4. 공식 충전기 API를 실제로 연동하거나, 차량등록·관리주체 문서를 열람하거나, 민원을 제출하지 않았다. 이런 자료가 자동으로 확보되는 것으로 화면을 설계하지 않는다.
5. 현행 차량 분류·출력·단속 시간·시설예외는 촬영 시점에 유효한 버전으로 적용해야 한다. 출시 때 최신 조문·고시·관할 최종 운영 공고를 재검증해야 한다.
6. 기록·계획과 논리 시나리오 검토만 완료한 상태다. 웹/iPhone 구현·빌드·실행·실기기·실제 AI 판독 정확도는 모두 이번 조사에서 미검증이다.
