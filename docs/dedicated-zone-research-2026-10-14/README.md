# 전용구역 3개 — 공식 조사·촬영 상황 검토·단계별 협의

> **현재 구현 기록 — 2026-10-15:** 사용자 “개선방안을 적용해서 푸시해.”와 후속 “ㄱㄱ”에 따라 웹·iPhone 구현과 검증·push 작업을 진행한다. 최신 범위·차이·검증·원격 상태는 [구현·검증 기록](../citizen-capture-implementation-2026-10-15.md)을 기준으로 확인한다. 아래의 승인 이력과 “구현 대기/미확정/푸시 직전” 표시는 각 논의 당시의 역사 기록이며 이후 포괄 실행 지시와 구분한다. 당시 법령 조사·가상 사례를 실제 사진 AI 검증 결과로 바꾸지 않는다.

최종 협의 기록일: **2026-10-15**. 현재 단계: **전용구역 3개 계획 확정 완료·웹/iPhone 구현 대기**. 친환경차 안의 수락 원문은 2026-10-15 “다음 진행”이며, 직전 병행주차 보완 포함 안을 수락한 뜻으로 해석한다고 사용자에게 명시했다. 다음은 상위 계획의 미확정 교차로 모퉁이 안이다. 선행 조사 기준일은 각 문서에 별도로 유지한다.

## 사용자 요청과 진행 범위

장애인전용주차구역·소방차전용구역·친환경차 충전구역을 각각 하나씩 개선하고, 차가 서 있는 여러 촬영 상황에서 실제 해당 구역인지 어떻게 확인할지 검토한다. 구역별 특징과 예외를 깊게 조사한다는 요청이다.

이 요청에 따라 종전 기본 6개 자동 판독 우선·전용구역 수동 선택/기록 우선의 **미확정 범위안은 재협의**한다. 세 유형 모두 사진 판독 개선 설계 대상으로 삼는다. 사용자가 유형별로 확정한 다음 항목으로 넘어가고, 전체 계획 확정 후 웹/iPhone 구현·검증·푸시 직전 상태를 준비하는 기존 절차는 유지한다. 조사 착수와 세부안 확정은 다르다.

## 시뮬레이션의 의미와 범위

이번 시뮬레이션은 **가상의 촬영 장면에 관찰 사실을 부여하고, 어떤 오판이 가능하며 무엇을 더 확인해야 하는지 단계별로 검토한 문서 기반 시나리오 검토**다. 실제 사진을 촬영·생성하거나 AI API로 판독한 실험이 아니다. 성공률·정확도·모든 예외 해결 수치를 산출하지 않는다.

각 JSON 항목은 독립적으로 검토 가능한 ID와 다음 정보를 갖는다.

- `sceneFacts`: 각 항목에 `source`와 `text`를 둔다. 사진 관찰·촬영 메타데이터·외부 자료·사용자 진술·시스템 상태·평가자만 아는 설정을 구분한다. 사진 모델에 목록 전체를 전달하지 않는다.
- `trap`: 단순 분류에서 생길 수 있는 오인.
- `expectedObservation`: `photoOnly`는 사진만으로 가능한 결과, `withContext`는 제공된 별도 정보까지 사용한 결과다. 두 단계 모두 평가자만 아는 설정은 사용할 수 없다.
- `requiredNextEvidence`: 원본 재확인, 추가 구도, 자료 확인 등 필요한 다음 행동. 모든 항목을 항상 추가 촬영하라는 뜻이 아니다.
- `forbiddenConclusions`: 주어진 근거로 해서는 안 되는 결론.
- `referenceIds`: 공식 자료 또는 설계 근거의 참조 ID. 정확한 출처·시행일·확인 한계는 각 연구 문서에 둔다.

기대 결과는 설계자가 작성한 기준이며, 모델 출력이 아니다. JSON 문법·참조 검사를 통과한 사실도 실제 인식 성공으로 보고하지 않는다. 향후 실제 평가 때는 이 기대 결과를 모델에 미리 알려주거나 같은 원본의 자른 이미지를 독립 표본으로 세지 않는다.

2026-10-14 독립 재검토에서 출차·사선 공간의 용도·시설 분류·인허가 시점·세대수 등 사진 밖의 사실이 사진 입력에 섞일 위험을 발견해 위 구조로 바꾸었다. 사례 제목·함정도 정답을 암시할 수 있어 모델 입력에서 제외한다. 표지와 차량이 함께 보이는 것만으로 적용 면이 확인되는 문제, 반사 중복의 과잉 확정, 다른 충전 채널/시점의 화면 연결도 보완했다. 구체 사례는 입력 분리 문서에 남긴다.

현재 JSON 사례는 총 118개이며 유형별로 실제 표시 가림, 옆 면 혼동, 다른 표시, 경계·통로, 오래되거나 상충하는 표시, 법적 적용, 차량 자격, 시간·사진 연결, 시스템 실패를 나누었다. 이는 118장의 사진 또는 118회의 모델 실행을 뜻하지 않는다. 2026-10-15 추가한 병행주차 사례 10개는 EV 안 본문 표로 별도 관리하며 기존 JSON 개수에는 포함하지 않는다.

## 검토한 공통 오판 경로

| 바꾸어 본 조건 | 막아야 하는 오판 | 제안하는 처리 |
| --- | --- | --- |
| 차량·눈·기둥이 표시를 일부/전체 가림 | 안 보임을 없음으로 처리, 가린 글자 복원 | 원본의 다른 부분과 기존 사진 검토 후 부족한 구도만 안내 |
| 옆 칸·여러 칸 공용 표지 | 표지 발견만으로 대상 차와 자동 연결 | 표지→면/구역→대상 차량 연결을 개별 확인 |
| 다른 층·반복되는 면 번호·차량 이동 | 주소·GPS·차량 일치만으로 같은 구역 연결 | 고정 위치 단서·시각·상충 기록. 연결 불명은 보류 |
| 색·기호가 비슷한 다른 표시 | 색이나 한 단어로 유형 확정 | 표시 목적·문구·설치 맥락과 대안 구분 |
| 구형·퇴색·임시·겹친 표시 | 현재 표준과 다르면 무효, 새 표지처럼 보이면 유효 | 현장 관찰과 설치·운영 자료의 확인 상태 분리 |
| 경계·옆 통로·진입로 | 면 안/밖 둘로 합쳐 방해 놓침 또는 과잉 판단 | 내부·경계·인접 공간·진입 관계를 별도 관찰 |
| 차량 자격·허가 시점·운영 시간 미확인 | 사진으로 법적 조건까지 확인한 척함 | 자료 확인 항목으로 남기고 재촬영 반복 방지 |
| 통신 실패·대상 변경·기존 초안 | 오류를 유형 없음으로 변환, 옛 응답으로 덮어쓰기 | 공통 보존·입력 버전·실패/취소/이어하기 적용 |

각 구역의 법적 조건은 서로 교환하지 않는다. 예를 들어 소방차의 인접 주차 예외를 장애인 구역에 적용하거나 충전구역의 시간조건을 다른 유형에 복사하지 않는다. 법령·행정안내·지역 접수 기준·사진 관찰·사용자 응답도 서로 다른 출처로 기록한다.

## 기술 제안의 공통 골격

전체 장면 → 필요한 원본 부분 → 표시 식별 → 대상 면/구역 연결 → 차량 관계 → 부족 사유별 보완 순서다. 법적 설치·운영·차량 자격·시간 조건은 각각 확인 상태와 출처를 갖는다. 이미 충분한 사진에서는 추가 촬영을 요구하지 않고, 사진으로 해결할 수 없는 문제는 자료 확인으로 넘긴다.

사진과 AI 결과에는 원본 ID·영역·대상·입력 버전을 연결한다. 동일 사진의 부분 분석을 새로운 촬영으로 세지 않는다. 사람이 용도/유형을 고른 사실을 자동 인식 성공으로 승격하지 않는다. 사용자 사진·주소·본문은 새로운 저장이 완료되기 전까지 보존한다.
