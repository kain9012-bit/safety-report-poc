# 소방차전용구역 사진 근거·보완 촬영 연구 초안

확인일: **2026-10-14, 한국 시각**. 상태: **소방차전용구역 확정안의 조사 근거·기능 구현 전**. 이 연구에 기반한 세부안은 2026-10-15 사용자 “확정했어”로 확정 완료·웹/iPhone 구현 대기로 전환했다. 2026-10-14 장애인 안 확정 후 [단계별 개선안](fire-plan.md) 협의를 시작했다. 장애인전용주차구역부터 순서대로 협의하는 전체 과정의 두 번째 전용구역 준비 자료다. 이 문서를 작성한 것으로 사용자 승인, 웹/iPhone 구현, 실기기 촬영 또는 AI 인식 정확도 검증을 완료한 것이 아니다.

핵심 제안은 **사진에 표시된 장소의 종류 → 표시가 적용되는 실제 바닥 범위 → 대상 차량과 그 범위·진입로의 관계 → 법 적용 및 신고 접수 조건**을 분리하는 것이다. 소방차 표시가 보이고 그 안에 차량이 있는 사진도 건축허가 신청 시점·법적 설치 근거·처분 가능성을 단독으로 증명하지 못한다. 반대로 표시 전체가 차에 가려졌다는 사실도 전용구역이 없다는 증거가 아니다.

## 1. 현재 코드와 개선 출발점

- GitHub 기준 `src/types/report.ts`의 유형은 기본 6개이며, `api/vision.ts`에는 소화전 근접(`fireHydrantNear`)만 있다. 소방차전용구역의 표시·점유·진입 방해를 구조화해 반환하는 필드는 없다. 소화전 판독 결과를 새 유형의 근거로 재사용하면 안 된다.
- 별도 기존 웹 및 iPhone의 `dedicatedGuides.json`에는 `fire_access` 안내가 있다. 전용구역과 통행로·소화전을 구분하라는 설명은 유지할 가치가 있다. 다만 모든 경우에 전용구획 전체·번호판·글씨를 한 장에 넣도록 요구하면 큰 구역과 점유 차량 때문에 불필요한 촬영이 생긴다. 연결 가능한 전체 사진과 필요한 상세 사진으로 개선한다.
- 기존 안내의 ‘건축허가·사업계획 승인 시점’은 구현 때 **각 신청 시점**으로 정밀하게 구분해야 한다. 준공·사용승인·입주 연도와 대체할 수 없다. [FR5]
- 이번 조사에서는 기능 코드·메인 협의 문서를 수정하지 않았다. 관련 파일은 읽기만 했다.

## 2. 공식 근거에서 확인한 사항

### 설치 대상과 시기

현행 시행령은 100세대 이상 아파트와 3층 이상 기숙사를 설치 대상으로 정한다. 단, 하나의 대지에 하나의 동이며, 주정차 금지인 편도 2차선 이상 도로에 직접 접하고 그 도로에서 직접 소방활동이 가능한 공동주택은 제외한다. 따라서 아파트 외관·층수·지도상 도로 폭 하나로 적용 여부를 판정할 수 없다. [FR2]

각 동 앞 또는 뒤에 설치하는 것이 원칙이지만, 하나의 구역으로 여러 동에서 활동할 수 있고 정해진 조건에 해당하면 동마다 별도로 설치하지 않을 수 있다. 사진의 구역에 가장 가까운 동 번호만 자동으로 연결하면 안 된다. 이번 조사에서는 이 예외의 세부 고시 적용까지 확인하지 않았으므로 실제 공동 사용 관계는 도면·관할 확인으로 남긴다. [FR3]

2018-08-10 시행 개정법의 적용례는 **시행 후 최초로 주택건설사업계획 승인 또는 건축허가를 신청하는 경우**다. 법제처 22-0799(2022-12-19)는 시행 전 신청·시행 후 승인의 사례에 해당 개정규정을 적용하지 않는다고 해석했다. ‘최근 지어진 건물’, ‘2019년 입주’, ‘2020년 도색’은 이를 대체하지 못한다. [FR5]

기존 건물의 소방 목적 공간이나 자발적으로 그려 둔 표시도 사진 근거로 보존한다. 위 적용례만으로 모든 다른 법적 조치까지 없다고 안내하거나 주차 허용으로 바꾸지 않는다. 증축·재건축·변경허가 등 경계 사례, 실제 지정·관리 상태는 본 조사로 포괄 판단하지 않았다.

### 표준 표시 형식

시행령 제7조의13은 별표 2의5로 설치 방법을 정한다. 해당 공식 PDF의 도면과 비고를 직접 열어 확인했다. 외곽 치수는 12,000×6,000mm이고 빗금 테두리 안에 주차금지 기호, ‘소방차 전용’ 문구, 119가 배치된다. 빗금 두께와 간격은 각각 30cm·50cm이며 황색을 기본으로 하고 P와 문구는 백색으로 표시한다. [FR3, FR4]

인식에서는 이를 **서로 보강하는 표지 단서**로 이용한다. 사진 속 픽셀 길이로 12m·6m를 실측했다고 주장하거나, 비율이 다르다는 이유만으로 즉시 제외하지 않는다. 원근, 점유 차량, 퇴색, 다른 설치 지침, 변경 흔적 때문에 일부만 보일 수 있다. ‘119’만 인식되거나 노란 빗금만 보이는 경우는 소방차전용구역 확인으로 승격하지 않는다.

### 차량이 구역 밖에 있는 경우의 중요한 예외

시행령 제7조의14는 내부 주차·적치 외에도 전후·양옆의 주차·적치, 진입로 차단, 표지 훼손, 기타 진입·주차 방해를 구분한다. **전후·양옆 주차 규정에는 주차장법 제19조 부설주차장의 주차구획 내 주차를 제외하는 단서가 있다.** [FR6]

따라서 ‘전용구역 옆에 차량이 있다’는 관찰을 바로 ‘방해’로 바꾸지 않는다. 이 단서는 인접 주차에 관한 해당 호의 예외이며, 실제 내부 침범이나 별도로 성립할 진입 방해까지 전부 허용한다는 뜻으로 확장하지도 않는다. 주차선이 그려졌다는 사실과 법정 부설주차장 구획이라는 사실 역시 구분한다.

### 사진 접수 조건은 별도 자료로 관리

태백소방서의 2022-06-08 안내는 차량번호·위반 구역 식별, 같은 배경 위치·방향, 5분 간격 사진 2장 이상을 설명한다. 인제소방서 2022-05-16 안내도 5분을 사용한다. 이는 확인한 지역·게시일의 안내다. 앱에서 법률 자체가 전국 모든 상황에 5분을 일괄 규정한다고 표시하거나, 5분 미만이면 합법이라고 바꾸지 않는다. 실제 적용 관할·시점의 최신 접수 기준 확인이 필요하다. [FR7, FR8]

## 3. 비슷한 표시를 구분하는 사진 관찰 설계

| 보이는 것 | 사진에서 기록할 사실 | 다음 확인·금지할 추론 |
|---|---|---|
| 소방차 전용 문구와 연결된 빗금 테두리 | 문구·테두리·대상 바닥 범위 | 법적 지정·시기는 별도 미확인 |
| 소방활동공간·소방차 활동공간 | 읽힌 정확한 문구와 연결 범위 | 법정 전용구역과 이름이 같다고 취급하지 않음 |
| 소방차 진입로·소방도로·진입금지 안내 | 통로의 방향과 실제 연결 | 독립 전용구획으로 바꾸지 않음; 연결된 전용구역 확인 |
| 소화전·송수구 주변, 붉은 바닥 | 시설 종류와 차량 관계 | 소방차전용구역 결과와 분리; 소화전 유형 근거는 별도 |
| 노란 격자·빗금·주차금지 기호만 보임 | 문자 미확인 또는 가림 여부 | 안전지대·통로·주차금지 공간 등 대안 보존 |
| 119 숫자만 보임 | 숫자 위치·원본 영역 | 차량 도장·광고·장비 표기일 수 있어 바닥 표지와 분리 |
| 이동식 ‘소방차 전용’ 표지·콘 | 임시 물체의 위치와 문구 | 고정 구획 경계·현행 지정의 증명으로 사용하지 않음 |
| 예전 황색선과 새 주차선이 겹침 | 두 표시와 충돌·퇴색 흔적 | 어느 것이 유효한지 색 선명도만으로 정하지 않음 |
| 공장·상가·학교 등에 소방 관련 표시 | 현장 표지 자체는 그대로 기록 | 공동주택 설치대상 규정을 그대로 대입하지 않음 |

소방 관련 활동공간이라는 표현은 더 넓은 현장 맥락에 쓰일 수 있다. 2010년 속초소방서 게시에는 현재 별표와 다른 황색 실선·점선의 권장 표시 사례도 있다. 이 자료는 **구형 표시가 존재했다는 역사적 사례**로만 쓴다. 그 문서의 당시 처분·규격 설명을 현행 공통 기준으로 사용하지 않는다. [FR9]

## 4. 권장 판독 단계와 최소 보완 촬영

1. **대상 차량을 정한다.** 차량이 여러 대면 사용자가 지목할 수 있게 한다. 선택은 OCR 또는 동일 차량 검증 성공으로 취급하지 않는다. 번호판 판독은 표지 판독과 별도로 수행한다.
2. **원본 전체에서 후보 표시와 구획을 찾는다.** ‘소방차’, ‘전용’, 119, P 금지 기호, 외곽 빗금, 입구 표지 등 각각 보인/안 보인/가린/읽기 어려운 상태와 원본 영역을 기록한다. 차가 가린 글자를 생성하거나 OCR의 문맥 보정 결과를 관측 사실로 저장하지 않는다.
3. **후보 영역만 원본 해상도로 재분석한다.** 가까운 표지와 바닥 문구를 각각 잘라 보되 원본 좌표·사진 ID로 되돌아갈 수 있게 한다. 표지 문구만 잘 나온 별도 사진은 해당 면을 구별하는 고정 특징과 사진 사이 연결·모순을 확인해야 대상 차의 사진 근거로 이용한다. 같은 차량이나 반복되는 도색 모양만으로 같은 구획임을 확정하지 않는다. 사용자의 위치 정정은 진술, 배치 도면은 외부 자료로 구분하며 그 자체로 사진 연결 확인을 대신하지 않는다. 다른 구획임이 확인되면 연결을 거절한다.
4. **실제 바닥 경계와 차량 관계를 분류한다.** 내부 점유로 보임, 경계에 걸쳐 보임, 인접 면에 있음, 진입 경로를 가리는 것으로 보임, 관계 미확인으로 나눈다. 사각형 검출 상자끼리 겹친 정도로 지상 점유나 소방차 통행 가능 폭을 확정하지 않는다. 차량 바퀴뿐 아니라 차체 돌출도 관찰하되, 2D 그림자·원근·가려진 경계는 미확인으로 둔다.
5. **추가 사진으로 해결되는 결손만 안내한다.** 기존 기본 사진에서 해결되면 촬영을 끝낸다. 읽기 어려운 문구에는 상세 사진, 바닥 연결이 불명확하면 차량·남은 문구·한쪽 구획 경계가 함께 보이는 보완 사진, 진입 방해 의심이면 현재 차량·관찰 가능한 통로·구획 연결 중 부족한 부분만 보완한다. 전구역 전체나 단지 전체의 진입·우회 경로를 촬영하도록 요구하지 않는다. 전체 경로와 실제 통행 가능성은 미확인으로 남기거나 별도 배치·현장 자료 확인으로 구분한다.
6. **법·행정 자료 결손을 분리한다.** 표시와 차량 관계가 충분하면 사진은 충분한 것으로 표시한다. 세대수·용도·신청일·인접 주차구획의 법적 지위·변경 지정 같은 문제는 재촬영으로 해결되지 않는다. 주소·동·구역 위치로 확보 가능한 공공 또는 관리 자료를 대조하고, 자료가 없으면 담당 기관 확인 필요로 남긴다. 민원인이 인허가 서류를 직접 찾아 제출해야만 저장할 수 있도록 만들지 않는다.

이 순서는 사용자 추가 행동을 최소화하는 **권장 초안**이다. 비용·지연·정확도 데이터를 측정하기 전에는 수학적으로 최적이라거나 모든 예외를 해결했다고 주장할 수 없다.

| 결손 | 첫 대응 | 필요한 경우의 안내 |
|---|---|---|
| 차량 밑 글씨가 대부분 가림 | 원본 남은 글자·테두리 및 다른 기본 사진 확인 | “차량과 보이는 소방차 표시, 구역 테두리가 함께 보이게 찍어 주세요.” |
| 글씨는 읽었지만 다른 면의 표지일 가능성 | 구획별 연결·경계 연속성 확인 | “표시에서 차량이 있는 자리까지 이어지는 바닥을 함께 보여 주세요.” |
| 경계선과 차량 끝이 겹치는지 불명확 | 원본 경계와 접지 관계 확인 | 안전한 기존 위치에서 관계가 보이는 다른 각도의 보완 사진 |
| 차량이 밖에서 입구를 막는 듯함 | 구획과 연결 통로 존재 확인 | “차량과 그 뒤의 진입 통로, 전용구역이 연결되어 보이게 찍어 주세요.” |
| 주변 차량이 일반 주차선 안에 있음 | 인접 구획·경계 침범 여부를 별도 기록 | 사진 추가보다 주차구획 성격 확인이 먼저일 수 있음 |
| 건물 신청일·지정 상태 미확인 | 주소·자료 출처 대조 | 추가 촬영 요구 없음 |
| 네트워크·분석 실패 | 저장한 원본으로 재시도 | 재촬영 요구 없음 |

젖은 노면에서 글씨 모양이 겹쳐 보이면 먼저 반사 의심·판독 품질 저하로 기록한다. 동일 표시의 반사임을 보이는 근거로 확인한 경우에만 중복을 합친다. 실제 표시와 반사를 구분하지 못하면 확정적으로 합치거나 별개 구역으로 늘리지 않고 연결 미확인으로 남긴다.

사용자가 차량을 옮기거나 물체를 치우도록 요구하지 않는다. 도로 진입, 차량 아래 촬영, 높은 곳에 올라서기, 진입 동선 방해를 전제로 한 지시를 만들지 않는다. 촬영이 불가능하면 ‘가려져 확인 어려움’으로 저장한다. 보완 사진은 기본 시간 비교 사진을 대체하지 않고, 시간 간격을 초기화하지 않는다.

## 5. 데이터·실패 처리 초안

다음은 제안 필드이며 실제 스키마를 구현하지 않았다.

- `zoneObservation`: 읽힌 원문, 문구 위치, 표준 표시 요소별 관측, 가림·퇴색·충돌 사유, 바닥 구획 ID, 가시 경계·불확실 경계 구분.
- `vehicleZoneRelation`: 대상 차량 ID, 내부/경계/인접/진입로/미확인, 근거 사진과 영역, 인접 주차구획 관측, 지상 관계 불확실성.
- `facilityApplicability`: 주소·동·실제 구역 식별, 공동주택 용도·규모, 최초 관련 신청일, 설치대상 예외·다동 공용·변경 상태, 자료 출처·유효일·확인일. 값은 확인/미확인/자료 충돌로 구분한다.
- `intakeRequirements`: 관할·유형·시행 기간이 명시된 출처에 따른 사진 수·간격·촬영 방식·마감. 미확인일 때 기본 6개의 조건을 대신 채우지 않는다.
- `evidenceLinks`: 전체·상세·보완 각 사진의 원본 ID, 해당 구역 및 차량과 연결한 이유와 확인 상태. 사진에서 확인한 연결, 사용자 진술, 외부 자료상 연결을 분리한다. 사진 두 장이 같은 초안에 있다는 이유만으로 같은 장소·차량으로 확정하지 않는다.

`photoEvidence=adequate`와 `legalApplicability=unknown`이 함께 존재할 수 있어야 한다. 사진 결손, 행정 자료 결손, 시스템 오류를 한 ‘불충분’ 상태로 합치지 않는다. 차량·구획 선택 변경 시 이전 분석의 연결과 보완 요구를 재검토하고 늦게 도착한 결과로 새 선택을 덮어쓰지 않는다. 사진·주소·사용자가 고친 내용은 새 저장이 성공하기 전까지 보존한다. 지도/GPS는 주소·단지 후보를 좁히는 보조 자료이며, 실내·고층·지하의 층과 구획을 자동 확정하지 않는다.

웹과 SwiftUI/AVFoundation iPhone은 같은 관측 의미와 실패·취소 흐름을 사용한다. 기존 iPhone 수동 전용구역 안내는 유지하되 새 AI 분석을 이미 제공한다고 표시하지 않는다. 최종 법 위반 판정·실제 제출·처분은 시제품의 완료 상태가 아니다.

## 6. 상황 시뮬레이션과 검증 범위

[fire-scenarios.json](fire-scenarios.json)은 **32개의 가상 상황을 구성해 기대 관찰·추가 근거·금지 결론을 도출한 문서 기반 시뮬레이션**이다. 실제 차량 사진이나 AI API에 넣어 얻은 결과가 아니며, 모델 정확도 수치를 뜻하지 않는다. 일부 사실을 알고 있는 평가자와 사진만 볼 수 있는 AI를 구분해 가려진 정보 누출을 방지한다.

각 사례의 `sceneFacts`는 `{source, text}` 객체 배열이며 다음 출처만 사용한다. 이 배열의 `photo`도 현재는 가상 사진의 가시 조건을 기술한 입력이지 실제 사진에서 측정한 관찰 결과가 아니다.

| source | 의미·사용 범위 |
|---|---|
| `photo` | 가상 사진에 보이거나 읽힌다고 설정한 조건. 가려진 글자·화면 밖 구역·법적 지정·사진만으로 알 수 없는 연대는 넣지 않는다. |
| `capture_metadata` | 제공된 것으로 설정한 촬영 시각·목록 등. 메타데이터 존재를 촬영 내용의 진위나 계속 주차의 증명으로 바꾸지 않는다. |
| `external_record` | 시뮬레이션에서 제공된다고 가정한 도면·행정 문서 등. FIRE-19·25의 문서는 실제 확보·진위 검증한 자료가 아니며 그 사실을 해당 항목에도 명시한다. |
| `user_statement` | 사용자가 제공한 대상 선택·위치 정정 등. 사진 판독이나 같은 구획 연결 확인으로 승격하지 않는다. |
| `system_state` | 자료 제공 여부, 요청 버전·응답 순서 같은 가정 시스템 상태. 현장 사실의 사진상 관측이 아니다. |
| `evaluator_only` | 가려진 실제 문구, 다른 구역·차량이라는 정답, 도색 순서 등 평가자만 아는 설정. 두 평가 모드 모두 모델 입력과 기대 관찰의 근거에서 제외한다. |

`expectedObservation`은 `{photoOnly, withContext}`로 나뉜다. `photoOnly`는 `photo` 사실만으로 가능한 관찰을 쓴다. `withContext`는 사진 외에 실제 해당 가상 입력에서 제공된 `capture_metadata`·`external_record`·`user_statement`·`system_state`를 출처별로 구분해 이용한다. 문서가 제공되지 않은 사례에서 다른 사례의 가정 문서나 평가자 지식을 가져오지 않는다. 맥락을 제공해도 사진상 미확인 상태가 자동으로 확인 상태가 되는 것은 아니다.

**평가 입력 분리 규칙:** `title`, `trap`, `expectedObservation`과 `evaluator_only` 사실은 모델에 입력하지 않는다. `requiredNextEvidence`, `forbiddenConclusions`, `referenceIds`도 사례별 정답·판정 지침이므로 모델용 사례 입력에 넣지 않고 평가에만 사용한다. 사진 전용 모드는 `source=photo`만, 맥락 포함 모드는 허용된 출처 중 `evaluator_only`를 제외한 사실만 전달하도록 구성해야 한다. 사례 제목처럼 정답을 노출할 수 있는 식별 설명을 프롬프트에 붙이지 않는다. 실제 사진 평가에서는 사진 원본과 허용된 맥락을 사용하고, 여기 적힌 가상 사진 설명을 실제 인식 성공의 대체 증거로 쓰지 않는다.

이번 수정에서 구조·출처 허용값·필드 형식·참조를 검사하고 기대 관찰을 문서 검토했다. 분리 규칙을 구현한 실제 모델 평가 하네스나 사진 판독을 실행한 것은 아니다.

범위: 전체·부분·완전 가림, 이웃 구획, 외부 표지, 표준/구형/사설/훼손/겹친 표시, 황색 격자·소화전 혼동, 내부 점유·인접 정상 구획·진입 경로·차체 돌출·적치물, 원근·다중 차량·반사·야간·눈, 허가 신청과 준공 차이, 설치 제외·다동 공유·비공동주택, 시간차 사진·타 구획 연결·통신 실패, 소방 차량으로 보이는 경우를 포함한다.

실제 평가에서 측정할 항목은 구역 식별의 오탐/미탐, 다른 차량·다른 구획에 근거를 잘못 연결한 비율, 가림 상태를 미확인으로 남기는 비율, 법적 사실을 사진만으로 확정한 건수, 추가 촬영으로 결손이 해결된 비율과 불필요 촬영 횟수다. 장면별 관측 정답과 법·행정 자료 정답을 따로 만든다. 다양한 실제 사진의 이용 권한을 확보한 뒤 별도 평가셋을 구성해야 한다. 가상 논리 검증 통과로 현장 판독 성능을 보증하지 않는다.

## 8. 남은 확인과 후속 협의 포인트

- 전국 전용구역의 현행 위치·경계·설치 근거·신청일을 함께 제공하는 공공 API는 확인하지 못했다. 있다면 출처·갱신일·실제 구역 ID를 검증한 뒤 연결한다. 지도 POI만으로 행정 확인 완료를 만들지 않는다.
- 2026년 전국 신고 접수 조건, 관할별 처리 차이, 설치대상 예외의 실제 적용, 증축·변경허가·자발 설치·재지정·폐지 사례, 비공동주택의 다른 법적 근거는 추가 확인이 필요하다.
- 기존 구형 표시의 인정 여부·표지 훼손자의 행위·차체가 일부 돌출한 경우의 구체적인 법적 판단은 사진 모델로 확정할 사안이 아니다. ‘표지가 훼손되어 보임’과 ‘누가 훼손했는지’를 분리한다.
- 사용자가 협의할 핵심 선택은 **사진상 구역과 점유·방해 근거를 적극 확인하되 행정 자료 미확인을 분리하고, 내부/인접/진입로를 구별하며, 필요한 사진만 보완하는 흐름**이다. 권한 확인이나 인허가 서류 확보를 현장 촬영의 필수 선행 단계로 만들지 않는 것을 권장한다.
