# 사진 상세 분석 API 배포본 — 2026-10-15

## 목적과 범위

설치된 iPhone 앱이 요청하는 소화전 상세 관찰과 원본 부분 확대 분석을 서버에서도 처리한다. 웹 화면과 신고 준비 순서는 바꾸지 않는다. 실제 신고 제출 기능은 아니다.

현재 `main`에는 해결되지 않은 병합 충돌 표시가 있고 최근 Vercel 운영 배포가 실패했다. 따라서 이 배포 브랜치는 GitHub에서 마지막으로 성공한 운영 배포로 확인한 `a55da6ae7fa08f35e7ca05e860841b3375862122`에서 만들었다. `main`과 팀원의 변경은 수정하지 않았다.

- 저장소: `kain9012-bit/safety-report-poc`
- 배포 브랜치: `codex/vision-api-production-20261015`
- 변경 파일: `api/vision.ts`, `server/`의 분석 모듈과 테스트, 이 문서
- `src/`, `public/`, `index.html`, `eval.html`, `vite.config.ts`, `vercel.json`: 기준 커밋과 동일
- iPhone 앱 화면·촬영 순서·저장 자료: 이 배포에서 변경하지 않음

## 기술적 변경

1. 사진 ID와 입력 버전을 보내는 개선된 웹·iPhone 요청을 상세 분석 v2로 연결한다. 기존 운영 웹의 요청과 응답 형식은 유지한다.
2. v2는 소화전의 정체, 글자·표지, 차량과의 관계, 불명확한 이유를 각각 반환한다. 사진 ID와 입력 버전을 결과에 연결한다.
3. 앱이 보낸 원본 부분 확대 사진을 전체 장면과 함께 분석한다. 확대본은 별개의 촬영 증거로 세지 않는다. 확대본만으로 차량과의 관계를 확정하지 않는다.
4. AI가 필수 상세 배열을 빠뜨리면 오류로 처리한다. 자료가 없는 것을 정상적인 상세 분석 결과로 꾸미지 않는다. 실제로 빈 배열을 반환한 경우와 구분한다.
5. 사진 판독으로 법적 거리나 위반을 확정하지 않는다. 식별되지 않은 작은 물체는 미확인으로 남길 수 있다.
6. `GET /api/vision`으로 배포 버전을 확인할 수 있다. API 키·사진을 반환하거나 AI 분석을 호출하지 않는다.

기존 운영 웹은 기존 응답 형식을 계속 사용한다. 이번 배포만으로 운영 웹에 새 상세 표시 UI가 추가되는 것은 아니다. 현재 개선된 웹 클라이언트와 설치된 iPhone 앱은 사진 ID를 보내므로 v2 경로를 사용한다.

## Vercel 관리자 적용 순서

1. 이 브랜치의 Vercel Preview 배포가 Ready인지 확인한다. `main`의 실패한 배포와 구분한다.
2. Vercel 프로젝트에서 이 배포를 **Promote to Production**으로 승격한다. Production 환경에서 다시 빌드되는 경우 완료까지 확인한다. CLI를 쓰면 해당 프로젝트 권한이 있는 계정으로 `vercel promote <이 브랜치의 배포 URL>`을 실행한다.
3. 기존 Production의 `VISION_API_KEY` 및 모델 설정을 유지한다. 비밀값을 Git이나 채팅에 올리지 않는다.
4. `https://safety-report-poc.vercel.app/api/vision`을 GET으로 열어 `analysisVersion: 2`, `release: "vision-api-2026-10-15"`, `legacyClientsSupported: true`인지 확인한다.
5. 같은 합성 사진으로 연결된 iPhone에서 앱의 분석 코드를 실행해 상세 응답·확대 요청·기존 자료 보존을 확인한다. 결과가 불명확하면 그대로 기록하며 소화전이라고 강제하지 않는다.

Vercel 관리 권한이 없는 GitHub 협업자는 Preview를 준비할 수 있어도 운영 전환은 완료할 수 없다. 기존 CLI 인증이 만료되어 이 문서 작성 시점에는 운영 전환이 완료되지 않았다.
